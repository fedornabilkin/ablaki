# Состояния грядки — 2026-11-03

Маршруты прежние: `GET v1/world/beds/{id}/cultivation`, парные POST `dig/sow/water/harvest/cancel` и их `-preview`.

Новый посев принимает `terms.watering_schedule = {version: 2, waterings: 2, interval_seconds: N}`. Посадка расходует семена; первый полив сразу после посадки расходует воду без дополнительного тарифа. Второй полив расходует воду и обычную плату за полив. Для стандартной моркови сохраняются две единицы воды и прежняя общая плата. Для культур без воды `waterings=0`.

Интервал до второго полива — настроенный интервал, ограниченный половиной роста. Первый срок заканчивается не позднее второго полива, второй — не позднее созревания. Окна также ограничены `water_window_seconds`. Если полив пропущен, повторное бесполезное списание воды запрещено; рост продолжается с уменьшенным урожаем. После сбора грядку снова нужно вскопать.

`cycle.state` сохраняет совместимые значения `growing`, `needs_water`, `ripe`, `expired`. Добавлены nullable `watering_step` (1 или 2) и `watering_total` (0 или 2). Для старого посева оба поля null, сроки, расходы и число поливов остаются принятыми ранее. Изменение схемы БД и переписывание текущих циклов не нужны.

Frontend показывает один этап и одну основную кнопку:

| Этап | Кнопка | Таймер |
| --- | --- | --- |
| Свободная грядка | Вскопать | — |
| Вскопана | Посадить семена | — |
| Первый полив | Полить | До конца окна |
| Ожидание второго | Полить, выключена | До начала окна |
| Второй полив | Полить | До конца окна |
| Рост | Собрать, выключена | До созревания |
| Созрела | Собрать | До истечения срока сбора |
| Погибла | Очистить грядку | — |

Переход времени на клиенте только меняет представление. Выполнение всегда проверяет актуальный preview, ревизию и сроки внутри CommandBus. После сбоя GET доступна ручная попытка и повтор через 5 секунд; непроверенное действие остаётся выключенным.

Порядок публикации: backend, затем frontend. Прежний клиент может обработать новую схему по старым временным полям. Полученный до релиза preview посадки потребует повторного расчёта; уже исполнявшиеся команды сохраняют идемпотентный ответ.

Проверено: полный цикл с двумя поливами, отсутствие третьего полива, полный и уменьшенный урожай, повтор команд, отдельные партии склада и покупка. Локально пройдены изолированные сценарии SQLite и MariaDB 10.11, экономические профили и маршрут развития.
