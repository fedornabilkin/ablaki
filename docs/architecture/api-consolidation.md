# Общие чтения API и совместимость

Обновлено 2026-10-31. [Карта маршрутов и вызовов SPA](../architecture/api-route-map-2026-10-31.md), [проверки и границы аудита](../operations/api-audit-2026-10-31.md).

## Контракты экранов

Данные, которые экран всегда использует вместе и которые имеют одинаковые права доступа, можно получать одним вложенным ответом. Для новых объединённых представлений используется `contract_version: 1`. Отсутствующая одиночная сущность — `null`, пустая коллекция — `[]`; пагинируемая коллекция — `{items, _meta, _links}` через общий `ApiList::envelope()` и штатный сериализатор Yii. Это сохраняет правила доступных полей моделей.

Прежние адреса и форматы без `include` продолжают работать. Новый формат включается явно; неизвестный `include` отклоняется. Массовой обёртки всех старых ответов в `data` нет: она сломала бы существующих потребителей без сокращения запросов.

### История баланса и рейтинга

`GET /v1/history/balance?include=types` и `GET /v1/history/rating?include=types` требуют авторизацию и возвращают:

```json
{
  "contract_version": 1,
  "history": {
    "items": [],
    "_meta": {"totalCount": 0, "pageCount": 0, "currentPage": 1, "perPage": 20},
    "_links": {"self": {"href": "..."}}
  },
  "filters": {"types": [{"type": "world_invest", "count": 44}]}
}
```

Пример иллюстрирует форму, а не согласованный набор записей. `page`, `per-page`, `q`, `sort`, `filter[type]` применяются к истории по [общему контракту списков](frontend-list-api.md). Типы и их количества относятся ко всей истории **текущего пользователя**, независимо от выбранной страницы/фильтра. `user_id` клиента не меняет владельца. Ошибка `include` — HTTP 400.

SPA получает записи, пагинацию и типы одним запросом вместо двух. Кнопки типов сохраняются при переходах между страницами; при смене раздела или сессии очищаются. `balance-type` и `rating-type` оставлены для совместимости, используют ту же выборку типов и больше не вызываются страницей истории.

### Персонаж мира

`GET /v1/world/economy?include=character` требует прежние права доступа к миру:

```json
{
  "contract_version": 1,
  "economy": {},
  "character": {
    "progression": {
      "craft": [],
      "professions": [],
      "extraction_work": null,
      "server_time": 0
    },
    "construction": {"active": null}
  }
}
```

`economy` содержит полный существующий [контракт экономики](economy-runtime-api.md), без изменения состава. `construction.active` — существующий Build DTO или `null`. Сервис `WorldPlayerRead` формирует навыки, профессии игрока, текущую добычу и стройку; его используют и объединённое представление, и прежние отдельные действия. Данные NPC и других пользователей не включаются. Ошибка `include` — HTTP 422 `INVALID_INCLUDE`.

Личные данные страницы персонажа загружаются одним запросом вместо `economy` + `economy/progression` + `builds/active`. Свойства, ночлег, хранилища и история остаются отдельными разделами со своими параметрами и загрузкой. Отдельный `economy/progression` нужен также ленивому поповеру персонажа; удалять его нельзя.

Объединение сокращает HTTP-вызовы, но не обещает транзакционный снимок всех чтений и не отменяет серверную проверку состояния при игровой команде.

## Общий транспорт SPA

`services/httpClient.ts::readApi()` объединяет только **одновременно выполняющиеся** явно разрешённые чтения. Ключ включает адрес с параметрами, токен, ревизию сессии и поколение чтений. Завершённые ответы не кешируются: следующее чтение заново обращается к API.

- Каждый потребитель получает собственную копию JSON, чтобы изменения модели одного компонента не затрагивали другой.
- Запрос с `AbortSignal` имеет отдельный жизненный цикл и не объединяется.
- Начало и завершение любой POST/PUT/PATCH/DELETE-команды, включая ошибку, отделяют новые чтения от ранее начатых.
- Настройка/смена сессии разделяет запросы аккаунтов. За игнорирование уже пришедшего устаревшего ответа отвечает существующий владелец состояния (`usePageRequest`, контроллер страницы).
- Авторизация и обработка 401 остаются в общем Axios-клиенте; новые адаптеры не читают токен из localStorage напрямую.

Неиспользуемый Vuex-модуль меню с запросом несуществующего `menu-list` и собственным транспортом удалён. Локальное объединение чтений `worldHome` заменено общим транспортом; `simpleWorld.startState` использует существующий разбор `startOverview`.

## Команды и исторические адреса

Канонический метод для ежедневных наград и запуска сапёра — POST:

| Команда | Канонический запрос | Совместимость |
| --- | --- | --- |
| Ежедневный кредит | `POST /v1/bonus/everyday` | GET того же адреса deprecated |
| Ежедневный рейтинг | `POST /v1/rating/everyday` | GET того же адреса deprecated |
| Запуск созданной игры | `POST /v1/saper/start/{id}` | GET того же адреса deprecated |

Оба метода ведут в одно действие и прежние сервисы. SPA переведён на POST; формулы, проверки владельца и защита от повтора не менялись. Изменяющие GET нельзя включать в предзагрузку или `readApi`. Другие исторические изменяющие GET, включая массовую отмену биржи, пока требуют отдельной миграции потребителей.

Из регистрации удалены 23 правила, у которых отсутствовали действия: `history/create`, сгенерированные CRUD/OPTIONS для несуществующих `items`, `recipes`, `inventory`, DELETE комментария форума. Удалена повторная запись OPTIONS мира. В массовой отмене биржи исправлена конфигурация `RemoveAction` (`modelClass`, `checkAccess`), чтобы существующий адрес достигал того же сервиса отмены и возврата средств.

### Что намеренно не объединено

- Preview и подтверждение команды: предварительная цена, ревизии и ключ повтора имеют отдельный смысл.
- Чужие публичные данные и личные финансы: разные права доступа.
- Разные страницы/фильтры истории: разные выборки.
- Карта и дерево уже имеют `view=home` / `include=tree`; второй конкурирующий endpoint не добавлен.
- Совместимые контроллеры игр/форума/биржи и `v1/WorldController` делегируют общим реализациям; внешние адреса не равны дублированию бизнес-логики.
- `users/last` уже вызывает `actionIndex`; `users/data` — старая статическая заглушка без потребителя SPA, а не источник профиля. Для профиля используется `users/profile`.
- Экспериментальные адаптеры чата и магазина крафта не подключены к текущим страницам. Их отсутствующие серверные ручки не заменены фиктивными ответами; подробности в отчёте.

## Порядок обновления

Миграций БД нет. Сначала обновляется backend с новыми `include` и POST-маршрутами, затем SPA. Старый клиент продолжает работать с обновлённым сервером. Новый SPA со старым backend несовместим в этих трёх местах; клиент намеренно проверяет версию вложенного ответа. Удаление работающих legacy-адресов в этот пакет не входит.
