# Контракт списков для SPA

Обновлено 2026-09-05. Старый клиент получает массив, новый указывает `envelope=1`:

```json
{
  "items": [],
  "_meta": { "totalCount": 0, "pageCount": 0, "currentPage": 1, "perPage": 20 }
}
```

Также сохраняются стандартные заголовки Yii `X-Pagination-*` и `_links`. Поиск `q` выполняется сервером до подсчёта и пагинации; строка до 100 символов, `%` и `_` экранируются. Номера `page` начинаются с 1, `per-page` по умолчанию 20 и не более 100. Сортировка по умолчанию `-id`; одинаковые значения других полей дополнительно упорядочиваются по `id DESC`. Рейтинг намеренно сортируется по `-rating`. Недоступная страница ограничивается последней существующей; фактический номер приходит в `_meta.currentPage`.

## Маршруты

| Маршрут | Доступ и поиск |
| --- | --- |
| `GET v1/users`, `GET v1/users/last` | Публично. `q` по логину; сортировка `id`, `created_at`, `username`. |
| `GET v1/users/referrals` | Авторизация. Пользователи с `persone.refovod`, равным текущему пользователю; тот же формат и поиск. |
| `GET v1/users/online` | Публично. Список по активности за последние 300 секунд. `all=1` возвращает полный массив без пагинации для модалки; прежний контракт с `envelope=1` сохранён. |
| `GET v1/users/online-count` | Публично. `{count, windowSeconds: 300}` без списка. |
| `POST v1/users/heartbeat` | Авторизация. Фиксирует активность и возвращает актуальный счётчик. |
| `GET v1/history/balance` | Авторизация. Только собственная история баланса; `q` по `type`/`comment`, `filter[type]`. |
| `GET v1/history/rating` | Авторизация. Только собственная история рейтинга; те же параметры. |
| `GET v1/history/balance-type`, `GET v1/history/rating-type` | Авторизация. Только существующие собственные типы: `[{type, count}]`. |
| `GET v1/transfer`, `GET v1/transfer/history` | Авторизация. Собственные доступные/участвовавшие завершённые переводы; `q` по логину участника, номеру или сумме. Поля дополнены `amount`, `username`, `username_buyer`. Код `password` виден только создателю. |
| `GET v1/exchange`, `GET v1/exchange/my`, `GET v1/exchange/history` | Авторизация. Сохраняются владельцы и `filter[type]`, `filter[amount]`, `filter[credit]`. `q` по участнику, номеру, типу и сумме. |
| `GET v1/stat` | Публичная общая статистика. Существующий объект `users`, `games`, `forum`, `exchange`, `topRating`. |
| `GET v1/stat/top` | Публичный рейтинг. `period=all/day/week/month/half-year`, `q` по логину. Новый envelope содержит `{id, username, rating}`; старый формат `{period, list}` сохранён. За период считается сумма положительных изменений рейтинга. |
| `GET v1/tips/random` | Публично. `{id, title, type}` из существующей таблицы `fact`, `hide != 1`. Если видимых подсказок нет, `null`. |

Участники сериализуются штатными моделями API; чужие email, баланс и кредиты не добавляются в публичные списки. Ссылки на стены поддерживают все символы, разрешённые текущей моделью имени пользователя (`-`, `.`, `@`, `_`, латиница и цифры).

DTO пользователя содержит `is_online` (boolean) из текущего кеша активности. DTO темы форума содержит `comment_count` — количество сообщений с `active=1`, подсчитанное сервером; существующий `view` остается счетчиком просмотров. Списки тем получают счетчик в SQL-запросе без отдельного запроса на каждую тему.

На главной SPA запрашивает 10 новых участников (`sort=-created_at&per-page=10`) и 10 последних тем (`sort=-id&per-page=10`), без поиска и навигации между страницами внутри блоков. Полные страницы сохраняют поиск и пагинацию.

Заявки биржи дополнены `username` (автор) и `username_client` (контрагент либо `null`).

Онлайн отражает активность авторизованных пользователей API за последние 300 секунд, включая границу окна. Вход и любой успешно авторизованный запрос обновляют активность; запись ограничена одним обновлением в минуту. Клиент отправляет `POST v1/users/heartbeat` во время работы с видимой вкладкой, чтобы чтение страницы также учитывалось. Ручка требует Bearer-токен и возвращает `{count, windowSeconds: 300}`. `GET v1/users/online?envelope=1` возвращает список активных пользователей с поиском и пагинацией; счетчик использует тот же источник. Гостей по IP не отслеживаем. Значение `last_login_at` остаётся временем входа.

API хранит активность только в `@runtime/presence`: общий файловый кеш и блокировка защищают обновления нескольких PHP-процессов. Таблица и миграция для онлайна не нужны. Этот режим рассчитан на один сервер с общим runtime; очистка runtime сбрасывает текущий онлайн, следующие запросы восстанавливают его. Ошибка записи активности не прерывает авторизацию и другие защищенные ручки.

## Выкладка и проверки

Онлайн не требует миграций БД. Форумные подарки требуют отдельной миграции `m260905_120000_create_forum_comment_gift_table`. Изменения только SPA без обновления API не включают новые серверные возможности. В тестах миграции и данные production не запускались.

```sh
php -d extension=pdo_sqlite -d extension=mbstring tests/release/frontend-lists.php
```

Проверки используют собственный временный SQLite-файл, не читают `.env`, проверяют поиск до пагинации, метаданные, URL-маршруты и DI сериализатора, приватность, собственные типы, рефералов, онлайн и подсказки. Lint выполнен PHP 8.3.33; новый синтаксис совместим с PHP 7.3. SQLite не подтверждает блокировки и миграции на целевой PostgreSQL/MySQL.

Полная совместная проверка форума, игр и маршрутов описана в `frontend-api-integration-audit.md`.
