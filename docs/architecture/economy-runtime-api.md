Актуализация 2026-10-28: после стартового убывающего запаса остаётся по одной единице сырья в сутки (`gather_minimum=true`), включая песок и глину. Прежние квитанции и лимиты не сбрасываются. Добытый игроками товар NPC продаётся через общий складской API; работа и общие станции описаны в [API мира](simple-world-api.md). Пополнение бюджетов использует только существующие средства bot, публичных территорий и выручку; защищённые обязательства сохраняются.

Обновление 2026-10-23: кузница 40, одна незавершённая стройка, дальнее кольцо ×10 при прежней цене соседних ячеек. Базовая самостоятельная цепочка до кузницы с восемью соседними ячейками и двумя поливами стоит 247,8 из 250. Стартовый резерв и уже выданные деньги не меняются. В недельном сценарии мастерская и средний склад строятся на стоянке; дополнительные дальние ячейки исследуются эликсирами. Три партии угля заменены тремя сборами волшебной травы в разные дни для изготовления двух дополнительных эликсиров, с сохранением лимита 20 добыч/сутки. Выдача угля — 3 за партию, песка — 4, редкой травы — 2; выручка недельного маршрута — 380.


Срез реализации от 2026-10-21. Базовый путь — `/v1/world`. Используется существующая Bearer-авторизация. Установка схемы не публикует профиль: публикация выполняется отдельно с предварительным просмотром и проверкой digest. Допуск закрытого теста проверяется сервером через RBAC; запись участника сама по себе права не выдаёт.

## Состояние и журнал

Журнал дополнен связями `actor_user_id`, `node_id`, `profile_id`, `profile_version`, `from`, `to`, `item_id`, `balance_before_cr`, `balance_after_cr`, `quantity_before`, `quantity_after`, `transfer_ids[]`, `transfer_phase` (`create/claim/cancel`). Недоступные исторические поля — `null`; чужие счета редактируются до безопасного endpoint без ID/объекта/баланса. Вещи показывают количество движения; исторические остатки стопок не восстанавливаются из текущего инвентаря. Подробная [матрица покрытия и миграций](economy-journal-migrations.md).

`GET /economy` возвращает `enabled`, `profile_version`, `admission`, `health`, `goals`, `quotas`, `feedback_path`, `server_time`. При отсутствии опубликованного профиля `enabled=false`; клиент не создаёт локальные цели или награды. `feedback_path=/forum` ведёт на список тем.

- `health`: `hp` (0–100), `max_hp=100`, `revision`, `foods[]`, `can_eat` (boolean), `disorder_until` и `last_food_at` (Unix timestamp либо null), `server_time`. Каждое блюдо содержит `code,name,restore_hp,kitchen_restore_hp,quantity,can_eat,repeat_limit,repeat_remaining,repeat_seconds,restores_at`. Количество относится к доступным местам рюкзака. Полные HP разрешают поддерживающую еду в пределах лимита блюда. HP учитываются отдельно от ночной болезни.
- `goals[]`: `code`, `completed`, `claimed`, `funded`, `can_claim`, `blocked_reason` (строка либо null), `funding_settlement_id` (ID поселения либо null), точная строка `credits_cr`, `steps[{code,completed,quantity,required}]`. Выполнение подтверждают журнал фактов и существующее состояние участника: членство, активная стоянка, вещи, законченные партии и действия. Количества журнала и имущества сверяются через максимум без двойного сложения. Уже полученная награда сохраняет выполненность всех своих шагов после расходования материалов. Выполненная цель без резерва остаётся недоступной, причина явно указана. `can_fund_goals` в корне означает наличие `world-manage`; создание резерва выполняется отдельной командой.
- `quotas[]`: контракт [клиентского парсера](../../../frontend/project/src/services/api/worldEconomyQuota.ts). Дневные лимиты восстанавливаются по московскому времени; клиент показывает серверный `restores_at`.

Дополнительно: `personal_credit_cr`, `target_start_credit_cr` (точные строки; последняя — базовая ставка профиля), `starter_funding` (принятое обязательство с фактической `amount_cr` либо null; именно эту сумму показывает клиент), `second_milestone_day` (проверенный срок). Шаг цели содержит `action_href` — внутренний путь мира к доступному действию. Источники возвращают `output_storage_id` принятой партии, `actions[].tool_names`, `actions[].experience` и `actions[].available_at`; клиент показывает опыт, срок кулдауна/дневного восстановления и не меняет хранилище уже принятой партии.

С 2026-10-19 состояние источника дополнительно возвращает `work_id` (целый ID принятой партии либо null), `required_seconds` из её принятых условий и `live_work: [{accounted_at,last_seen_at}]`. Вместе с `worked_seconds` и `server_time` они позволяют плавно показывать прогресс. При проекции каждый работник учитывается максимум до `last_seen_at + 60`; завершение и выдачу подтверждает сервер. Клиент сверяется heartbeat каждые 10 секунд и при заполнении шкалы. Старая шахта возвращает `worked_seconds` и тот же `live_work`, длительность единицы остаётся в `seconds_per_unit`.

С 2026-10-21 `actions[].unavailable_reason` объясняет отсутствие исправного необходимого инструмента; null означает отсутствие этой причины блокировки. Корневое `unavailable_reason` относится к инструментам уже принятой партии, включая условия прежней версии профиля. Ограничения квоты, времени и хранилища сохраняют собственные поля. Клиент блокирует известное недоступное действие до POST; сервер всё равно повторно проверяет условия команды. Текущий профиль источников не расходует входные материалы.

`GET /economy/history?source=commands&page=1&q=` читает существующие журналы без копирования балансов. `source`: `commands`, `credits`, `items`, `transfers`, `wallet`, `health`. Поиск выполняется сервером, страница содержит 20 записей. Ответ: `items`, `_meta{totalCount,pageCount,currentPage,perPage}`, `server_time`.

Запись содержит `id`, `source`, `operation_id`, `created_at`, `kind`, `classification`, `amount_cr`, `quantity`, `balance_before_cr`, `balance_after_cr`. ID игровой команды — строка; ID старого журнала может быть числом. Денежные значения — строки или null; старый журнал переводов сохраняет свою точность. История не раскрывает хэши/пароли переводов и остатки чужих счетов. Необязательный `user_id` доступен только управляющему миром или администратору.

## Еда и цели

Для новой команды нужен новый `request_key` (либо заголовок `Idempotency-Key`); после потери ответа повторяются прежние ключ и тело.

| POST | Поля JSON кроме `request_key` | Результат/ограничение |
| --- | --- | --- |
| `/economy/food` | `code`, целое `health_revision` из GET, необязательное `kitchen_node_id` | Атомарное потребление одной порции, учёт голода и изменение HP. `HEALTH_CHANGED` требует перечитать состояние. При указании кухни проверяются доступность объекта и окно приёма пищи |
| `/economy/goals/claim` | `code`: `day-1` или `day-2` | Однократная награда при выполненных фактах и обеспеченном резерве |
| `/economy/goals/fund` | `code`, целое `settlement_id`, целое `participants` (1–1000) | Резерв из существующего бюджета поселения; требуются права `world-manage` |

Из рюкзака блюдо восстанавливает максимум 8 HP. Профиль задаёт отдельные правила:

| Блюдо | HP из рюкзака / в кухне | Порций в скользящем окне |
| --- | --- | --- |
| Печёная морковь | 4 / 15 | 2 за 6 часов |
| Овощной отвар | 8 / 30 | 1 за 8 часов |
| Походный паёк | 6 / 20 | 3 за 12 часов |

Видимая кнопка блокируется при исчерпании лимита. Если клиент всё же отправит лишнюю порцию, она расходуется с потерей 4 HP и пищевым расстройством на половину окна блюда. Пока расстройство активно, обычная еда отклоняется с `FOOD_DISORDER` без расхода. Лимиты не суммируются между блюдами; `restores_at` означает время освобождения следующей порции. Граница скользящего окна исключительная, например ровно через 6 часов первая порция моркови перестаёт занимать лимит.

`GET /economy/kitchen/{id}` возвращает `node_id,meal,meal_used,health,server_time`. `meal={timezone:"Europe/Moscow",current,next}`; каждое окно — `{code,name,starts_at,ends_at}`, `current=null` во время перерыва. Полевая кухня должна быть действующим видимым объектом с действующими предками. Завтрак 06:00–10:00, обед 12:00–16:00, ужин 18:00–22:00 по Москве; конец окна исключительный. Один игрок может использовать каждое окно один раз на всех кухнях мира, то есть максимум три приёма за дату. Порция берётся из его рюкзака. Кухня использует полное восстановление блюда, не расходует лимит обычной еды и не снимает действующее пищевое расстройство или ночную болезнь. `KITCHEN_UNAVAILABLE` означает недоступный объект, `MEAL_UNAVAILABLE` — перерыв либо уже использованное окно. Проверка и расход защищены общей блокировкой игрока; повтор с прежним ключом возвращает исходный результат.

`GET /economy/progression` — компактная собственная прокачка без загрузки инвентаря: `craft[{name,level,xp}],professions[{name,level,xp}],server_time`. У крафта уровень равен `1 + floor(xp/100)`. Поповер информации ноды загружает эти данные при открытии.

Команда `/workspace/craft` дополнительно возвращает `craft_result={output:{item_id,name,quantity,storage_id,fits},materials:[{item_id,name,quantity}],price_cr,experience}` из принятых условий. Результат хранится вместе с командой и одинаков при точном повторе; клиент сохраняет его под кнопкой после обновления расчёта. Рецепт палки теперь расходует одно бревно и даёт четыре палки. Недельный маршрут пересчитан с прежними лимитами и источниками средств.

Денежная награда цели направляется в казну стоянки. Сбор в её бюджет сохраняет действующие отчисления и не пополняет личный кошелёк. При профиле `starter.funding=parent_budget` стартовые средства переводятся из защищённого резерва поселения в бюджет первой стоянки. Организатор выделяет резерв из существующего свободного бюджета и задаёт ставку; до вступления показываются обеспеченные места города/региона. При нехватке принятое обязательство ждёт пополнения резерва в FIFO-очереди, сохраняя принятую сумму. Отдельный личный перевод не нужен. Эмиссии и повторного старта нет. См. схему 42 в [контракте простой модели](simple-world-api.md).

После 72 часов без еды голод уменьшает HP на 2, затем ещё на 2 за каждые следующие 24 часа, с нижней границей 0. Отсчёт начинается от последней еды, а для участника без еды — от более поздней даты вступления и первой публикации экономики. Новая версия цен не перезапускает отсчёт. Учёт выполняют существующие ночные задания и команда еды под блокировкой игрока; повтор и возврат после долгого отсутствия учитывают только неоплаченные периоды. GET не изменяет здоровье. Еда перезапускает отсчёт даже при полных HP; отдельную ночную болезнь она не удаляет.

Кандидат профиля от 2026-10-20 устанавливает шалашу `20.0000` Cr, дому `80.0000` Cr. Сумма двух построек остаётся 100 Cr. Изменение файла не обновляет опубликованную версию: для каждого окружения нужна явная публикация профиля.

## Расширение хранения

`GET /economy/storage/{id}` возвращает `storage_id`, `kind`, постоянную `capacity`, `options[{code,slots,price_cr,capacity_after}]`, `profile_version`, `writable`, `server_time`. Временные места рюкзака не превращаются в постоянные. Пустые `options` означают отсутствие доступного пакета.

`POST /economy/storage/{id}/expand-preview` с `{code}` возвращает обычный quote: `quote_id`, `expected_revisions`, сроки и `terms`. Условия включают `capacity_before`, `capacity_after`, `price_cr`, `payer=personal_wallet` и версию профиля.

`POST /economy/storage/{id}/expand` принимает `{code,request_key,quote_id,expected_revisions}`. Полный объект ревизий копируется из preview. Списание выполняется с личного баланса; старые предметы и вместимость сохраняются. `STORAGE_EXPANSION_CHANGED` требует нового расчёта. При неопределённом результате клиент сохраняет исходную команду для точного повтора.

## Конечное снабжение и состав истории — 2026-10-22

Схема мира 40 добавляет `world_supply_claim`: отдельный конечный остаток на пользователя, мир и ID предмета каталога. Ежедневные команды стоянки и общей модели используют один SupplyGrant. Ответы состояния сбора и supplies в campsite дополнены `gather_remaining,gather_limit,gather_exhausted`. Доступность следующего дня задаётся реальным `gather_available_at`, вычисленным по календарю мира. Исчерпанная кнопка скрывается; остаток не обнуляется при смене даты, переименовании предмета или публикации профиля.

Текущий профиль: пять выдач по предмету; для бревна/камня/волокна/воды при полном здоровье — 14, 12, 10, 8, 6; для травы — 7, 6, 5, 4, 3. Штраф здоровья применяется при принятии, следующая фактическая выдача всегда меньше предыдущей. Постройка соответствующей добычи уменьшает выдачу этого ресурса на 50% с округлением вверх (лес: бревно; каменоломня/шахта: камень; луг: волокно/трава; источник: вода). Факт постройки сохраняет уменьшение и после удаления источника. Новый gatherable-предмет каталога получает собственный остаток; исчерпанные прежние предметы не возвращаются к стартовому объёму: остаётся только суточный минимум. Уникальные ограничения защищают день/порядковый номер; точный повтор команды возвращает прежний результат.

В каждом элементе `GET /v1/world/economy/history` добавлен `items: [{item_id,code,name,quantity,direction}]`. Направления: collected, created, spent, received, moved, sold, bought. Источник — агрегированные inventory_movement принятой операции с фильтром собственных хранилищ; чужие предметы не раскрываются. Старые строки без предметных движений возвращают пустой массив. Поиск команд/вещей поддерживает имя и код предмета. Старые поля и пагинация сохранены.

Административная главная `/world-admin` содержит согласованный финансовый снимок: общие кошельки сайта, счета действующего мира, резервы внутри счетов, открытые переводы и определимые резервы биржи. План на двух участников: 500 стартовых переводов, 820 конечных заказов и 300 наград, всего 1620; бюджетная часть 1120. Уже оплаченные заказы (по переводам исполнений) и выданные награды показаны отдельно и уменьшают требуемое начальное обеспечение; повторно вносить их не предлагается. Выплаты, свободные средства и резервы относятся к действующему миру в целом. Это расчёт обеспечения, не эмиссия. Неопределённые исторические типы биржи не исполняются; их резерв не придумывается.

Актуальный автономный недельный сценарий — `first-seven-days-finite-supplies`. Прежние сценарии оставлены с явной меткой historical_daily_model для сопоставимости старых аудитов. Реальный gameplay replay использует конечное снабжение и ранний первый сбор до постройки источников.

## Единая покупка слотов — 2026-10-24

Для рюкзака `/economy/storage/{id}` возвращает варианты `backpack-N` для каждого допустимого количества от 1 до оставшегося постоянного лимита 50. Цена вычисляется через общий `CraftInventory::purchaseQuote`: базовая цена `craft_meta.slot_price` умножается на последовательные номера платных слотов сверх стартовых 20. При базе 10 первые 10 слотов стоят 550, следующий — 110. Исторические пакеты профиля «5 за 50» и «10 за 90» для рюкзака больше не применяются. Остальные хранилища сохраняют свои пакеты.

Инвентарь и размещение используют один компонент и маршруты `expand-preview` / `expand`. Состояние классического инвентаря дополнено `backpack_storage_id`, когда включено каноническое хранилище. Старый `buy_slots` оставлен как совместимый адаптер того же прогрессивного расчёта и записи; дешёвый либо устаревший подтверждённый итог отклоняется. Уже оплаченные места и временные расширения сохраняются.

Конечный ежедневный сбор сохраняет принятые базовые параметры, лимит и историю каждого предмета. `gather_items` и условия выдачи включают `production_reduction_bps` (0 или 5000). Расчёт учитывает здоровье, затем уменьшение от постройки, затем требование строго убывающего количества. Доступность и фактическая выдача используют одну рассчитанную величину; после исчерпания остаётся суточный минимум в одну единицу, при сохранении прежних квитанций.

## Экземпляр мира и локальный чеклист

`GET /v1/world/economy` также возвращает `world_instance`: строку `<id>:<created_at>` активного корня мира либо `null`, если корня нет. Идентификатор стабилен при навигации и публикации профиля; после пересоздания мира меняется даже при повторном использовании числового ID. Клиент использует его вместе с ID пользователя для ключа localStorage чеклиста. Результаты не влияют на игровые права, награды или деньги. Дополнительных клиентских запросов для чеклиста нет: используются уже загружаемые задания.
## Маршрут развития · 2026-10-30

`GET /v1/world/economy` дополняется полем `development`. При выключенном профиле оно равно `null`. Иначе ответ содержит `version: 1`, `completed`, `total`, `next_stage` (код первого незавершённого этапа или `null`) и упорядоченный массив `stages`.

Этап: `{code,title,description,completed,steps}`. Шаг: `{code,title,quantity,required,completed,action_href}`. Счётчики вычисляются сервером из истории действий и принадлежащих участнику объектов текущего мира. Клиент не сохраняет отметки прохождения. `action_href` ведёт на `/world`, `/world/nodes/{id}`, `/world/workspace/{id}` или `/world/character`; при отсутствии нужной постройки используется стоянка. Переход не выполняет игровую команду. Факты `produced:*` используют код изготовленного рецепта, например `produced:starter-carrot-seeds`, а не код выходного предмета.

Маршрут охватывает 29 типов построек собственного дерева и отдельную грядку в теплице. Публичные города, регионы, мир и поместье на чужой городской территории не выдаются за доступные игроку цели. Шаг добычи на своей шахте не засчитывается наёмной работой. Установка верстака и плавильни проверяется по размещённым предметам, приготовление и еда — отдельно. Стартовая каменная кирка учитывается фактом получения, сохраняющимся после её расходования.

`DevelopmentRoute` не зависит от Yii и содержит порядок/описания. `WorldProgress` собирает общие факты для маршрута и прежних наградных целей; `WorldDevelopment` подставляет доступные переходы. Чтение не создаёт денег, предметов, наград или обязательств. Прежние `/goals/claim` и зарезервированные награды остаются отдельными командами. Новый набор применяется при публикации профиля, а уже выданные наборы повторно не выдаются.
