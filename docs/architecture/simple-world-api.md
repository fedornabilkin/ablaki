# API простой модели мира

Обновление 2026-10-23, схема 43 (`m261023_200000_world_template_context`): `/templates?parent_id` фильтрует постройки по `world_template_parent` до пагинации и подсчёта; `Build::begin` проверяет те же связи. Стандартные дом, кузница, ловушка и добывающие участки доступны в стоянке/усадьбе, грядка — в огороде или теплице. Связи для дополнительных объектов профиля и подходящих мини-складов заполняются повторяемо; пользовательские связи администратора сохраняются. Неподходящий прямой POST — `INVALID_TEMPLATE`. Существующие объекты не перемещаются и не удаляются.

`placement-options` и перенос используют одну политику: кровать требует крытого/внутреннего места, костёр — наружного; станции подходят рабочим помещениям, укрытию/дому, верстак — также лесному участку, наковальня — шахте. До изготовления показываются только совместимые предметы. Свободное место и открытая ячейка проверяются дополнительно при переносе. Канонические места костра/очаги без явного переопределения исправляются на наружные; исторические деньги, предметы и прочность сохраняются.

На игрока разрешена одна незавершённая стройка или ремонт в мире (`CONSTRUCTION_LIMIT`). Рабочая сессия тоже одна: чужой активной стройке нельзя отправлять возобновляющий heartbeat (`BUILDER_BUSY`). Ранее принятые несколько проектов сохраняются для завершения/отмены. На карте родителя управление показывается только для выбранной стройки; скрытая текущая сессия продолжает heartbeat.

Для `housing-lodge-preview` и `housing-lodge` необязательное `replace_current: true` разрешает атомарно закрыть прежнее назначение и назначить выбранную кровать. Флаг должен совпадать в preview/execute; quote включает `previous_assignment`. При изменении назначения — `HOUSING_CHANGED` без потери текущего ночлега. Операция бесплатна, сохраняет интервалы прошлых ночей и идемпотентность. Клиент выполняет обе стадии в фоне после одного нажатия.

`map.pricing.outer_ring_multiplier` (целое 1–100, по умолчанию 1) умножает цену всех колец с радиусом более 1 до пакетной скидки. В текущем профиле база 0,5 и множитель 10: ближняя ячейка — 0,5, второе кольцо — 10. Уже купленные права и принятые стройки сохраняют условия. Кузница стоит 40: базовые шалаш + огород + грядка + шахта + кузница = 240; восемь ближних ячеек со скидкой и два полива дают 247,8 из стартовых 250. Это расчёт самостоятельной стройки без оплаты помощников и необязательных дополнительных объектов.


Обновление 2026-10-23, схема 42 (`m261023_160000_world_starter_reserve`): стартовые выплаты обеспечиваются отдельным резервом поселения. Резерв хранится как обязательство существующего бюджета и уже входит в его остаток; свободные расходы его не используют. `payout_cr` — положительная точная строка, `add_amount_cr` — неотрицательная. Нехватка свободных средств даёт `INSUFFICIENT_BUDGET`; неверная сумма — `INVALID_STARTER_RESERVE`; неподходящий объект — `SETTLEMENT_REQUIRED`.

Новая ставка применяется только к новым обязательствам. Принятые суммы сохраняются; очередь оплачивается целиком в порядке ID, без частичных выплат и эмиссии. Обычное пополнение бюджета не заменяет выделение в резерв. Доступные места: `floor(max(остаток резерва − ожидающие обязательства, 0) / ставка)`. Возврат неизрасходованного старта отменённой стоянки вновь защищается резервом. В админке мира доступны формы выплаты/пополнения для каждого поселения, суммы, очередь и обеспеченные места; POST защищён CSRF и правом `p-admin`.

Бюджет строителей `0` допускает самостоятельную стройку; положительный должен соответствовать принятому минимуму. Build DTO добавляет `can_reduce_budget`: после принятия работы помощниками или начисленного им труда снижение запрещается, увеличение сохраняет обещанную оплату. При снижении свободный остаток освобождается; при увеличении оплачивается только разница, `top_up=true` разрешает ровно недостающую личную доплату. Клиент нормализует пустое поле в `0`. `parent_id` позволяет вести дочернюю стройку с карты родителя, сохраняя heartbeat и прогресс без перехода внутрь объекта.

Дополнение 2026-10-17: [API экономики закрытого теста](economy-runtime-api.md) описывает состояние профиля, цели, еду, сквозную историю и постоянное расширение хранилищ. Установка схемы не равна публикации профиля; допуск проверяется сервером.

Актуально для схемы 38 с миграцией `m261008_160000_world_construction_mining`, 2026-10-08. База `/v1/world`, прежний Bearer. Требуются `world_read`; для команд также `world_write` и `storage_v2`. Авторизация и видимость проверяются сервером. Скрытый или архивный предок скрывает всё поддерево. Игровые карта, навигация, списки, статистика и прямое чтение исключают архивные объекты и их потомков также для `world-manage`: это право открывает приватные действующие объекты, но не возвращает отменённые стройки на карту.

## Общий контракт

Дополнение 2026-10-09: миграция `m261008_210000_world_object_repair` сохраняет историю стройки и позволяет последующие ремонты одного объекта. Чтение прежней схемы совместимо; создание ремонта требует новых колонок.

GET ничего не изменяет. Списки возвращают `{items: [...], _meta: {totalCount, pageCount, currentPage, perPage}}`, страницы нумеруются с 1; клиент передаёт `envelope=1`. Размер страницы — 20 (для шаблонов — 30). Поддерживаются `q`, `page`, `sort`; обратный порядок обозначается `-`, по умолчанию `-id`. Дополнительные фильтры перечислены ниже.

POST принимает JSON и обязательный заголовок `Idempotency-Key` (совместимый вариант — поле `request_key`). Для нового действия нужен новый ключ; при сетевой неопределённости повторяются прежние ключ, URL и тело. Один ключ с другим действием или телом отклоняется с 409. Денежные величины — десятичные строки с точностью до четырёх знаков, времена — Unix UTC, количества и ID — целые числа. Команда возвращает результат и `operation_id`.

Ошибки имеют неуспешный HTTP-статус и `{code, message, details}`: 401 без входа, 403 при недостаточных правах, 404 для недоступного объекта, 409 для конфликта/повтора с другими условиями, 422 для неверного ввода, 503 для неготовой схемы или отключённого функционала. `details` может отсутствовать. OPTIONS доступен без авторизации.

## Чтение

| Метод и адрес | Параметры / ответ |
| --- | --- |
| `GET /objects` | Фильтры `parent_id`, `template_id`, `hierarchy_level`, `status`, `owner_user_id`; сортировки `id,name,hierarchy_level,status,created_at,parent_id,owner_user_id`. Список Node. |
| `GET /objects/{id}` | Один Node. |
| `GET /templates?parent_id={id}` | Включённые пользовательские шаблоны, разрешённые для выбранного родителя; `q`, `hierarchy_level`, `enabled`; список Template. |
| `GET /events?node_id={id}` | Действующие сейчас события выбранного объекта и всех предков; `q`, `scope_node_id`, `status`; сортировки `id,name,starts_at,ends_at,status`. |
| `GET /builds` | Свои стройки и открытые оплачиваемые стройки видимых объектов; фильтры `parent_id,node_id,status`, `q` по имени объекта; сортировки `id,created_at,required_seconds`. |
| `GET /builds/{id}` | `{build: Build, work: [...]}` для видимого объекта. |
| `GET /builds/active` | `{build: Build|null}` — текущая незавершённая рабочая сессия пользователя; восстанавливается после перезагрузки. |
| `GET /objects/{id}/gather` | Своя действующая стоянка: `{gather_available,gather_can_claim,gather_reason,gather_items:[{name,quantity,...}],gather_remaining,gather_limit,gather_exhausted,gather_available_at,server_time}`. Сервер заранее проверяет место в рюкзаке. Следующая выдача — после полуночи мира; остаток и состав определяет конечное снабжение. |
| `GET /start?node_id={id}` | `{node: Node|null, funding: {amount_cr,available,available_places,reserve_cr,pending_cr,waiting,message,settlements}|null, starter_funding: {status,amount_cr,source_node_id,destination_node_id,paid_at}|null}`. До вступления показывает обеспеченные места выбранного города или сумму мест городов региона/мира. Старый `city_id` поддерживается. Для региона `amount_cr=null`; каждая запись `settlements` содержит `node_id,name,amount_cr,available_places`. |
| `GET /objects/{id}/budget` | Только владельцу: `{amount, reserved, available}` в Cr. |

Node содержит `id,parent_id,root_id,template_id,hierarchy_level,node_type,name,status,visibility,owner_user_id,building_kind,position_x,position_y,revision`. `parent_id` и владелец могут быть null. Состояния: `planned,constructing,active,archived`; последние не выдаются публичным списком.

Template содержит постоянные `id,code`, `name,kind,hierarchy_level,build_seconds,enabled,player_buildable,materials_json,defaults_json` и удобочитаемый `material_summary`. Поля `world_time_rate,world_build_seconds` показывают коэффициент и трудоёмкость в секундах мира; `build_seconds` сохраняет реальные секунды. Каталог с `parent_id` добавляет `available,unavailable_reason`: сервер проверяет материалы, инструменты и станции пользователя. JSON-колонки передаются строками. Каталог фильтруется по разрешённому шаблону родителя; произвольная вложенность закрыта. Шаблоны инфраструктуры с `player_buildable=0` в него не входят; эквивалентные старые рецепты представлены одной записью. При отсутствии прав или действующего родителя каталог остаётся видимым с `available=false` и понятной причиной.

Build содержит `id,node_id,parent_id,owner_user_id,required_seconds,worked_seconds,labor_budget,status,revision,created_at,world_time_rate`. Состояния: `building,completed,cancelled`. Сервер сохраняет материалы и трудоёмкость на момент начала стройки в реальных секундах. Коэффициент по умолчанию 60; его изменение меняет отображение времени мира, сохраняя принятую реальную длительность существующих строек.

`job_kind` — `construction` или `repair`; `initial_condition` — прочность при начале ремонта (у стройки 0). `condition,max_condition` учитывают исходную прочность и труд; 100 единиц восстанавливаются за минуту суммарной работы. Один объект имеет только одну незавершённую работу, завершённые записи сохраняются. В `/nodes/{id}` и элементах карты `details.repair_active` указывает текущий ремонт. Поля `server_time,live_work` позволяют непрерывный прогресс; клиент сверяет его heartbeat сразу при достижении полной прочности, без ожидания периодического запроса.

Event содержит `id,name,scope_node_id,description,starts_at,ends_at,status`. `ends_at=null` означает отсутствие срока окончания; клиент не вычисляет финансовые эффекты из описания события.

| Адрес POST | Тело | Результат |
| --- | --- | --- |

| `/builds` | `{"parent_id": 8,"template_id": 5,"name": "Мой дом","labor_budget": "0","x":0,"y":0,"top_up":false}` | `{node,build}`; труд резервируется из доступного бюджета своего родителя, иначе объекта. Парные `x,y` выбирают свободную открытую ячейку; без них автоматически выбирается свободная координата, которая также должна быть открыта; пропуск координат не обходит покупку ячейки. |
| `/builds/{id}/settings` | `{"name":"Мой дом","labor_budget":"10","top_up":false}` | `{node,build}`; владелец меняет имя и бюджет. Новые деньги не создаются. |
| `/builds/{id}/start` | `{}` | `{work,build}`; начать собственный труд или оплачиваемую помощь. |
| `/objects/{id}/repair` | `{}` | `{node,build}`; начать ремонт своего действующего повреждённого объекта любого уровня. Возвращённый `build.id` используется в прежних `/settings`, `/start`, `/heartbeat`, `/stop`, `/cancel`. Бюджет ремонта сначала резервируется из свободного бюджета этого объекта; личная доплата только при `top_up=true`. |
| `/builds/{id}/heartbeat` | `{}` | `{build,work}`; учесть время по серверным часам, при достаточном труде завершить стройку. |
| `/builds/{id}/stop` | `{}` | `{build,work}`; учесть последнее время и остановить свою сессию. |
| `/builds/{id}/cancel` | `{}` | Только владелец. Для новой стройки `{build,return_node_id}`: архивировать объект, освободить место на карте, повысить revision родителя и вернуть `floor(quantity × 0.7)` каждого материала, даже при нулевом прогрессе. `return_node_id` — родитель для перехода клиента. | `/objects/{id}/budget` | `{"amount":"10.0000"}` | `{amount,reserved,available}`; явное пополнение своего бюджета из личного кошелька. |

Владелец строит без платы. Оплата каждого помощника: `floor4(labor_budget × его учтённое время / required_seconds)`. Нельзя передавать отработанные секунды с клиента. Рекомендуемый heartbeat — 10 секунд; верхний предел учёта после последнего сигнала — 60 секунд. Детали транзакций и конкуренции описаны в [архитектуре](simple-world.md).

## Прежние API

GET `/nodes/{id}/garden` показывает условия ранее приобретённого огорода также при расположении внутри стоянки. Для открытия грядок используйте ID самого огорода: `garden.beds` содержит текущие цены, `garden.available_budget` — свободный бюджет, `can_expand` — доступность расширения. POST `/nodes/{id}/garden-expand-preview` принимает `quantity,top_up` и необязательный `bed_ids` — уникальные целые ID выбранных закрытых грядок этого огорода, ровно `quantity` штук. Покупаются именно они, независимо от порядка. В общей модели цена равна сохранённой базовой цене огорода × `max(1, abs(x), abs(y))`, `terms.curve="rings"`; пакет от трёх получает 5% скидку. Старые суммы уже оплаченных прав не переписываются. Без `bed_ids` открываются следующие оставшиеся закрытые грядки. В `garden.beds` возможны открытые грядки между закрытыми; `garden.unlocked` — их общее количество. При нехватке бюджета только явное `top_up=true` разрешает доплату с личного баланса. Подтверждение `/garden-expand` использует те же поля выбора, полученные `quote_id,expected_revisions` и ключ команды.

POST `/nodes/{id}/map-explore-preview` и `/map-explore` принимают `cells` из 1–100 уникальных координат. Все ячейки должны быть свободными и неисследованными. При достаточном уровне исследование бесплатно; `use_elixir=true` разрешает один эликсир на каждую ячейку выше текущего уровня, остальные эликсир не расходуют. Для пакета `terms.elixir_quantity` показывает расход. Все ячейки и расход сохраняются одной транзакцией; повтор прежнего ключа возвращает тот же результат. Одиночные команды и прежние `x,y` совместимы. Пакетная покупка исследованных ячеек сохраняет прежний `/map-buy-preview` и `/map-buy`.

Изготовление временно разрешено только в собственной действующей стоянке (`PLOT`, `plot_kind=campsite`). GET `/workspace?node_id=...`, POST `/workspace/preview` и `/workspace/craft` возвращают `WORKSPACE_UNAVAILABLE` для других объектов. Оборудование и склады внутри дочерних построек доступны через область стоянки. Классический `/v1/craft/command` в каноническом режиме также запрещает изготовление без контекста стоянки; каталог рецептов и операции рюкзака доступны.

GET `/nodes/{id}/harvest` для мини-склада дополняется для владельца `destinations: [{id,name,kind}]`: собственные доступные рюкзак, сундуки и склады на территории стоянки. POST `/nodes/{id}/harvest-withdraw-preview` и `/harvest-withdraw` принимают необязательный `destination_storage_id` вместе с `inventory_id,quantity`. Без него сохраняется выдача в рюкзак. Чужие, удалённые и недоступные назначения отклоняются; покупка по-прежнему поступает в рюкзак покупателя. Расчёт возвращает `terms.destination_storage_id, fits`, подтверждение использует прежние `quote_id,expected_revisions,request_key`.

Данные принадлежащего игроку объекта включают единый набор параметров в `details` для всех типов; неприменимые значения могут быть null. `details.settings_json` содержит настройки объекта строкой JSON. Для чужих объектов сохраняется ограниченный публичный набор.

Основа MVP от 2026-10-07: новые карты имеют 5×5 ячеек и одну открытую ячейку независимо от типа и уровня. Настройки шаблона `map_width,map_height` позволяют изменить размеры (целые 1–1000). `map.exploration.allowed` и `can_expand` отражают права владельца действующего видимого объекта на любом уровне, включая мир, регион, город, грядку, сундук и место. Приобретённые ранее грядки сохраняют `/garden-expand`; построенный через `/builds` огород использует общий `/map-explore` и `/map-buy`. Бюджет/казна доступны для всех объектов общей модели. Фильтр `type` списка дочерних объектов принимает также `CHEST,PLACE`.

Строительство на всех уровнях начинается в `constructing` и завершается в `active` только после учтённого труда. Доступность задают `enabled,player_buildable` и явные родители шаблона. Родители должны принадлежать одному уровню; сервер вычисляет следующий уровень без фиксированной таблицы «тип → уровень». Корень — `WORLD`. Чужая принадлежащая игроку территория закрыта для строительства независимо от её уровня.

В общей модели базовый уровень исследования — 1, даже без записи профессии. Владелец может исследовать соседние ячейки после нового старта. Профессия и эликсиры нужны для дальнейшего расширения; чтение карты не создаёт профессию и не выдаёт предметы.

Карта `/nodes/{id}/map` и страница объекта включают `equipment_cells` — координаты занятых оборудованием ячеек. Они недоступны для стройки. `GET /nodes/{id}/placement-options?x=0&y=0` проверяет слот выбранной ячейки; координаты передаются парой. Без координат сохраняется выбор первого подходящего слота. Станции размещаются в действующих рабочих комнатах и местах внутри подходящих построек, с проверкой условий помещения. Размещение станции прямо на стоянке запрещено.

Сбор снабжения через крафт требует контекст собственной стоянки; интерфейс ведёт туда из мастерской. Ошибка `NIGHT_CATCHING_UP` означает незавершённый серверный расчёт здоровья: материалы не списываются, запрос можно повторить после обработки ночей. Обработчик запускается через `world-worker/run` с `WORLD_WORKER=1`.

Новый старт использует эти команды без обязательной пары quote/execute. Старые маршруты склада, рабочего места, жилья, перекопки/посева/урожая продолжают обслуживать существующие модели и интерфейсы. Классический `/v1/craft` сохраняет свой прежний контракт и отметку deprecated.

Прямое размещение, перемещение, покупка готового помещения/огорода, старый onboarding и развёртывание шалаша помечены deprecated для схемы 38. Создание новых объектов проходит через `/start` и `/builds`; внутренние правила дерева запрещают обход стройки даже через старый маршрут. Оплаченные ранее права и история сохраняются. Запросы совместимых расширенных операций и их ограничения находятся в коллекции Insomnia.

Готовые запросы находятся в [Insomnia.json](../../Insomnia.json), папка **World · simple core**. Перед каждой новой командой меняйте `simple_request_key`; для точного повтора оставляйте его прежним.

## Цикл строительства и оснащения MVP

При отправке `/start` и `/builds` клиент сразу открывает отдельную модалку параметров с индикатором размещения; сохранение доступно после ответа. `/builds/{id}/settings` принимает название, **общий** `labor_budget` и булевый `top_up` (по умолчанию false). Увеличение разрешено при активных работниках, уменьшение запрещено. Сначала используется свободный бюджет счёта резерва; при его нехватке только `top_up=true` разрешает личную доплату ровно недостающей суммы. Иначе `INSUFFICIENT_BUDGET` без частичных изменений. Для новых строек выбирается бюджет принадлежащего владельцу родителя, иначе самого объекта; чужой или городской бюджет не используется. Старые стройки сохраняют прежний счёт. Помощники получают долю общего бюджета по учтённому труду. Неиспользованный резерв освобождается; при отмене личное финансирование нового объекта возвращается владельцу.

Build DTO дополнительно содержит `server_time` и `live_work: [{accounted_at,last_seen_at}]`. Клиент непрерывно интерполирует общий труд, ограничивая каждый heartbeat окном 60 секунд, и сверяет данные каждые 10 секунд. Завершение подтверждает только сервер. Управление находится справа на вкладке карты; отдельной вкладки развития нет. Переходы используют Vue Router, данные после команд обновляются без перезагрузки документа.

Обновление 2026-10-19: каталог `/templates` сохраняет прежние поля и envelope, принимает `per-page` до 100; проверка материалов выполняется пакетно для страницы. Создание `POST /builds` отправляется после выбора названия, `labor_budget` и `top_up` в модалке, вместе с актуальным `terms_digest`. Это позволяет явно добавить недостающую сумму с личного баланса при первоначальном размещении платного объекта.

Обновление 2026-10-21: Template и записи `/nodes/{id}/placement-options` дополнены `description` — строкой до 5000 символов, пустой для старых записей без описания. Профиль публикует описание объекта в `defaults_json.description`; DTO не требует разбирать JSON на клиенте. Описание доступно в поповере плитки, цена и время строительства показаны одной строкой. Переход к изготовлению предметов находится над общим каталогом размещения.

Чтение `/storages`, `/storage/{id}` и `/placement-options` повторно использует одинаковые SQL-результаты только в пределах одного вызова сервиса; названия объектов списка загружаются одним запросом. Кэш не переносится на следующий GET или команду. Preview и commit заново проверяют права, вместимость, ревизии и условия размещения. Клиент загружает две панели хранения параллельно и использует переданную карту либо отдельный `/nodes/{id}/map`, без повторного полного состояния мира для каждой панели.

Новые счета сразу получают опубликованную изменяемую политику казны: налог родителю 10% собранной выручки (корню 0%), срок 86400 реальных секунд; защита поступлений 3600 секунд, затем потери 1% за 3600 секунд. Уже опубликованные правила не переписываются.

Базовая цена ячейки равна `max(1, 8 - hierarchy_level)` Cr. `map.pricing.curve="rings"`: цена конкретной ячейки — база × `max(1, abs(x), abs(y))`. Ячейки одного кольца стоят одинаково независимо от предыдущих покупок. Пакет от трёх получает скидку 5%; `terms` содержит `gross_total,discount_amount,total` и цены выбранных ячеек. Например, шесть ячеек по 12 Cr: 72 Cr до скидки и 68,4 Cr после неё. Серверная quote определяет окончательную сумму.

Build DTO содержит `condition,max_condition,funding_node_id,budget_available`. Максимальная прочность — `max(1, ceil(required_seconds × 100 / 60))`; текущая — целая доля подтверждённого и ограниченного heartbeat-окном труда. Новый объект начинает с 0, несколько работников суммируют труд. Node также показывает `details.condition,max_condition` с учётом текущих сессий; клиент отображает непрерывный прогресс в прочности, завершение подтверждает сервер. Материалы стройки доступны из своего рюкзака и доступных собственных хранилищ стоянки; инструменты и станции не расходуются.

## Склад и добыча руды

Шаблон `warehouse` размещается внутри стоянки рядом с домом, кузницей и огородом. После строительства предоставляет 30 слотов; материалы — 120 досок, 100 камней, 40 верёвок, трудоёмкость 3600 реальных секунд. Общий `/nodes/{id}/harvest*` обслуживает также этот склад. Параметры `storage_capacity,allow_sales` доступны через общие настройки.

Шаблон `drilling-rig` внутри `mine` требует 300 досок, 400 камней, 100 слитков, 80 верёвок и 86400 реальных секунд труда. Шахта включается настройкой `production_enabled=true`; активный дочерний объект задаёт `extraction: {item_code:"classic-ore",seconds_per_unit:60}`. Существующая сессия добычи сохраняет принятый ресурс и скорость.

`GET /objects/{id}/mining` возвращает `{node_id,ready,working,workers,produced_quantity,pending_quantity,seconds_per_unit,server_time}` без изменений состояния. `POST /objects/{id}/mining/start`, `/heartbeat`, `/stop` принимают `{}` и `Idempotency-Key`, возвращают то же состояние и `operation_id`. Без готовой установки — `EXTRACTOR_REQUIRED`; нельзя одновременно строить и добывать. Работники в MVP — игроки с открытой страницей шахты; heartbeat 10 секунд, после обрыва учитывается максимум 60 секунд. Их труд суммируется; руда поступает в собственный дочерний склад шахты, иначе в рюкзак владельца. При нехватке места сохраняется `pending_quantity`, выдача повторяется при следующем учёте. Worker учитывает активные сессии, просроченные удаляются. Закрытая или неактивная шахта прекращает работу; повтор команды не дублирует руду.

Рецепты `classic-bed` и `classic-campfire` доступны в крафте на стоянке. Правила размещения хранятся в `world_furnishing_rule`: кровать — под укрытием или в помещении, костёр — снаружи. Для кровати создаётся место ночлега; при переносе кровати текущее назначение закрывается с сохранением истории ночей.

Огород и постройки больше не получают автоматический склад. Шаблоны `mini-storage-level-2..7` создают объект в одной ячейке, по умолчанию пять слотов; `storage_capacity` и `allow_sales` редактируются в шаблоне, разрешение продажи также в настройках объекта. Урожай поступает в первый действующий дочерний мини-склад, при отсутствии — в рюкзак. `/nodes/{id}/harvest*` для мини-склада обслуживает материалы и продукцию: установку цены, снятие с продажи, перемещение, покупку с поступлением денег в его казну. GET включает `capacity` и `allow_sales`. Продажа закрыта для оборудования, зарезервированных предметов, чужих приватных и неактивных объектов. При добавлении продукции в уже выставленную стопку цена сбрасывается. Миграция переносит существующие неявные склады в отдельные объекты, сохраняя ID хранилищ и предметов.

Ремонт использует тот же учёт труда и выплаты помощникам, что и стройка. Владелец работает без оплаты. При `/cancel` объект остаётся действующим, набранная прочность сохраняется, помощники получают заработанное, неиспользованный резерв остаётся в бюджете объекта. Материалы исходной стройки не возвращаются; хранилища, дочерние объекты и установленная кровать сохраняются.

Каталог `/nodes/{id}/placement-options` показывает совместимые предметы мебели даже до изготовления: `requires_crafting=true,quantity=0,available=false,input=null`. Положительный `id` в такой записи обозначает предмет каталога, а не переносимый inventory; ключ плитки должен отличать его от записи инвентаря. Размещение по-прежнему требует существующего предмета в собственном хранилище. Кровать размещается в крытом/внутреннем слоте, после установки позволяет назначить ночлег. Ни покупка комнаты, ни наличие шалаша без кровати не позволяют новое назначение; перемещение кровати завершает текущее назначение, сохраняя историю прошлых ночей.

## Общая основа страниц нод, 2026-10-09

В read-DTO `/nodes/{id}`, breadcrumbs и map.items добавлено `extensions: string[]`: `garden,cultivation,mining,nights,housing,gather,harvest` объявляют дополнительные блоки, не изменяя общий интерфейс. `details.condition,max_condition,repair_active` представлены одинаково. `has_finances=true` для общей модели; это не разрешение читать чужие балансы. `actions` содержит общий набор `open,explore,buy,build,repair,storage,craft,finance` с `allowed,reasons`; write-flag, выбранные координаты и ресурсы дополнительно проверяются командами/preview.

`GET /templates?parent_id=...` возвращает одинаковый каталог на всех уровнях; уровень нового экземпляра выводится из родителя, а трудоёмкость и материалы сохраняются из выбранного шаблона. Обычный `POST /builds` требует своего родителя; вступление в публичном городе остаётся отдельным `/start`.

`GET /nodes/{id}/placement-options` возвращает один каталог действующих станций, мебели и сундуков независимо от вида/уровня ноды. При наличии вещи возвращаются исходный inventory ID, quantity и проверенный input; без вещи — catalog ID, `requires_crafting=true,quantity=0,available=false,input=null`. У чужого объекта каталог публичный, личные количества и inventory IDs не раскрываются. Размещение требует своей действующей доступной ветви и свободной открытой ячейки. `workspace` доступен в любом собственном действующем объекте с членством в мире; материалы/станции из чужих или недоступных ветвей исключаются.

Команды общей модели возвращают `changed_node_ids` и в той же транзакции создают событие `world.node.changed` версии 1 с `{node_ids,command}`. Повтор по Idempotency-Key возвращает прежний результат и не создаёт новое событие. Для доставки действуют существующие подписки outbox и дедупликация inbox; названия и приватные настройки нод в это событие не включаются.


## Вложенный мир и реактивные обновления, 2026-10-09

Расширения `housing` и `equipment_expansion` независимы: ночлег поддерживают ROOM/PLACE/BUILDING, а legacy-расширение мест оборудования объявляется только для ROOM, как требует его endpoint. Клиент не вызывает endpoint расширения оборудования по признаку `housing`.

Основной экран SPA запрашивает `GET /nodes/{id}/navigation?include=tree` или `GET /?view=home&include=tree`. Ответ: `{contract_version:1,tree_version:1,server_time,capabilities,focus_id,world}`. `world` — вложенный корень доступной ветви, с полями `id,parent_id,root_id,type,code,name,label,children,children_loaded,child_count,descendant_count,population_total,extensions` и группами:

- `geo: {coordinates:{x,y},footprint}` — положение в родителе и контур.
- `state: {status,visibility,revision,portable,details,permissions,actions}` — состояние и разрешения.
- `construction: {condition,max_condition,repair_active}` — прочность и наличие ремонта.
- `owner: {id,owned_by_me,has_finances}` — публичный ID владельца и возможности текущего читателя.
- `map: {x,y,width,height}` — границы карты. У `focus_id` дополнительно `cells,equipment_cells,can_expand,exploration,pricing`.

`children_loaded=true` означает полный список доступных прямых детей; `false` — только уже включённая часть ветви. В ответ попадают путь от корня, текущий объект, его прямые дети и первая страница соседей. Потомки остальных объектов подгружаются при открытии их карт. Один снимок согласован транзакцией чтения. `WorldSnapshot` собирает вложенность из прежней пакетной выборки страницы, не выполняя SQL; активный труд всех строек также читается одной общей выборкой. Нормализованные таблицы, `parent_id` и closure остаются источником истины, без хранения или перезаписи общего JSON в БД. Прежний `include=map` и остальные read-маршруты сохраняют совместимость.

Pinia хранит одно реактивное дерево, а индекс по ID указывает на те же объекты. Карта и breadcrumbs используют ссылки на это дерево. Новые ответы меняют существующие поля и массивы на месте; частичный ответ сохраняет загруженных потомков, полный удаляет отсутствующих. Устаревшие версии не откатывают ноды. Смена сессии, закрытие мира и потеря доступа очищают соответствующие данные. После команды перечитывается текущая ветвь; открытая видимая страница также сверяется раз в 30 секунд, без перекрывающихся фоновых запросов и без перезагрузки документа.

В `equipment_cells` флаг `lodging` берётся из правил предмета, независимо от названия или иконки. При выборе собственной установленной кровати блок информации показывает назначение/отмену ночлега, текущее место, состояние защиты и переход к здоровью. Прежняя вкладка «Ночлег» убрана. `GET /nodes/{id}/nights` поддерживает `per-page=1..30` (по умолчанию 20); модалка запрашивает только страницу 1, 30 последних результатов в обратном хронологическом порядке, без фильтра и пагинации, с внутренним скроллом. Ночной журнал и здоровье остаются серверными. Доступные кнопки используют единую оранжевую палитру, отключённые — приглушённую.

## Дополнение темы 82 · 2026-10-23

Схема 41 добавляет `world_starter_funding`: одно обязательство на участника и мир. В опубликованном профиле `starter.funding=parent_budget` первая стоянка получает 250 кредитов в собственный бюджет из свободного бюджета родительского поселения. При нехватке обязательство остаётся `pending`; личный кошелёк не пополняется. Полные суммы гасятся FIFO при взносе, сборе казны и целевом финансировании родителя. Повтор команды не создаёт второе обязательство. Отмена стоянки возвращает оставшийся родительский грант родителю, не выводит его в кошелёк и не открывает повторное стартовое финансирование.

`POST /objects/{id}/mining/settings` принимает `{enabled:boolean,reward_cr:decimal-string}` и общий `Idempotency-Key`. Только владелец действующей шахты может менять условия. `GET /objects/{id}/mining` дополнен `employment`: `{enabled,reward_cr,storage_id,owner,available,reason,accepted_reward_cr,storages:[{id,name,capacity}]}`. Список складов виден владельцу; для новых партий автоматически выбирается первый действующий дочерний мини-склад типа `CHEST`; отдельный выбор склада отсутствует. Поле `storage_id` старого клиента принимается для совместимости и не задаёт назначение. Чужому работнику сервер назначает склад работодателя, игнорируя личный выбор результата. Для принятия партии нужны HP ≥60, прочность шахты ≥50%, место, свои инструменты и свободный бюджет. Цена резервируется на партию и сохраняется после изменения цены или закрытия найма. Выдача, износ, квота, опыт, оплата и снятие резерва атомарны. При временной блокировке выдачи труд и резерв сохраняются. Одновременно допускается одна незавершённая оплачиваемая партия на работника.

Вскопка своей грядки бесплатна по кредитам, расходует прочность лопаты. Чужая вскопка разрешена для свободной невскопанной грядки и оплачивается из бюджета огорода (`crop.dig_wage_cr`, сейчас 1 кредит). Расчёт добавляет `worker_reward_cr`; состояние грядки добавляет `owner`. Посадка и последующие действия остаются владельцу.

Template дополняется `minimum_labor_budget`, Build — `minimum_labor_budget,builder_limit`. Принятый минимум хранится в настройках строящегося объекта и не меняется при правке шаблона. По умолчанию минимум — 2 кредита на каждые 100 000 прочности с округлением вверх; начальная стоянка имеет нулевой минимум. Помощников одновременно не больше `floor(labor_budget / 2)`, включая возобновление просроченной сессии. Для новых объектов прочность определяется фактической глубиной размещения и возрастает к верхним уровням; явная прочность специальных шаблонов сохраняется. Завершение открывает одну начальную ячейку. Базовая цена покупки в новом профиле — 0,5 кредита за клетку ближайшего кольца; исследование само не списывает кредиты. Полный недельный маршрут проверяется с финансированием 810 кредитов на участника: 250 старт, 410 конечные заказы, 150 награды.

`closed_test.all_templates=true` совместно с серверным `WORLD_TEST_MODE=1` допускает в профиль все включённые пользовательские шаблоны, включая мини-склады; права родителя, материалы и обычные лимиты сохраняются. В DTO ноды `details.is_lodging` помечает назначенный текущему игроку ночлег. По умолчанию темы форума, включая список «мои темы», сортируются по последнему активному сообщению убыванием, затем по ID темы убыванием; явный `sort` сохраняется.

## Размещённые предметы и хранилища

В ответах `GET /nodes/{id}/map` и страницы ноды массив `equipment_cells` сохраняет координаты `x,y` и добавляет `item_id,name,icon,description,quantity,characteristics`. Характеристики — список `{label,value}`; содержат тип, размер стопки, редкость, возможности станции/ночлега и прочность, когда она учитывается для данного предмета. Иконка берётся из каталога предметов. `inventory_id,storage_id` предоставляются владельцу вещи; для остальных читателей равны null. Содержимое сундука в публичный ответ карты не включается.

Возврат выбранного предмета использует существующие `/storage/transfer-preview` и `/storage/transfer`: клиент выбирает свободную ячейку рюкзака, сервер проверяет владельца, доступность, резервирование и версии. Повтор использует тот же ключ операции. Сундук переносится с прежней идентичностью и содержимым.

Названия хранилищ `placement,stockpile` включают название объекта и назначение: «Название · Размещение» или «Название · Склад». На общей модели доступность размещения в `slots[].available` учитывает открытые ячейки карты. Старый строительный шаблон `chest` отключён миграцией `m261009_180000_world_chest_item_only`; ссылки существующих объектов сохраняются. Предмет `classic-chest` и его рецепт не отключаются.

Перенос на фронте оптимистично меняет только содержимое текущих сеток. Пока результат не подтверждён, новый перенос заблокирован. Отказ возвращает исходные ячейки и выбранную стопку; неопределённый результат сохраняет исходную команду для идемпотентного повтора. После подтверждения содержимое сверяется в фоне без удаления сеток и без перезагрузки документа.

Все суммы в интерфейсе показываются через `formatCredits`: целые числа либо максимум одна цифра после точки. `WorldCreditInput` применяет тот же формат к денежным полям и числовым плейсхолдерам. Неизменённые исходные суммы сохраняют четыре разряда в контракте. Админка использует `Money::display()`; неизменённые поля восстанавливают исходную сумму при формировании FormData, а явно изменённые поля передают новое значение.

## Назначение добычи — 2026-10-24

Состояние профильных источников `/objects/{id}/mining` дополнено `output_storages[{id,name,kind,capacity}]`: владельцу доступны его рюкзак и действующие непосредственные дочерние мини-склады; чужому работнику возвращается пустой список. Новая собственная партия по умолчанию назначается в рюкзак. `output_storage_id` может указывать только на рюкзак или такой мини-склад этого объекта; удалённые склады, сундуки и размещение отклоняются с `SOURCE_STORAGE_UNAVAILABLE`.

Работник всегда получает автоматически назначенный мини-склад работодателя. Без мини-склада оплачиваемая работа не включается (`EMPLOYER_STORAGE_REQUIRED`). Принятые партии сохраняют исходный склад и резерв оплаты, включая исторические назначения в собственный склад шахты. Новые правила не перенаправляют заработанную партию и не сбрасывают её прогресс.
