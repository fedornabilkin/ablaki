# Классический крафт

Расширение существующих `craft_*`; владелец — `user.id`, единственный кредитный счёт — `persone.credit`. Миграция `m260920_190000_extend_classic_craft` сохраняет старые строки и инвентари. Идентификаторы переносимого каталога — стабильные строковые `code`; числовые ID остаются внутренними.

Если исходные таблицы крафта ещё не создавались, эта же миграция создаёт только недостающие таблицы перед расширением. Семь исходных миграций распознают уже установленную новую схему и не пытаются пересоздать таблицы при последующем штатном migrate/up. Обе последовательности проверены на MySQL/PostgreSQL.

## API

Все запросы требуют существующий Bearer-токен аккаунта. Права на чужие инвентари клиент не задаёт.

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/v1/craft` | items, recipes, categories (включая description), stations, skills, inventory, credit, charge_credits, доступность наборов, слоты |
| POST | `/v1/craft/command` | message, replayed, актуальный state |
| GET | `/v1/craft/history?envelope=1&page=1` | items, _meta; только операции владельца, по 20 записей |

Пример тела команды: `{"action":"craft","id":123,"quantity":2,"request_key":"unique-command-key-123"}`. `id` — рецепт для craft, предмет для use/discard. Для starter/gather ID не требуется. Доступные действия: craft, starter, gather, use, discard. Количество — целое 1–100. Ключ 16–80 символов: латиница, цифры, `_`, `-`. Неизвестный результат запроса повторяется с прежним ключом; новый ключ означает новую операцию. Один ключ с другим действием или количеством отклоняется.

Набор starter выдаётся один раз (тройной объём сырья), gather — раз в календарные сутки Europe/Moscow. Выдача определяется только `gather_quantity` активных материалов каталога. Нельзя запросить произвольный предмет. Лимит новых успешных команд — 30 в минуту на аккаунт. Повторы ранее принятых команд возвращаются без повторного изменения данных.

Все записи одной операции находятся в транзакции. Порядок блокировок: craft_meta → persone владельца. Сейчас короткая общая блокировка каталога также сериализует команды разных игроков; при росте нагрузки можно заменить её версионированием каталога и отдельными блокировками аккаунтов, сохранив совместимость с импортом. Баланс меняет общий CreditLedger, история записывается атомарно.

Ингредиенты расходуются; инструменты и предмет станции сохраняются. Если один предмет одновременно ингредиент и инструмент, требуется расходуемое количество плюс одна сохраняемая единица. Предметы складываются по stack_size, максимум 200 слотов. Освободившиеся и старые пустые слоты переиспользуются. Недостаток места откатывает всю операцию.

Навык отдельный для каждой категории: уровень `1 + floor(experience / 100)`, максимум 100. Зависимый рецепт открывается после изготовления каждого requires-рецепта и достижения min_level. Расходники с use_xp дают опыт своей категории; остальные предметы не имеют скрытых эффектов. Экипировка пока является изделием инвентаря.

## Администратор

По решению владельца от 21.09.2026 списание кредитов **выключено по умолчанию**. Миграция `m260921_100000_craft_credit_switch` добавляет переключатель в `craft_meta`; до применения миграции новый код также не списывает кредиты. Рецепты сохраняют настроенные цены, но при `charge_credits=false` эффективная стоимость равна нулю, баланс не проверяется и не меняется, запись списания в history_balance не создаётся. Ингредиенты расходуются как обычно, craft_event сохраняет credit_change=0. Переключатель «Списывать кредиты за создание предметов» находится в каталоге админки и применяется через POST `/craft/catalog/settings` с CSRF и p-admin. Настройка блокируется в той же транзакционной последовательности, что и крафт, сохраняются автор и время изменения. Параметры команды игрока не могут включить оплату; повтор завершённой команды не пересчитывает её цену после переключения режима.

`/craft/catalog` в backend-приложении (тест: порт 3195). Нужны вход и `p-admin`; публичные приложения не могут исполнять эти контроллеры. Изменения требуют POST и CSRF. Старые служебные действия выдачи и крафта отключены.

В каталоге доступны редакторы категорий, предметов, станций и рецептов. Связи ингредиентов, инструментов и предшествующих рецептов задаются стабильными кодами. Сначала показывается результат проверки, затем администратор подтверждает сохранение. Нельзя изменить каталог между проверкой и применением без повторного просмотра.

Экспорт — JSON версии 1 с группами categories/items/stations/recipes. Импорт — полный каталог или пакет upsert с четырьмя группами (ненужные группы — пустые массивы), до 2 МБ. Отсутствующая в файле запись не удаляется. Проверяются типы, диапазоны, ссылки и циклы. Применение всего пакета атомарно. Имеющиеся игровые остатки, навыки и история не удаляются. Для отключения предмета/рецепта используется active=0; принадлежащие игрокам предметы остаются видимыми.

Начальный каталог скачивается в админке: 44 предмета, 34 рецепта, четыре станции. `php yii craft-setup/seed` импортирует его только при отсутствии classic-plank; повторный запуск сохраняет изменения администратора. При совпадении названия со старым каталогом добавляется суффикс «(крафт)», без замены старой записи.

## Развёртывание

Рабочая ветка: feature/09-classic-crafting. Test workflow отдельно применяет две миграции крафта (`m260920_190000_extend_classic_craft`, `m260921_100000_craft_credit_switch`) через `craft-setup/install-test` в `/var/code/ablaki`, затем начальный каталог. Команда требует явный флаг окружения CRAFT_TEST_INSTALL. Существующая команда обычного деплоя git pull / make up и production не изменены. Миграции необратимы через down: инвентари и журнал нельзя терять при откате приложения, а удаление переключателя может вернуть оплату в старом коде.

Перед production проверить резервную копию и миграцию на копии соответствующей БД; затем применить эту миграцию и начальный каталог. Сам production требует отдельного поручения владельца. SQLite-тест не заменяет CI на MySQL/PostgreSQL с параллельными запросами.

Таймеры и очереди крафта, биржа предметов и её комиссии отложены владельцем. Платежи, мир/бои, экипировка с эффектами, износ и ремонт — отдельные этапы; текущая реализация их не имитирует.
