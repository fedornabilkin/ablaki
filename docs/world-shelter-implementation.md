# Шалаш и назначение ночлега

Одиннадцатый блок, 2026-09-27. Код в `feature/09-worlds`, без запуска миграций, lint, тестов, сборки, коммита и выкладки. Далее добавлены [ночи/здоровье](world-nights-implementation.md) и [ремонт](world-shelter-repair-implementation.md); актуальный schema marker после огорода — 15. На test остаётся версия 10, для шалаша нужна штатная активация `storage_v2`. Точный кошелёк для бесплатного шалаша не требуется.

## Игровой путь

На собственной стартовой стоянке появляется панель «Шалаш и ночлег». До явного подтверждения предмета нет. Можно получить его в свободную активную ячейку рюкзака или сразу установить на стоянке, в том числе при заполненном рюкзаке. Получение бесплатно и отдельно от craft starter.

`world_starter_grant` хранит право по UNIQUE(user_id, grant_code=world-starter-shelter). Оно не зависит от мира, ревизии каталога, вкладки или наличия предмета. Повтор команды возвращает прежний результат; другая команда получения после выдачи отклоняется. Ошибка выдачи откатывает предмет, проекцию постройки и использование права вместе.

После установки игрок отдельно назначает этот шалаш постоянным местом ночлега. Закрытие вкладки назначение не отменяет. Отмена ночлега — отдельная подтверждаемая команда. Для складывания занятого шалаша нужна галочка прекращения ночлега и повторный расчёт; без свободной ячейки складывание полностью откатывается, прежний ночлег сохраняется.

## Предмет, размещение и износ

Системный предмет имеет kind=equipment, stack_size=1, один `craft_equipment_instance`, исходную прочность 100. Seed создаёт определение без выдачи вещей и не перезаписывает существующий каталог. Зарезервированный код запрещён в рецептах, станциях, расходниках и обычных командах выдачи/списания. Сложенную вещь можно переносить между обычными доступными хранилищами; экземпляр сохраняется.

Установка создаёт приватную временную BUILDING-проекцию и закрытое хранилище kind=shelter ёмкостью 1. В нём находится тот же предмет. Доступ обычных storage-команд к этому хранилищу закрыт. Складывание перемещает ту же inventory row в рюкзак, закрывает интервал размещения, выводит storage из эксплуатации и архивирует проекцию. Повторная установка создаёт новую проекцию, сохраняя instance ID и прочность. Исторические проекции не удаляются.

У шалаша нет комнаты, монтажных мест, собственного дохода или бюджета. Инвестиции направляются в стоянку. Вложенные помещения, обычный перенос постройки и размещение станций запрещены. Шалаш не расходует площадь капитальных покупок и не блокирует покупку мастерской. Детали BUILDING читают прочность из экземпляра; сохранённое техническое поле world_building.condition для шалаша не является источником истины.

Используется существующая черновая политика износа v1: на улице 4 единицы в сутки, в переносимом состоянии 0. Дробный остаток не теряется. `world_shelter_deployment` фиксирует исходные условия развёртывания. Добавленная миграцией 14 `world_shelter_protection` хранит отдельные интервалы защиты и исчерпания прочности; ремонт закрывает старый и открывает новый, сохраняя прошлое. API показывает срок текущего интервала. Это не новый опубликованный баланс и не общий WearJob. Изношенный шалаш можно сложить или [починить на месте](world-shelter-repair-implementation.md) вручную за сырьё без Cr; повторная бесплатная выдача недоступна. Будущие погода/смена ставки также должны сохранять исторические интервалы.

## Ночлег и дальнейший расчёт

`world_lodging_interval` хранит actor, deployment и серверные границы [started_at, ended_at). Nullable UNIQUE(active_actor_id) и UNIQUE(active_deployment_id) обеспечивают одно текущее место на персонажа и одного персонажа на место; закрытая история сохраняется. Все записи выполняются под общими command locks craft_meta → user/persone → registry, вместе с аудитом и outbox. Quote повторно сверяет предмет, размещение, назначение, ячейку, права и ревизии.

Ночной календарь, болезнь и выздоровление добавлены следующим [двенадцатым блоком](world-nights-implementation.md). Они включаются отдельной публикацией правил после активации хранения. До публикации API возвращает `night_resolution_enabled=false`; существующее onboarding.grace_until само по себе болезнь не запускает. Действующие участники получают полный льготный день от активации. Прошлые назначения сохраняются для истории, но не приводят к болезни за ночи до новой льготной границы.

## Контракт и отложенная приёмка

[OpenAPI](api/world-shelter.openapi.json): GET nodes/{id}/shelter; POST shelter-{claim|deploy|fold|lodge|leave|repair}[-preview]. В теле всегда два boolean `direct_deploy`, `end_lodging`; true допустимы только для claim и fold соответственно. Commit дополняется request_key, quote_id, expected_revisions. Идентификатор в пути — собственная стартовая стоянка, ID экземпляра клиент не выбирает.

После решения владельца о проверках: fresh/repeated install на PostgreSQL и MySQL/MariaDB; два одновременных claim, потерянный ответ, истёкший quote; полный рюкзак и прямое размещение; перенос через сундук; fold занятого шалаша с/без подтверждения; сохранение остатка износа и прочности; сломанное укрытие; покупка помещения рядом с шалашом; запрет инвестиций и помещений внутри шалаша; смена сессии и pending retry. Ни один из этих сценариев пока не объявлен пройденным.
