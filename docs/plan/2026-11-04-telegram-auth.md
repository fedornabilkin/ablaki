# Авторизация через подтверждение в Telegram

Цель: подтвердить вход inline-кнопкой в чате и автоматически войти в исходной вкладке. Контекст — [ТЗ](../tz/auth-social.md), уточнение владельца 4 ноября: сначала сайт/API, затем отдельно бот. [Контракт, env и порядок подключения](../architecture/telegram-auth.md).

## Группа A: Сайт и API

- [x] A1. Реализовать короткоживущие заявки, browser proof, TTL, отмену и защищённые ручки будущего бота.
- [x] A2. Создавать пользователей обычным lifecycle и безопасно привязывать Telegram к существующему аккаунту без объединения по имени/email.
- [x] A3. Добавить общую форму на вход/регистрацию/профиль, опрос и автоматическое обновление сессии.
- [x] A4. Подготовить приватные env и образцы для API и отдельного бота; включать функцию через настройки админки.
- [x] A5. Проверить ошибки, повторный вход и конкурентные подтверждения на изолированной MariaDB; добавить регрессии в CI.

## Группа B: Запуск отдельного бота

- [x] B1. Реализовать отдельный long-polling бот: /start, код сравнения, inline-confirm/deny, проверка отправителя, сохранение offset и привязки сообщения.
- [x] B2. Подготовить Docker/Compose, GitHub Actions для GHCR и opt-in SSH deploy, env-шаблон и инструкцию.
- [x] B3. Заполнить BotFather token и пройти локальную проверку; имя регистрируется автоматически.
- [x] B4. Пройти привязку существующего аккаунта, reload профиля и автоматический повторный вход через настоящий Telegram на компьютере.
- [ ] B5. Проверить настоящий Telegram → сайт на телефоне, отказ, истечение и повтор update.
- [ ] B6. Настроить VPS и выполнить серверный запуск после локальной приёмки.

## Группа C: Упрощение конфигурации

- [x] C1. Перенести код и npm-файлы бота в project, использовать Node 26.
- [x] C2. Оставить три env бота и автоматическую регистрацию имени в API.
- [x] C3. Добавить включённую настройку в БД и интерфейс администратора.
- [x] C4. Подготовить локальный Docker и обновить инструкции.

6 ноября 2026: локальный бот работает без Docker на Node.js 26. Во встроенном браузере пройдены привязка существующего аккаунта и автоматический вход после подтверждения в Telegram Desktop; переход в приложение потребовал участия пользователя. Аккаунт, баланс и рейтинг сохранены. Исправлена неоднозначная ссылка на hits в PostgreSQL ON CONFLICT; проверены PHP lint, изолированный lifecycle Telegram на SQLite и реальный счётчик с префиксом таблицы на локальном PostgreSQL (третья попытка возвращает 429, тестовая транзакция откатывается).

Docker runtime и production в эту локальную проверку не входят.
