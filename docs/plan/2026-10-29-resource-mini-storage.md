# Добыча и мини-склады

Цель: компактный блок добычи с прогрессом сверху, просмотр и покупка продукции выбранного мини-склада из родительской ноды, пять ресурсных ячеек по 100 единиц и отсутствие лишних складов внутри складов. Контекст: продолжение `feature/10-drill-map-controls`; изменения выпускаются совместно с фронтендом в test, без production и выпуска кредитов.

## Группа A: Интерфейс

- [x] A1. Спрятать пояснения добычи под иконки и вернуть живой прогресс в начало блока.
- [x] A2. Встраивать выбранный мини-склад с покупкой/перемещением в инспектор карты родительского объекта.
- [x] A3. Не показывать исследование/покупку карты без прав и не отправлять такие запросы после потери прав.

## Группа B: Вместимость и данные

- [x] B1. Исправить NPC-мини-склады на 5 ячеек, сохранить содержимое и принятые работы.
- [x] B2. Ограничить стопку в мини-складе 100 единицами при расчёте, добыче, изготовлении и перемещении.
- [x] B3. Запретить мини-склады внутри больших складов и убрать лишний мини-склад NPC с сохранением товаров и средств.

## Группа C: Проверка и выпуск

- [x] C1. Проверить права, смену выбранной ноды/сессии во время запроса, встроенную покупку, прогресс и подсказки.
- [ ] C2. Проверить вместимость, полную/неполную стопку, повтор настройки и сохранность запасов/денег на одноразовых БД.
- [ ] C3. Применить локально, выпустить парный пакет в test по короткому пути и подтвердить версию/API; расширенные проверки выполняются отдельно.

Критерии: из шахты можно купить сырьё выделенного мини-склада без навигации; выдача не переполняет 5×100; старые данные не пропадают; склад не предлагает построить мини-склад; чужая карта не показывает недоступные команды.

До выпуска: все 395 frontend-тестов прошли, сборка прошла; изменённый PHP проверен lint, короткие backend-сценарии и игровой маршрут SQLite прошли. Встроенная покупка, смена выбора/сессии, потеря прав во время расчёта и сохранение живого прогресса проверены реальными компонентами. Новые проверки данных сохраняют товарные строки/цены/деньги, откатывают неподходящую старую раскладку и подтверждают лимит 5×100 для расчёта и перемещения. PostgreSQL/MySQL выполняются на отдельной одноразовой CI-базе. Браузеры CUA не подключены; ручная визуальная проверка не заявляется.
