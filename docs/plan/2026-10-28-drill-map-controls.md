# Управление ячейками и добыча с буровой

Цель: вернуть клики в блоках исследования/покупки ячеек и учитывать работающую буровую в добыче, оплате и резерве NPC. Коэффициенты в профиле: ресурсы ×5, оплата ×3; новые кредиты не выпускаются.

## Группа A: Управление картой

- [x] A1. Разделить индикатор перехода и интерактивные действия карты, исправить недоступность мыши и проверить исследование/покупку.

## Группа B: Буровая и деньги

- [x] B1. Применять бонус только от исправной буровой внутри той же шахты; заменить кирки, сохранить принятые условия партии.
- [x] B2. Увеличить выдачу и оплату через профиль; резервировать фактическую зарплату и сохранять её при повторе/сбое выдачи.
- [x] B3. Учитывать оплату буровой при пополнении и перераспределении бюджетов NPC; сохранить средства игроков и защищённые резервы.
- [x] B4. Показать бонус и фактическую оплату в интерфейсе без повторного умножения базовой ставки при сохранении.
- [x] B5. Устранить найденную регрессию заселения после передачи города bot: разрешить стартовую стоянку в публичном городе с проверкой текущего мира; обычные стройки требуют владельца.

## Группа C: Проверка и выпуск

- [x] C1. Проверить клики/стили, обычную шахту, исправную/неисправную/чужую буровую, повтор выдачи и оплату без кирки.
- [x] C2. Проверить сохранение старой партии при изменении оборудования/профиля и недостатке места/бюджета.
- [ ] C3. Применить локально, опубликовать парный пакет в test по короткому пути и проверить API/готовность; полные проверки запускаются отдельно.

Критерии: кнопки доступны мышью; обычной шахте нужна кирка; буровая даёт указанные сервером бонусы; принятое количество и зарплата неизменны; повтор не дублирует деньги/сырьё. Браузерный инвентарь CUA пуст, поэтому доступность проверяется компонентами и правилами CSS; ручная визуальная проверка этим не подменяется.

Проверено до выпуска: lint изменённых PHP; короткие backend-сценарии auth/reward/refund/API/install; 158 проверок профиля; 739 проверок игрового маршрута с выдачей 15 камня и оплатой 3 кредита без кирки, заморозкой условий после публикации, поломкой/ремонтом буровой и повтором запроса без повторной выдачи. Фронтенд: 388 тестов в 55 файлах, сборка прошла. Обе новые проверки указателя воспроизводят ошибку на исходных стилях и проходят после исправления. Проверки PostgreSQL/MySQL выполняются на отдельной одноразовой CI-базе.
