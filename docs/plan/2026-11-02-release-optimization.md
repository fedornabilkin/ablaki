# Выбор проверок и быстрый обычный релиз

Цель: не ждать проверок неизменившихся частей приложения и не повторять первоначальный запуск мира. Сохранить проверки игровых операций, целевой MariaDB и совместимости миграций.

## Группа A: План релиза
- [ ] A1. Определять изменения относительно последней успешной публикации, включая пропущенные/неудачные релизы. При неопределённости запускать полный набор.
- [ ] A2. Пропускать деплой для документации/тестов; выбирать runtime, MariaDB и переносимость по изменениям. Полный прогон оставить ручным и регулярным.
- [ ] A3. Отделить обычный production от первоначального запуска и условно выполнять установщики старых модулей.

## Группа B: Проверки и выпуск
- [ ] B1. Устранить повтор minimum/full и повтор подготовки совместимых тестовых сценариев без изменения их утверждений.
- [ ] B2. Проверить классификацию, отказы и публикацию; прогнать полный CI перед первым выпуском новой схемы.
- [ ] B3. Обновить соглашения, опубликовать и зафиксировать результаты.

Готовность: неизменившийся runtime не собирается; nginx не ждёт игрового маршрута; игровые PHP-изменения проверяются на MariaDB; неизвестная база сравнения никогда не сокращает проверки. Production-БД не используется для тестов.
