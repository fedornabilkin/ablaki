# Критические исправления backend

## Актуализация 2026-10-29

Часть сентябрьских блокеров закрыта: ExchangeService/TransferService и игровые сервисы используют транзакции и блокировки; auth-response и финансовые сценарии включены в расширенный SQLite/MySQL/PostgreSQL CI. PHP 8.3.36 / Yii 2.0.55 опубликованы на production. Основания: [обновление runtime](done/2026-10-24-php-83-security-upgrade.md), `.github/workflows/backend-full.yml`, текущий CreditLedger. Открытыми остаются только неподтверждённые проверки, жизненный цикл токенов, секреты/лимиты входа и подготовка к кластеру; они не объявляются завершёнными по наличию CI.

Дата: 2026-09-05. Статус: финансовая основа и CI внедрены; остаются отдельные задачи безопасности и проверки.

- [ ] D5. До деплоя в кластер заменить временный файловый кеш онлайна общим хранилищем активности для всех экземпляров приложения.
- [ ] D6. Проверить единый список и счетчик онлайна при распределении запросов между экземплярами, перезапуске экземпляра и истечении окна 5 минут; зависит от D5.

Файловый кеш онлайна в `@runtime/presence` — временное решение для одного сервера.
При кластерном деплое локальные файлы и файловые блокировки не разделяются между
экземплярами приложения: каждый видит только свою часть активности. Поэтому
текущая реализация не обеспечивает корректный общий онлайн в кластере; D5–D6
обязательны до горизонтального масштабирования. Подробности текущего решения:
[исправление авторизации и онлайна](done/2026-09-06-auth-presence-fix.md).

## Проверки и критерии готовности
Из yii2:
- php -d extension=pdo_sqlite tests/release/daily-reward.php
- php -d extension=pdo_sqlite tests/release/exchange-refund.php
- php -l для изменённых PHP-файлов.

Локальные проверки выполнены на portable PHP 8.3.33 и временной SQLite-БД.
Все 9 изменённых/новых PHP-файлов прошли lint. Оба регрессионных скрипта прошли; проверена конкуренция восьми процессов.
Коммит первого этапа: c16c63c.
Исторический первый этап выполнялся на PHP 7.3.2; актуальный production-runtime — PHP 8.3.36.
Первый этап готов при успешных регрессионных проверках. Для новых выпусков обязательны действующие gates; непроверенные части B8/B9 и открытые задачи безопасности остаются в очереди.
