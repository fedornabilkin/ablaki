## Группа A: Выполненный аудит

- [x] A1. Сверить актуальные BAL/ECO/CONTENT/UI/CONUI/ACC с завершёнными пакетами и последним подтверждённым релизом; отделить реализацию от оставшейся приёмки.
- [x] A2. Проверить текущие read-only API, профиль, frontend SHA, ограничение анонимного доступа и реальную ночную политику.
- [x] A3. Пересчитать актуальный семидневный профиль без БД; зафиксировать сохранность денег, полную добычную квоту и конечный спрос.

## Группа B: Подготовка локальной приёмки

- [x] B1. Согласовать и включить единый коэффициент времени мира; сейчас 1:1. Восстановить реальные суточные ночные правила.
- [x] B2. Обнулить только локальный игровой процесс с архивом и проверкой сохранности аккаунтов, паролей, RBAC и форума.
- [x] B3. Обеспечить два старта по 250, по две награды обоих этапов и конечный выкуп ресурсов: всего 1620 кредитов из существующих средств.
- [x] B4. Восстановить bot, его публичные объекты/буровую/мини-склады, работу других участников, регулярное пополнение и продажу добычи без выпуска новых Cr.
- [x] B5. Подключить модалку чеклиста рядом с заданиями, сохранение результатов для пользователя/экземпляра мира и экспорт отчёта.

## Группа C: Ручной маршрут — ближайший шаг

- [ ] C1. Владельцу пройти маршрут двумя обычными участниками: старт из резерва, задания, строительство/оплачиваемая помощь, крафт, огород, добыча NPC без кирки при буровой, покупка вторым игроком, еда и ночлег. Сверить деньги и предметы; сохранить JSON чеклиста.
- [ ] C2. Зафиксировать отрицательные сценарии: нет роли/чужое имущество, нулевая квота, полный склад, сломанный инструмент, две вкладки, смена пользователя, потеря ответа и повтор команды. Зависит от C1; автоматические проверки не заменяют наблюдение владельца.
- [ ] C3. Закрыть визуальную/клавиатурную матрицу 360/390/768/1280 px через [QA:B1](../../../frontend/docs/plan/2026-10-29-manual-ui-acceptance.md) и ACC:B7.
- [ ] C4. Собрать результат C1–C3 в ACC:C4: версии, календарь, остатки, замечания и отсутствие блокирующих дефектов. Локальные результаты не выдавать за test/production.

## Группа D: Первое включение production

- [ ] D1. Снять read-only отчёт реальной схемы/движков, миграций, кошельков, инвентаря, резервов и активных команд. Проверить транзакционность persone/history_balance; прежний MyISAM не считать автоматически исправленным на сервере.
- [ ] D2. Для разового переноса подготовить проверяемый backup/restore, checkpoints, финансовый baseline и совместимый rollback build. Это отдельная процедура первой активации; обычный test deploy не получает dump/restore.
- [ ] D3. После C4/D1/D2 выпустить проверенную рабочую ветку через master по отдельному поручению на production; выполнить установку мира, сверку storage/wallet/accounts, профиль, время, bot и достаточные резервы существующих средств. Test-only скрипты не применять к production.
- [ ] D4. Запустить отдельный world-worker на production с теми же кодом/флагами. Проверить просроченную очередь, ошибки и перезапуск без повторных выплат/предметов.
- [ ] D5. Подтвердить HTTP двух пользователей с world-tester и отказ без роли; проверить стартовые места, задания и денежную сводку. Сохранить фактические SHA/схему/профиль и решение о допуске.

## Группа E: Эксплуатация и дальнейший допуск

- [ ] E1. На целевом контуре измерить нагрузку выбранной пары, p95, backlog и восстановление worker; перед расширением повторить с новым размером группы.
- [ ] E2. Назначить ответственного и проверить остановку новых записей с сохранением чтения, сверкой активов и совместимым откатом.
- [ ] E3. Подготовить отчёт когорты с денежным baseline и различать retention по игровому действию и простой визит; не трактовать отсутствие команды как отсутствие визита.
- [ ] E4. После реального запуска наблюдать D1/D7 и дефициты. Для открытого допуска закрыть BAL:B3/B4: конечный пул NPC/мира и спрос могут исчерпаться, натуральный минимум не является гарантированным денежным доходом.
- [ ] E5. В нагрузочном прогоне E1 измерить ожидание общих блокировок `craft_meta`/`world_registry` в `Command` и `CommandBus` и определить предел перед расширением группы. Наличие этих блокировок подтверждено кодом; фактическое влияние на пропускную способность пока не измерено.

## Критерии готовности

Для технического включения пары нужны зафиксированная ручная приёмка, сверенная production-активация, обеспеченный старт и работоспособная эксплуатация. Потеря/дублирование вещей или кредитов, обход прав и невозможность базового старта блокируют допуск. D7/D30 появляются после наблюдения и не являются предварительным ожиданием. Предел двух минут на выкладку и серия десяти замеров ведутся в [отдельном плане](2026-10-19-test-deployment-optimization.md).
