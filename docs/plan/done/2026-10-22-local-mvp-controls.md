# Локальный MVP: время, снабжение, средства и история

## Цель и контекст

Поручение владельца 2026-10-22 заменяет предложение отдельного контура: использовать существующую локальную БД, очистить игровой прогресс и подготовить ручную проверку двумя пользователями. Общий коэффициент времени первоначально 1:1. Test и production не сбрасываются; пользователи, авторизация, личные средства и неигровые разделы сохраняются.

## Группа A: Время мира

- [x] A1. Сделать единый коэффициент скорости с непрерывным календарём и начальным значением 1:1; сохранить историю и принятые условия действий при изменении скорости.
- [x] A2. Подключить коэффициент к игровым длительностям и ночам, дать управление в админке.

## Группа B: Финансовая картина

- [x] B1. Точно рассчитать стартовые средства, конечный спрос и награды на двух участников без новой эмиссии.
- [x] B2. Показать на главной странице мира в админке личные средства, бюджеты, казны, резервы и дефицит обеспечения.

## Группа C: Конечное снабжение

- [x] C1. Общим серверным правилом ограничить и уменьшать ежедневные выдачи по предметам; исключать ресурс после постройки соответствующей добычи.
- [x] C2. Показать остаток на кнопке и скрывать исчерпанный сбор; новый предмет открывает новую конечную выдачу без обновления старых запасов.
- [x] C3. Пересчитать ранний и недельный маршруты с новым конечным снабжением.

## Группа D: Биржа и история

- [x] D1. Исправить отказ списка биржи на старых типах заявок без изменения или исполнения неопределённых заявок.
- [x] D2. Показывать названия, количества и направления вещей в истории сбора, изготовления, покупок и продаж, сохраняя приватность.

## Группа E: Проверка и локальная подготовка

- [x] E1. Проверить PHP 7.3, PostgreSQL/MySQL, гонки снабжения и финансов, клиентские тесты и сборку.
- [x] E2. Очистить только локальные игровые данные с проверкой сохранности пользователей/кошельков и установить новый профиль с временем 1:1.
- [x] E3. Проверить реальные локальные API, админку и интерфейс двух пользователей; записать адреса и условия ручного маршрута владельца.

## Критерии готовности

Коэффициент влияет на время мира, число конечных выдач нельзя обойти старым API или повтором команды; администратор видит обеспеченность обоих участников, история объясняет состав операций, биржа открывается с историческими записями. Локальные пользователи и неигровые средства сохранены; внешний выпуск выполняется отдельно.

## Результат и проверка

PHP 7.3 lint всех изменённых/новых PHP-файлов успешен. На отдельных существующих loopback `ablakin_ci` MySQL 3306 и PostgreSQL 5432 пройдены target-database, world-feedback-food, world-economy-gameplay и world-economy-race. Реальные команды завершают недельный путь до дома и склада на 50 мест с конечными выдачами; шесть конкурирующих сборов дают одну выдачу, точные повторы возвращают прежнюю операцию. Проверены откаты и повтор после частичного DDL. Профиль/конечная неделя и расширенный runtime прошли SQLite; отдельная проверка финансов обеих серверных СУБД подтвердила точные новые поля выплат. Реальный SQLite gameplay подтвердил отсутствие повторного требования уже выплаченных средств.

357 frontend-тестов в 55 файлах и сборка прошли. Playwright проверил реальную биржу, финансовую главную/настройку коэффициента в админке и вход LocalMvp01/LocalMvp02 с заданиями на 1440/390 px без ошибок страницы и переполнения. Проверены обычные роли, отрицательный допуск, отсутствие членства и стартовых игровых действий у обоих участников, реальные окна ночи 22:00–06:00.

Сброс затронул 201 игровую таблицу; 39 сохранённых таблиц совпали по контрольным суммам после установки. Из существующих средств подготовлены 500 стартовых переводов, 820 спроса и 300 наград; эмиссии нет. Подробности и адреса — в [локальном отчёте](../../operations/local-world-reset.md). Артефакты/логи и пароли остаются вне Git в `temp/mvp-local-controls` общего workspace. Ручное полное прохождение оставлено владельцу, внешний test не выкатывался.
