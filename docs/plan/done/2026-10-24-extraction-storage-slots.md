# Добыча, ежедневное снабжение и покупка слотов

Цель: закрепить добычу работников за мини-складом объекта, дать владельцу выбор рюкзака или местного мини-склада и устранить разные цены расширения рюкзака. Текущий прогресс и принятые партии сохраняются.

## Группа A: Правила сервера

- [x] A1. Автоматически выбирать действующий дочерний мини-склад для новых оплачиваемых партий; сохранять склад уже принятых партий.
- [x] A2. Ограничить выбор владельца рюкзаком и мини-складом текущего объекта, по умолчанию использовать рюкзак.
- [x] A3. Использовать единый прогрессивный расчёт и команду покупки слотов из разных страниц; оставить совместимый адаптер старого API.
- [x] A4. Заменить исключение сырья после постройки источника на уменьшение выдачи вдвое с округлением вверх, сохранив конечный лимит и убывание.

## Группа B: Клиент и контракт

- [x] B1. Показывать начало перехода по двойному клику и исключить повторные переходы.
- [x] B2. Заменить выбор складов кнопками владельца и убрать настройку склада работников.
- [x] B3. Подключить общий компонент и API покупки слотов к инвентарю и размещению.
- [x] B4. Обновить API-документацию и Insomnia.

## Группа C: Завершение

- [x] C1. Проверить снабжение, направление добычи, цены, повтор и конкуренцию на PostgreSQL/MySQL, клиентские сценарии, сборку и браузер; сохранить рабочие ветки.

Критерий готовности: один и тот же прирост рюкзака имеет одну цену и команду; новая добыча поступает только в допустимый склад, камень остаётся в доступном ежедневном снабжении после постройки шахты, индикатор перехода виден сразу.

## Результат и проверки

Профильная добыча владельца по умолчанию назначается в рюкзак; доступны только рюкзак и действующие дочерние мини-склады текущей ноды. Новая оплачиваемая партия автоматически получает местный мини-склад, без него найм не включается. Старое поле настройки назначения игнорируется; уже принятые партии сохраняют склад и оплату.

Общий компонент инвентаря и размещения использует `/economy/storage/{id}/expand-preview` и `/expand`. Для рюкзака сервер возвращает `backpack-N` с единым прогрессивным расчётом: при базовой цене 10 первые десять мест стоят 550, следующее 110. Старый `buy_slots` остаётся совместимым адаптером того же расчёта и записи. Дешёвый итог старого пакета отклоняется.

Построенный источник уменьшает соответствующее ежедневное сырьё вдвое с округлением вверх. Конечный лимит, строгое убывание, принятые базовые параметры и прежняя история сохраняются. Реальная локальная read-only проверка вернула камень: 6 единиц, ещё 4 сбора, уменьшение 5000 bps. Новых миграций, публикации профиля или изменения локальных балансов/вместимости не потребовалось.

Пройдены PHP 7.3 lint, SQLite-сценарий `world-feedback-food` со всей цепочкой зависимостей; PostgreSQL и MySQL — `world-feedback-food`, недельный `world-economy-gameplay`, `world-economy-race`. Проверены атомарная выдача/зарплата, сохранение заработанной партии при заполненном складе, точный повтор, прогрессивные цены и шесть одновременных покупок слотов с одним списанием. Для проверки гонки используются собственные средства фикстуры в одноразовой CI-БД.

381 клиентский тест в 55 файлах и production-сборка прошли. Проверены смена сессии, отказ перехода, изменение выбора ячейки во время перехода, сохранение редактируемой оплаты при автоматической смене мини-склада и возврат назначения в рюкзак при исчезновении склада до начала партии. Chrome проверил видимый индикатор нативного двойного клика, защиту повтора, общий API и одинаковую цену на двух страницах, отсутствие выбора склада работодателя, рюкзак по умолчанию и мобильную ширину. Баланс и вместимость локального игрока после браузерной проверки не изменились; реальные покупки и добыча не запускались. Логи/снимки: `temp/extraction-storage-slots` вне Git. Контракты и Insomnia обновлены.
