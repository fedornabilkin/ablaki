# Единый цикл объектов MVP

Цель: единое размещение и строительство на всех уровнях, с реактивным интерфейсом и явным оснащением объектов.

Контекст: локальный запуск после переустановки мира. Требуется сохранить имущество и финансовую историю существующих объектов.

## Группа A: Строительство и оснащение

- [x] A1. Реактивная навигация, плоские блоки, строительство справа на карте, отдельные модалки.
- [x] A2. Название и пополняемый бюджет после размещения, плавный прогресс с серверной сверкой.
- [x] A3. Начальный шалаш, более дорогой дом, кровать и костёр с размещением и ночлегом.
- [x] A4. Правила казны для новых объектов, стоимость ячеек по уровню.
- [x] A5. Явный мини-склад вместо автоматических складов, хранение и продажа продукции.
- [x] A6. PostgreSQL-проверки команд и миграций, frontend unit/build, проверка локального интерфейса.

Изменения применяются к локальной БД. Существующие предметы и финансовая история сохраняются; тестовые проверки выполняются на отдельной копии.

## Критерии готовности и результаты

Миграция `m261008_120000_world_mvp_facilities` установлена на `ablaki_local`: число объектов 15 → 16, все 23 строки с предметами сохранены; неявных действующих складов не осталось. Существующий склад огорода преобразован в дочерний мини-склад. API 3180, админка 3195 и frontend 5173 работают с локальной PostgreSQL 55432.

- PHP: 77 файлов прошли парсер PHP 7.3 и runtime lint.
- Общий SQLite regression: 465 проверок крафта, совместимых операций и админки прошли. Старая схема проверяется до преобразования; новые миграции применяются в соответствующем порядке.
- PostgreSQL `ablaki_world_reset_checks`: чистая установка, 24 проверки бюджета, идемпотентности, оплаты труда, возврата остатка, оснащения, ночлега, продажи и цен ячеек. Изменения сценариев откатываются транзакцией.
- PostgreSQL: повтор новой миграции сохраняет ID и количество предметов старого склада, не создаёт дубликаты и сохраняет изменённые администратором настройки.
- Frontend: 46 файлов / 282 unit-теста, production build; после заключительных правок повторены затронутые тесты и сборка. Отдельная проверка прогресса покрывает дробное время, нескольких работников и предел 60 секунд после heartbeat.
- Браузер на копии БД: старт в городе, имя и бюджет, строительство справа, плавный прогресс, пополнение во время работы, завершение, доступный шалаш и недоступный начальный дом, адаптивная модалка. Все переходы выполнены одним документом через Vue Router, ошибок JS/HTTP нет.
- Браузер на рабочей локальной БД: чтение преобразованного мини-склада без ошибок; проверка выполняла только GET/HEAD/OPTIONS.

Логи, сценарии и скриншоты находятся в общей `temp/world-mvp-flow`, вне репозиториев. Обновлены архитектура, контракт API и Insomnia. На внешние окружения изменения не выкладывались.
