# Согласование API и запросов фронтенда

Цель: проверить публичные маршруты и их потребителей, убрать дублирующие запросы и реализации, объединить совместные чтения экрана и согласовать вложенные ответы.

Контекст: Vue SPA использует общий транспорт, но сохраняет старые адаптеры и несколько поколений API мира. Совместимость существующих клиентов, права, транзакции и идемпотентность игровых команд должны сохраниться.

## Группа A: Инвентаризация
- [x] A1. Сопоставить зарегистрированные API-маршруты, действия контроллеров и запросы SPA по всем разделам.
- [x] A2. Проверить дубли адресов, одинаковые реализации, лишние последовательные запросы и расхождения ответов.

## Группа B: Объединение
- [x] B1. Выделить общие вложенные ответы для совместно загружаемых данных; перевести потребителей на них.
- [x] B2. Устранить повторные чтения и дублирующие адаптеры с сохранением границ пользовательской сессии.
- [x] B3. Упорядочить регистрацию маршрутов и обозначить совместимые исторические адреса.

## Группа C: Проверки и документация
- [x] C1. Проверить контракты, права, ошибки, повтор команды и смену сессии; собрать SPA.
- [x] C2. Обновить Insomnia, карту API и результаты проверки с явными границами охвата.

Готовность: у каждого используемого адреса есть понятный владелец и контракт; общие чтения не дублируются; операции не теряют защиту от повторов; нет массовой смены адресов без миграции потребителей.
