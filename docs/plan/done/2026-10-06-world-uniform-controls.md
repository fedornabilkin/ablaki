# Единые формы и управление огородом/крафтом

Цель: понятный склад урожая и карта огорода, один итоговый расчёт крафта после ввода количества, единые формы сущностей.
Контекст: локальная PostgreSQL ablaki_local, API 3180, админка 3195, frontend 5173. Сохранить текущие изменения; удалённые базы не изменять.

## Группа A: Фронт

- [x] A1. Разделить перемещение урожая и управление продажей на два блока.
- [x] A2. Отличить закрытые грядки от открытых; показать управление открытием рядом с картой.
- [x] A3. Отправлять итоговый расчёт количества с debounce; исключить устаревшие ответы и таймеры после ухода.
- [x] A4. Крафт доступен только на собственной стоянке; дать переход при нехватке ресурсов размещения.
- [x] A5. Пустые ячейки рюкзака без видимых надписей.

## Группа B: Единый интерфейс

- [x] B1. Все настройки и поля шаблонов видимы независимо от типа, без индивидуальных исключений по названию/коду.
- [x] B2. Одна форма объектов с общими настройками и полями; служебные вычисляемые поля видимы только для чтения. Поля создания и редактирования каталога совпадают; подпись предмета сохраняется, пустая наследует название.
- [x] B3. Убрать индивидуальные исключения фронта в отображении данных; сохранять серверные права и ограничения операций.

## Группа C: Проверка

- [x] C1. PHP lint и серверные проверки ограничения крафта/форм.
- [x] C2. Unit-тесты, сборка, браузерные сценарии, документация API и Insomnia.

Критерии готовности: сценарии выполнены и проверены локально, настройки сохраняются, API не позволяет обойти ограничение крафта.

Результаты: 266 unit-тестов в 46 файлах, production-сборка, PHP lint и синтаксис PHP 7.3 для 59 изменённых/новых файлов, регрессия `world-ui-admin/behavior.php`, 14 адресных проверок PostgreSQL с откатом изменений. Браузер: реальные формы разных шаблонов и объектов, создание/редактирование каталога и предварительный просмотр подписи, реальные параметры объекта на мобильном экране; контролируемые ответы API для закрытых грядок, блоков урожая, выбора назначения, debounce и пустых ячеек. Экономические операции отдельно проверены сервером. Проверки и снимки находятся в корневой `temp/world-uniform-controls/`.
