# Стартовые объекты NPC и минимальный сбор

Цель: сохранить ежедневный минимальный сбор после расходования стартового запаса; добавить песок и глину; передать публичные территории основному NPC `bot` и подготовить в Северограде общедоступную инфраструктуру. По ответу владельца бюджеты пополняются только существующими средствами bot/мира и выручкой, без выпуска Cr. Игровой процесс участников не сбрасывается.

## Группа A: Снабжение

- [x] A1. После убывающего запаса выдавать по одной единице сырья раз в сутки, сохраняя принятые выдачи и блокировку повтора.
- [x] A2. Добавить песок и глину в профиль снабжения, расчёт и интерфейс; обновить объяснения и таймер.

## Группа B: Инфраструктура

- [x] B1. Повторяемо передать действующий мир, регионы и поселения пользователю bot с аудитом, сохраняя имущество игроков.
- [x] B2. Создать стоянку, шахту с буровой, кузницу, мастерскую, шесть участков/источников, две ловушки и склад; добавить мини-склады и оборудование.
- [x] B3. Открыть оплачиваемую работу на стартовых источниках и использование станций NPC, сохранив личные инструменты, квоты и резерв принятой оплаты.

## Группа C: Деньги и продажа

- [x] C1. Регулярно пополнять свободные бюджеты объектов из существующих денег NPC и публичных территорий; не расходовать зарезервированные суммы или деньги игроков.
- [x] C2. Автоматически выставлять добытое сырьё на продажу из мини-складов и возвращать собранную выручку в работу NPC через существующий журнал казны.
- [x] C3. Показывать понятные условия работы/продажи, недоступность при недостатке инструмента/здоровья/квоты и состояние финансирования.

## Группа D: Проверка и запуск

- [x] D1. Проверить минимум после исчерпания, день/повтор/новый каталог, NPC-настройку без дублей и сохранность денег/вещей.
- [x] D2. Проверить работу двух игроков, однократную оплату, покупку/переполнение/права и изготовление на чужой станции на поддерживаемых СУБД.
- [x] D3. Применить к локальному миру, проверить интерфейс и минимальный путь тестовой выкладки; сохранить актуальный список приёмки MVP.

Критерии готовности: минимальный сбор не исчезает и не повторяется в одни сутки; инфраструктура принадлежит bot и доступна участникам; выплаты и продажи объяснимы журналом; повтор установки не создаёт объекты/средства повторно. Успех CI не заменяет ручной путь двух игроков, проверку первого дня и недели, мобильного интерфейса, ночи/еды и восстановления после обрыва/перезапуска.

## Проверки реализации

- PHP 8.3.36: lint изменённых файлов; профиль/CLI, авторизация, награды, возвраты, маршруты API, установка и контекст команд.
- SQLite: минимальный сбор после пяти выдач, запрет повтора/день/новый каталог; NPC-настройка без дублей, зарплата и покупка с повтором, изготовление на общей станции без доступа к чужим материалам; сбор выручки, защищённая оплата, worker, исчерпание денег и административная сводка.
- PostgreSQL и MySQL/MariaDB: новые NPC-сценарии и конкурентные проверки с шестью процессами на отдельной `ablakin_ci`; сохранность сумм и частичный DDL проверены. Боевые данные не использовались.
- Frontend: 384 unit-теста, включая минимум и навигацию общего workspace; production build. Сценарии deployment guards проходят, минимальный путь test и отложенный полный CI сохранены.
- При сборе всех ежедневных выдач офлайн-недельный маршрут упирается в 21-ю ячейку. Требуется перенос лишнего сырья в уже установленный сундук; проверка бюджета при наличии места проходит. Это включено в [ручную приёмку MVP](../../architecture/economy-mvp-verification.md).

## Применение и тестовый выпуск

Локально: мир 1, bot 6, стоянка 17; создано 26 нод со вспомогательными мини-складами и три станка. Профиль 5, схема 44. В бюджеты 14 объектов переведено 280 кредитов из существующего свободного бюджета Северограда; осталось 673,35 в бюджете города и 1,4 в кошельке bot. Общая сумма до и после — 124138,1753; вещи, кошельки и частные объекты участников сохранены. Стартовый резерв Северограда пока пуст, одна стоянка ожидает 250 кредитов; для двух участников расчёт требует 1620 кредитов с заказами и наградами. Пополнение стартового резерва остаётся явным действием владельца перед ручным маршрутом.

Сначала финансируется минимум одной партии на каждом источнике. При нехватке общего запаса допустимы свободные буферы других объектов NPC; у других источников сохраняется оплата хотя бы одной новой партии, принятые резервы не трогаются. Затем при наличии средств заполняются целевые буферы по 20. Исчерпание конечного запаса отражается недостачей в админке, без выпуска денег и без скрытого списания у игроков.

Тест: backend `8872c4e9700d2fe02c57bb104731e9baa9830bb2`, frontend `a33897d7a09e09d094859fabcf8e5682b45966a2`; стоянка NPC 28. Авторизованные HTTP-проверки входа, карты, работы у источника, станка кузницы и магазина прошли, ответы 200. Backend readiness: PHP 8.3.36, схема 44, профиль 5, `npc_ready=true`, нет ожидающих миграций. Контрольный запуск worker выполнил две задачи без ошибок; постоянный worker запущен.

Первый cold-выпуск прервался при контрольном запуске worker после успешной установки схемы/объектов; CI не сохранил текст причины, код возврата 255. Данные и установочные checkpoints сохранились. Добавлены ограниченная диагностика preflight без окружения/аргументов/трассировки и подъём API перед этой проверкой. Успешный повтор не создавал объекты/деньги повторно. Это не считается установленной причиной первой ошибки.

Последний успешный backend run: [40760022368](https://github.com/fedornabilkin/ablaki/actions/runs/40760022368) — минимальные проверки 23 с, deploy 52 с, полный отложенный прогон SQLite/MySQL/PostgreSQL 94 с, всё успешно. Frontend: [40758452534](https://github.com/fedornabilkin/ablaki-front/actions/runs/40758452534) — минимум и сборка 38 с, deploy 26 с, отложенные тесты 27 с, всё успешно. Это длительности отдельных jobs, не всей работы над задачей.

Ручная визуальная приёмка и игровой путь двух аккаунтов перед production остаются за владельцем по списку MVP; их не подменяют компонентные тесты и HTTP smoke. Production не выкатывался.
