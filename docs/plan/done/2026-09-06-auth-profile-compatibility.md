# Авторизация с прежней схемой профиля

## Цель и контекст

Устранить UnknownPropertyException Person::description при сериализации ответа
site/login-key. Необязательная колонка может отсутствовать в существующей схеме
либо в её кеше. Восстановленные Docker, make up и настройки БД не меняются.

## Группа A: Исправление

- [x] A1. Проследить ответ LoginForm → User → Person.fields и проверить использование description клиентом.
- [x] A2. Воспроизвести реальную авторизацию на временной SQLite без description — до исправления получен тот же UnknownPropertyException и стек сериализации.
- [x] A3. Вернуть null для недоступного description, сохранив значения существующей колонки и ограничения приватных полей.

## Группа B: Проверка и публикация

- [x] B1. Проверить login-key, вход по паролю, актуальный token и публичный профиль на обеих схемах — 23 проверки прошли, включая неверный ключ, null и пустую строку.
- [x] B2. PHP 7.3 lint, frontend-lists, frontend-api-routing, actionlint и diff --check прошли. Docker/runtime по-прежнему совпадают с c875c7c.
- [x] B3. Подключить регрессионную проверку в CI и подготовить исправление к публикации в master.

## Критерии готовности

Первый CI для 524d509 выявил отсутствующую настройку переводов user в новом
изолированном тесте. Добавлен явный PhpMessageSource из yii2-user; прикладное
исправление Person от этого не меняется. Повторные 23 локальные проверки прошли.

Повторный CI для 253b089 выявил ту же зависимость тестового приложения от
сгенерированного vendor/yiisoft/extensions.php: Finder не получил userQuery.
Отключение автозагрузки расширений через extensions=[] воспроизвело ошибку локально.
В тест добавлен явный dektrium/user Bootstrap, и все 23 проверки прошли на PHP 7.3
с отключённой автозагрузкой расширений. Конфигурация приложения и деплоя не менялась.

Ответ авторизации сериализуется при отсутствии description и сохраняет прежний
контракт при наличии поля. Миграции и подключение БД не меняются. Вход по прежнему
одноразовому ключу может потребовать нового ключа: loginKey меняет auth_key до
сериализации ответа даже в старом коде; эту логику данное исправление не меняет.
