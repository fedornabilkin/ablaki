# Авторизация и активность пользователей

## Цель и контекст

Восстановить онлайн и защищенные ручки, гарантировать непустой сохраненный токен после успешного входа. Публичный production GET online-count подтвердил HTTP 500 из-за отсутствия user_presence. Владелец прямо исключил эту таблицу: удалены миграция из коммита 959b8af и обращения к ней. Docker и production-данные не меняются.

## Группа A: Исправления

- [x] A1. Хранить активность только в файловом кеше с блокировкой между PHP-процессами и окном 300 секунд; убрать таблицу и миграцию из кода.
- [x] A2. Отделить ошибки записи активности от авторизации; записывать активность при входе.
- [x] A3. Восстанавливать пустой auth_key при входе по паролю; проверять сохранение токена; неверные учетные данные возвращают 401.

## Группа B: Проверки

- [x] B1. Проверить login/login-key, пустые ключи, неизвестного пользователя, неверный пароль и отказ записи токена на временной SQLite.
- [x] B2. Проверить полный dispatch heartbeat, online и forum-theme/my?page=1&sort=-id&envelope=1 без таблицы активности, фильтрацию по автору и границу 5 минут.
- [x] B3. Пройти PHP 7.3 lint, auth-response, frontend-api-routing и frontend-lists; обновить контракт.

## Критерии готовности и ограничения

Регрессии выполняются на PHP 7.3.33 с изолированными SQLite и runtime. На production выполнен только публичный диагностический GET. Владелец разрешил commit/push master с русскими сообщениями; push запускает штатный CI и деплой. Файловый режим поддерживает один сервер с общим runtime. Наличие пустого auth_key у конкретного пользователя не подтверждено: обычный вход до изменения проходил локальный тест; добавлены проверки пограничных случаев.
