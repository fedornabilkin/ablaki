# Открытие закрытых грядок

Цель: на огороде №10 виден рабочий способ открыть следующие грядки.
Контекст: локальная копия БД; не менять права или баланс пользователя при проверке. Сохранить текущие изменения.

## Группа A: Причина и исправление

- [x] A1. Проверить реальное состояние №10 и восстановить получение условий открытия. Причина: `details` родителя возвращается объектом, обращение как к массиву давало 500.
- [x] A2. Показывать управление перед складом урожая, действия перед списком грядок и ошибку загрузки вместо скрытого блока. Добавлена ссылка над картой с прокруткой к форме; при нехватке бюджета — объяснение, ссылка на пополнение и согласие на доплату.

## Группа B: Проверка

- [x] B1. Проверить серверное состояние и расчёт открытия на локальной PostgreSQL без сохранения покупки. Шесть проверок: одна открытая грядка, цена следующей 10 Cr, бюджет 1,8 Cr, доплата 8,2 Cr, права/баланс неизменны. Записи preview откатились.
- [x] B2. Проверить браузером огород №10, ошибки загрузки, unit-тесты и сборку; обновить документацию. Реальный HTTP API владельца и экран №10, девять замков, цена/бюджет/согласие, прокрутка обеих ссылок, мобильный экран. Ошибка API воспроизведена подменой ответа и остаётся видимой с повтором. 268 unit-тестов, production-сборка, PHP 7.3 parser/runtime lint 60 файлов и diff-check прошли. Документация API/UI и Insomnia обновлены.

Критерий готовности: владелец видит стоимость и кнопку открытия, сбой API не скрывает управление, игровые данные при проверке не меняются.

Артефакты проверки: корневая `temp/garden-unlock/`. Серверная экономическая операция не выполнялась: проверен реальный preview с откатом, в браузере подтверждена доступность кнопки после явного согласия на доплату.
