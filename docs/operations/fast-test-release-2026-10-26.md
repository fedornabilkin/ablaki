# Минимальные проверки и быстрая тестовая выкладка — 2026-10-26

Новая версия test публикуется после коротких необходимых проверок. Полные backend/SQLite/MySQL/PostgreSQL проверки и Composer audit выполняются отдельным job после успешной публикации. Полные frontend unit-тесты также идут после публикации. Production сохраняет полный обязательный прогон до deploy.

Перед backend обязательны lint изменённого PHP, проверка deploy-скриптов, locked Composer/platform, авторизация, ежедневные награды, возвраты биржи, маршруты API, установщик и аудит профиля при наличии мира. Перед frontend — авторизация/HTTP-клиент, проверки окружения и скриптов, сборка. Ошибка любого обязательного job блокирует deploy.

При неизменной установке backend пропускает повторные seed/backfill и остановку worker. Это подтверждается fingerprint установочных файлов, отсутствием pending, состоянием управляемых миграций, storage/wallet и флагами мира. Изменённая установка проходит прежние additive activity/craft/forum/world установщики; посторонние исторические миграции не воспроизводятся. Выпускается ровно проверенный commit, даже если ветка успела продвинуться. Публикация изменённого файла профиля встроена в выпуск; неизменённый файл сохраняет административный профиль. Кредиты не выпускаются, игровой процесс не сбрасывается.

На frontend используется rsync с проверкой содержимого в промежуточный каталог. Передаются только изменившиеся файлы; перед активацией проверяется полный список и SHA-256 каждого файла по манифесту CI. Затем сохраняются прежние проверки архива, HTTP-версии и восстановление прежней статики при ошибке. Для первого такого выпуска вместо полного архива 1,9 МБ передался один файл 41 байт; SSH-сеанс переиспользуется. Серверный deploy сократился со 111 до 17 секунд.

Два повторных замера подтверждают короткий рабочий путь, а не безусловную гарантию времени для холодной установки или любого изменения схемы.

## Проверка внедрения

Проверены 30 shell-сценариев и Linux-сигналы TERM/QUIT worker, 48 тестов frontend-автоматизации, недоступная схема, сохранность инвентаря/истории миграций, профиль с административными изменениями, публикация без выпуска денег и повторное применение. Для incremental frontend проверены повторное использование файлов, полный манифест, отказ при порче и сохранность прежней версии. Полные дополнительные проверки backend на SQLite/MySQL/PostgreSQL и все frontend unit-тесты успешно прошли после первой публикации; очередной backend-прогон после усиления проверки commit выполняется независимо от доступности стенда.

Готовность означает зелёный `Deploy backend to test` / `Deploy frontend (test)` и выполненный HTTP smoke. Не ждать окончания дополнительных jobs, чтобы сообщить о доступности версии. Бэкапы/restore в test deploy не возвращались; production не публиковался.

Логи и вспомогательные сценарии: `temp/fast-test-release-artifacts/` общей рабочей папки, вне Git. Рабочие ветки обоих репозиториев: `feature/10-fast-test-release`; тестовые изменения опубликованы в `test`.
