## Проверки и оставшиеся границы

Локально пройдены PHP 7.3 parsing/runtime lint 68 файлов, недельный маршрут и гонки на MariaDB/PostgreSQL, профиль/источники/ошибки, повтор подготовки на полной копии. CI frontend: **329 тестов, 51 файл**, сборка успешна. При проверке настоящего test выявлены и исправлены два отличия от упрощённых фикстур: пробелы в старых PostgreSQL `CHAR` полях истории и допустимый вид `shelter` в аудите хранения. Недельная PostgreSQL-проверка теперь использует старые `CHAR(50)`/`CHAR(255)`; отдельная проверка отклоняет неправильную вместимость шалаша.

API нового тестера: экономика, состояние старта и история переводов — HTTP 200; чужая история — HTTP 403. Отрицательный контроль: чтение экономики, старта и команда старта — HTTP 403; обычный профиль сайта — HTTP 200. Это подтверждает серверное ограничение мира и сохранение доступа к другим разделам.

Существующий календарь общего test неизменяем: сутки 3600 секунд, ночь последние 900 секунд. Расчёт семи дней проверен на отдельной копии с реальными сутками 86400 секунд и календарём Europe/Moscow. Для внешней недельной волны требуется отдельное решение о мире/календаре; существующая политика не перезаписывалась.

Визуальная и клавиатурная приёмка 360/390/768/1280 px остаётся открытой. В предыдущем запуске автоматическая проверка разрешений отклонила Google Chrome без дополнительного объяснения; скриншотов и браузерного заключения нет. Фактические D1/D7/D30 и решение о запуске волны не заменяются CI. После исчерпания конечных заказов постоянный денежный заработок не обеспечен: BAL:B3/B4 остаются открытыми, [расчёты](../architecture/economy-balance-conclusions.md).

Артефакты: `temp/world-mvp/release-manifest.json`, `release-backup.json`, `remote-{before-prepare,prepared,check,final}.json`, `remote-release-checks.json`, `remote-domain-audit.json`, `remote-frontend.json`, `release-legacy-char-pgsql.log` и логи GitHub jobs. Они находятся вне Git. `check-remote-release.py` подтверждает сохранение общей суммы, готового маршрута и недельного каталога, корреляцию старой истории, серверный допуск, актуальность очереди и SHA frontend.
