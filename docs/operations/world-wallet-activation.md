# Активация точного кошелька и начальные финансовые связи

Дата: 2026-09-27. Седьмой блок `feature/09-worlds`. Реализован код; **проверки, отчёты, перенос, активация, коммиты и выкладка не выполнялись** по поручению владельца. Продолжает [подготовку переноса](../implementation/world/world-wallet-implementation.md).

## Старые потребители кредитов

| Путь | Реализация |
|---|---|
| Создание Orel/Saper | Общая внешняя транзакция в AbstractCreate: блокировка persone, актуальная проверка средств, создание строк, списание и история. Неуспех middleware откатывает пакет. Успешный прежний ответ сохранён. |
| Участие Orel/Saper/Duel | GameParticipation блокирует игру, затем счета по user_id. Orel/Saper получают саму заблокированную строку, а не повторный обычный SELECT, который может видеть старый snapshot MySQL. |
| Завершение Saper | Ход и расчёт результата в одной транзакции. При проигрыше выполняется предусмотренная цепочка выплаты создателю/комиссии; сообщение «Game lost» отправляется после commit. Ошибка сохранения откатывает ход; повтор упирается в завершённую игру. row/col обязательны. Это исправляет прежний выход из middleware до расчёта выигрыша. |
| Duel/Five | Создание блокирует личный счёт; результаты save проверяются. Перед резервированием проверяется представимость ставки и комиссии. Five уже имел общий transactional service. |
| Бонусы, подарки, переводы, отмена игр, бот, крафт | Используют ранее подключённый CreditLedger/точные адаптеры. Нынешние целые цены/подарки/пакеты сохраняют смысл. Отчёт дополнительно проверяет открытые резервированные суммы перед переносом. |
| Старый UpdatePersonMiddleware | Всегда получает актуальную persone через блокирующий SELECT; в точном режиме credit/balance/одна история проходят ledger, остальные счётчики остаются в общей транзакции. В прежнем режиме также проверяются конечность/достаточность средств под блокировкой. |
| BalanceBehavior / реклама | Денежный behavior очищает дельты между событиями и после активации требует внешнюю транзакцию ещё на BEFORE_*. Advertising объявляет транзакции для записи/удаления; возврат берёт заблокированный остаток кампании. Баланс самой кампании не переводится этим блоком в отдельную экономику мира. |
| Прямые Person/Persone AR writers | Общий trait запрещает credit-save/updateAll/updateAllCounters после активации; нужен CreditLedger. Новый личный счёт получает только 0.0000. Удаление идёт через существующий UserClearService с блокировкой и проверкой пустого аккаунта. Регистрация учитывает заморозку. |

Deprecated HTML-контроллеры Orel/Saper создавали/удаляли строки игр напрямую без резерва и возврата ставки. После активации их изменяющие actions возвращают 410 с указанием использовать текущую страницу игры; списки остаются доступными. Работающие API-контроллеры сохранены и используют транзакционные пути. Неиспользуемые старые behavior-классы не подключаются заново.

`LegacyCreditPolicy` проверяет сумму до резервирования. Money получил деление без округления. Для кредитных игр комиссия с банка равна stake/10, для обмена credit/20: дробный остаток сверх 0.0001 Cr отклоняется. Например, игровая ставка 1.001 Cr допускается, 1.0001 Cr требует решения о комиссии; курс/комиссия не округляются автоматически. Открытые исторические позиции проходят ту же проверку до ALTER. Обнаруженные случаи остаются в отчёте, не отменяются и не возвращаются самовольно. Граница float-адаптера и его допуск на двоичное представление остаются описанными в предыдущем блоке; новые операции мира принимают только десятичные строки.

## Допуск активации

`WalletCompatibility` добавлен в read-only `world-audit/credits`: открытые Orel/Duel/Five, обмен, переводы, остатки рекламы, дубли/отсутствие владельца persone, наличие основных таблиц и InnoDB участников финансовых транзакций. Проверяется реальное имя `comission`. Таблицы craft/world/game/economy включены в проверку движка. Отчёт содержит counts и ограниченные списки ID/причин, без остатков и секретов.

Проверка совместимости вызывается перед необратимым `wallet-convert` и повторяется при активации. Нужные изменения старых данных и движков не выполняются автоматически.

Добавлена отдельная команда `world-setup/wallet-activate`. Её условия:

1. Выделенное offline-окно и прежние явные переменные WORLD_INSTALL/WORLD_WALLET_MAINTENANCE; старые HTTP/worker/cron/регистрации остановлены и завершены.
2. Текущая попытка находится в verified, все три колонки converted и имеют точный тип.
3. Полная повторная сверка каждой строки, количества и hashes с сохранённым снимком.
4. Совместимость открытых старых позиций и транзакционности таблиц.
5. Под блокировками registry/rollout атомарно записываются wallet_ready=1 и phase=active.

Повтор после успешной активации возвращает текущий статус и не сравнивает уже рабочие балансы со старым снимком. Ready требует одновременно флаг и active-фазу. Установка миграций, verify и отчёт сами кошелёк не открывают. Команда активации разрешена bootstrap во время заморозки. В deploy/Docker ничего не добавлено; команды не запускались. Обратного перехода на неточные writers нет.

## Совместимость API

В собственном профиле прежний `credit` остаётся числовым для существующих клиентов; после активации дополнительно выдаётся `credit_exact` — строка с четырьмя знаками. Чужой публичный профиль этих полей не получает. Личная история аналогично дополняется `credit_exact` и `credit_up_exact`, публичная лента ежедневных наград — только `credit_up_exact`, без раскрытия остатка или владельца. Числовые поля — совместимое представление, не источник истины для новых денежных расчётов. API мира уже использует строки. Отображение точного поля в старой шапке/истории SPA можно подключать отдельно; новых элементов UI в этом блоке нет.

## Финансовые родители

Восьмая отдельная миграция `m260927_107000_economy_parents` добавляет `economy_parent_history` и указатель на действующую версию `economy_parent_rule`. Schema marker — 8. История хранит subject, parent subject, revision, базу, ставку в basis points, срок, интервал, причину и operation. UNIQUE(subject,revision), FK и единственный текущий указатель разделяют действующее правило и запись, на которую позднее будет ссылаться обязательство.

`EconomyHierarchy::provision` подключён к личному взносу в объект. Внутри той же CommandBus-транзакции он проходит предков от мира к объекту, создаёт недостающие нулевые budget/treasury и начальные связи. Проверяет активность, общий мир, отсутствие цикла/чрезмерной глубины; запись сериализована world_registry. Никакие Cr не копируются из личного кошелька в родительские счета. Права предков не переходят вкладчику. Изменение счетов/связей повышает revision соответствующего node и делает старые quotes устаревшими.

У мира родителя нет. Другие начальные связи получают `unconfigured` со ставкой NULL; это означает отсутствие опубликованного тарифа, а не разрешение бесплатного сбора. Существующая финансовая связь не переписывается при повторном вложении или перемещении объекта на карте. Настройка/смена родителя и публикация новой ставки станут отдельной командой с историей. Узел с финансовым subject пока нельзя архивировать общим действием, чтобы не спрятать бюджет/обязательства.

Начальные связи — только часть BE:L1/DB:J1. Пока нет публичного редактора правил, receipts/loss/protection, обязательств/резервов и платежей родителю; collect_available остаётся false. Далее — опубликованное правило, поступления казны, сбор с резервом и отдельная выплата. Помещения, шалаш/ночлег и огород остаются следующими игровыми блоками.
