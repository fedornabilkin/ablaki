# Включение мира на production

Разрешено владельцем 2026-11-01: публичный мир и совместимый фронтенд. Резерв Северограда — **25 000 Cr из существующего баланса bot**, по 250 Cr на нового поселенца. Автоматическое финансирование NPC использует оставшиеся существующие средства; выпуска кредитов нет.

## Предусловия

- Завершена подготовка production `a2a4df9`: InnoDB, точный кошелёк, схема мира 44; сохранён `financial-maintenance/completed`.
- Полный CI проверяемого выпуска и репетиция переноса на полной копии MariaDB 10.1.48 проходят успешно.
- Production checkout `/var/www/api.ablakin.ru`, ветка `master`; локальный Compose сохраняется. Тестовые setup-команды, `WORLD_TEST_MODE=1` и полный исторический migrate на production не запускаются.

## Запуск

В `Backend CI and deployment` выбрать `master`, `target=production`, `activate_world=true`, `starter_reserve=25000`, `economy_test=skip`.

Workflow сначала проверяет и доставляет код, затем запускает `deploy/world-production-activate.sh`. Процедура:

1. Устанавливает маркер паузы денежных операций, останавливает cron/worker, дожидается старых PHP-запросов и берёт исключительную блокировку денежных записей. Чтение прежнего сайта остаётся доступным.
2. Переносит инвентари существующим `StorageRollout`/`StorageBackfill`, сверяет каждого владельца и активирует формат со строгим уникальным индексом. Существующие деньги и права проверяются baseline-механизмом.
3. Создаёт нулевые счета существующих нод; публикует версию проверенного профиля с открытым доступом, создаёт инфраструктуру NPC, переносит согласованный резерв. Сумма денег в личных кошельках и счетах мира должна сохраниться; личные остатки и предметы остальных пользователей должны совпасть.
4. Включает постоянные флаги и календарь 1:1. Записывает отдельный игнорируемый Git файл `yii2/common/config/world-local.php`; существующие `main-local.php` и `.env` сохраняются.
5. Проверяет фактические флаги, запускает контейнер `ablaki-world-worker-production` с `WORLD_WORKER=1` и `restart=unless-stopped`, возобновляет cron и денежные операции. Публичный World API требует авторизации (401 для гостя).

## Повтор после сбоя

Не удалять `financial-maintenance/paused` и `world-activation.pending` вручную. Повторить тот же workflow для **того же SHA и той же суммы**. Перенос продолжится с сохранённого состояния; стартовый перевод имеет постоянный идентификатор операции и повторно не списывается. Изменение суммы при повторе отклоняется. Существующий опубликованный административный профиль не заменяется молча.

Диагностика на сервере: `financial-maintenance/activation-error.log`, `world-activation-verified.json`, `world-activation-state.json`, `world-activated`. GitHub `production_audit=true` выполняет только чтение; `progress_only=true` показывает фазу переноса и количество сверенных владельцев во время долгой операции. Резервированные средства города недоступны для обычных расходов NPC.

При аварии после создания `world-local.php` глобальная финансовая пауза продолжает запрещать изменения. Формат хранилищ не откатывается переключением флага; применяется исправление вперёд и повторная проверка.
