# Мастерская мира и восстановление вещей

Дата: 2026-09-27. Третий блок реализации в `feature/09-worlds`. Это описание добавленного кода, **не результат проверки**. По поручению владельца lint, тесты, сборки, применение миграций и выкладка не запускались. Изменения всех трёх блоков пока не закоммичены. Новая схема по-прежнему не включается автоматически.

## Изготовление в выбранном месте

`CraftWorkspace` предоставляет отдельные `GET /v1/world/workspace`, `POST /v1/world/workspace/preview` и `POST /v1/world/workspace/craft`. Доступ: участник соответствующего мира, собственные активные PLOT/BUILDING/ROOM, действующие постройки в цепочке родителей. Административная видимость не даёт права расходовать вещи другого владельца.

Payload фиксирует node_id, recipe_id, количество партий 1–100, **упорядоченный** список source_storage_ids (1–20), output_storage_id и множество конкретных equipment_instance_ids (до 100). Порядок источников определяет порядок списания; экземпляры нормализуются сортировкой. Эти поля, quote_id и revisions входят в fingerprint общей CommandBus. Повтор успешного запроса возвращает сохранённый результат без повторного расхода, оплаты, износа и опыта. Старые `craft_command`, их ключи и fingerprint не изменены.

Материалы берутся из явно выбранных рюкзака, сундуков в рюкзаке, сундуков на площадке или локального склада. Удалённые хранилища, placement и recovery источниками ингредиентов не являются. Неактивные из-за аренды позиции рюкзака не расходуются. Результат допускается только в выбранное доступное хранилище; сундук нельзя изготовить внутрь другого сундука. Изношенный сундук допускает извлечение, но не приём результата.

Инструменты выбираются среди исправных экземпляров активного рюкзака; физическая станция — среди исправных экземпляров в действующем месте размещения выбранного объекта. Старые общедоступные станции каталога без item_id сохраняют прежнюю семантику. Тарифы общественных мастерских ещё не добавлены.

`CanonicalInventory::planCraft` строит детерминированное списание по строкам и instance ID и выдачу по позициям. Для вместимости учитывается освобождение ячеек ингредиентами этой операции. Заполненные сундуки, выбранное оборудование и сами сундуки-источники/получатели не расходуются. Одна операция ограничена 2000 строками плана списания и выдачи. Нехватка материалов, прочности, Cr или места отражается в серверных reasons и DTO материалов. Preview не меняет вещи.

Commit заново рассчитывает условия под общими блокировками и сравнивает terms; изменение отображаемой прочности за время действия quote также требует нового расчёта. Ревизии включают `instance:<id>`, каталог, место и выбранные хранилища. `EquipmentExposure::use`, списание, выдача, legacy CreditLedger, известные рецепты, XP, craft_history/craft_event, inventory_movement, command result и outbox входят в одну транзакцию. Новый код использует вынесенные из существующего Crafting методы `recipeInputs` и `completeRecipe`; формулы опыта и стоимость старого крафта сохраняются. Получающий сундук изнашивается один раз за депозит команды, независимо от числа партий. Точная универсальная денежная модель бюджетов/казны всё ещё относится к следующему этапу.

## Интерфейс

`/world/workspace/:id` и `/craft?node=:id` открывают мастерскую объекта. `/craft` без node сохраняет прежнюю мастерскую. По умолчанию материалы и результат — в рюкзаке; доступны выбор источников в порядке расходования, места выдачи и физических экземпляров оборудования с прочностью и классом защиты. Расчёт показывает красную нехватку, результат, цену, XP рецепта и рабочий износ. Любое изменение выбора сбрасывает quote. Смена аккаунта/места и уход со страницы отбрасывают устаревшие ответы; неопределённый результат команды сохраняется для точного повтора. После оплаты обновляются данные профиля.

## Восстановление

`StorageRecovery` и `/world/recovery` перечисляют только вещи владельца из placement/stockpile, если объект или его предок архивирован/разрушен либо состояние постройки равно нулю. Список имеет серверную пагинацию по 50 записей; скрытая страница мира не препятствует доступу к собственным вещам. Пользователь не выбирает произвольный повод для переноса: основание повторно определяется сервером.

Preview/commit переносят одну целую строку в личный recovery, сохраняя inventory ID, экземпляры, прочность, ID сундука и его внутреннее хранилище. Перед сменой среды фиксируется накопленный износ. Движение и событие содержат источник и основание; извлечение идёт через обычный transfer с проверкой доступных ячеек. В recovery нельзя класть вещи, использовать их как инструменты или ингредиенты. Содержимое восстановленного сундука также не становится источником крафта до извлечения сундука в доступное место. При достижении технического предела recovery в 10000 строк исходная вещь остаётся на месте, требуется забрать ранее восстановленное.

Это путь сохранения имущества, а не реализация разрушения зданий или NPC-резервов. Архивирование узла с хранилищами по-прежнему запрещено. Автоматическое перемещение при будущем demolition, административные операции с чужим имуществом и запреты для производственных резервов ещё не подключены.
