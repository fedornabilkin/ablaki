# Финансовый отчёт отдельного объекта

Дата: 2026-09-27. BE:L17 / FE:I12 — следующий этап L8/I6 после журнала поступлений. Код подготовлен в `feature/09-worlds`, не опубликован. Новых миграций нет; ветка требует marker 21 от предыдущего сноса. Миграции 20/21, тесты, сборка и выкладка не запускались. Опубликованный test остаётся на marker 19.

## Возможности

В разделе «Бюджет и казна» прежний краткий список операций заменён финансовым отчётом. Он содержит сводку за всё время, текущие остатки и журнал с поиском по назначению, фильтрами по виду операции/направлению и серверной пагинацией по 20 записей. Параметры журнала сохраняются в URL с префиксом `finance`; порядок — новые операции сверху.

Сводка показывает поступления в казну с отдельными отчислениями других объектов, оплатой заказов/покупок/работ и прочими поступлениями; перевод казны в собственный бюджет; потери казны; личные вложения в бюджет; выплаты родителю; расходы на заказы, покупки и работы. Обратный внутренний перевод бюджета в собственную казну и прочие движения также учитываются. Неизвестные будущие виды операций не пропадают: в сводке используются соответствующие категории «прочие», в журнале — фильтр «Другие виды».

Сводка относится **только к двум счетам данного объекта за всё время**, не зависит от поиска/фильтров журнала и не включает счета дочерних объектов. «Извне» означает из-за пределов этих двух счетов, а не создание новых Cr в мире. Внутренний перевод отражается в журнале один раз. Сбор собственной казны не увеличивает внешние поступления; платёж между объектами не объявляется новой выручкой мира.

## Остатки и сверка

Отчёт возвращает остаток, резерв и доступную сумму отдельно для бюджета и казны. Для каждого счёта вычисляется сумма всех поступлений минус все списания по `economy_transfer` и сравнивается с сохранённым остатком. При совпадении UI это подтверждает; при расхождении показывает оба значения и необходимость административной сверки. Автоматического исправления денег нет.

Сверка исходит из нулевых начальных счетов, создаваемых существующим provision. Она не заменяет проверку всех резервов, funding lots, обязательств, receipt или всей экономики мира. Служебный счёт потерь мира не включается в бюджет/казну отчёта. Невалидные отрицательные остатки/резервы и резерв больше остатка отклоняются сервером.

Оборот за всё время может превышать допустимый остаток отдельного кошелька. Поэтому агрегаты вычисляются SQL NUMERIC/DECIMAL и возвращаются нормализованными строками с четырьмя знаками, до 40 цифр целой части. Для них не применяется лимит `Money` или преобразование через float. Балансы и отдельные проводки сохраняют прежний контракт `Money`; расчёт доступного остатка остаётся точным. Баланс по журналу может быть отрицательным при несогласованных данных — он явно показывается как расхождение.

## Контракт и доступ

[OpenAPI](../../api/world-finance-report.openapi.json): `GET /v1/world/nodes/{id}/finance-report`, `page`, `q`, `kind`, `direction=all|incoming|outgoing|internal`. `kind=other` выбирает неизвестные отчёту виды. Фильтры применяются до totals/пагинации **журнала**; финансовые lifetime totals всегда неизменны относительно фильтра.

Требуются `world_read` и фактическое владение узлом; управленческое право не открывает чужие финансы. Отсутствие счетов даёт нули и пустой журнал без provision. Активация кошелька/storage для чтения не требуется. API не возвращает ID и остатки чужих счетов, ID плательщиков или служебные operation IDs. Роли source/destination указываются только для собственных бюджета/казны.

`FinanceReadSnapshot` используется отчётом и предыдущим `TreasuryReceipts`: одна транзакция REPEATABLE READ без блокировки registry и записей в ledger. В этой версии Yii MySQL задаёт изоляцию перед BEGIN, PostgreSQL — после BEGIN до первого чтения. Снимок согласует остатки, агрегаты, число и строки журнала при параллельном collect/pay/loss. Старый `GET economy` и его контракт с entries сохраняются для прежних потребителей; SPA для списка теперь использует новый отчёт.

Запросы чтения не собирают казну, не списывают потери, не создают счета/задания и не меняют правила. Новая панель отбрасывает устаревшие ответы после смены узла, сессии или фильтра. После команд используется прежнее обновление страницы мира; кнопки обновления перечитывают серверные данные.

## Следующие этапы и отложенная приёмка

L8/I6 остаются открытыми для отчётности по иерархии и сверки мира с устранением повторного счёта межобъектных переводов. Отчёты за произвольные периоды, детализация контрагентов по правам и административное исправление расхождений не входят в этот блок.

Для приёмки: личный вклад; оплаченный заказ; сбор; выплата родителю; потеря; покупка/ремонт; внутренние переводы в обе стороны; неизвестный вид; нулевые счета; расхождение остатка; оборот больше лимита кошелька; фильтры/страницы; чужой ID; параллельное чтение и worker на MySQL/MariaDB/PostgreSQL. Эти проверки пока не запускались.
