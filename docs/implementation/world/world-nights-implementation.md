# Календарь ночей и здоровье персонажа

Двенадцатый блок, 2026-09-27. Код в `feature/09-worlds`; проверки, миграции, сборка, коммит и выкладка этого блока не выполнялись. После [ремонта укрытия](world-shelter-repair-implementation.md) install marker был 14; после огорода актуальная версия — 15. На test по-прежнему версия 10; storage_v2, точный кошелёк и ночной календарь не активированы. Ночная механика не зависит от кошелька или производственного economy_tick.

## Правила и включение

Миграция создаёт четыре пустые таблицы и не публикует календарь. Оператор отдельно задаёт продолжительность игрового дня, смещение начала ночи от эпохи, длительность ночи, предел тяжести, количество защищённых ночей для снижения тяжести и коэффициенты эффективности. Автоматического «боевого» баланса нет. Новая публикация дополнительно требует действующих рецептов бесплатного ручного ремонта шалаша; повтор существующей политики не сбрасывает эпоху.

Команда `world-setup/nights-activate WORLD DAY_SECONDS NIGHT_OFFSET NIGHT_SECONDS MAX_SEVERITY RECOVERY_NIGHTS MILD_BPS SEVERE_BPS` требует обычный контекст `WORLD_INSTALL=confirmed-world-install`, дополнительный `WORLD_NIGHTS_ACTIVATE=confirmed-night-policy` и уже открытые world_write/storage_v2. Значения обязательны; день 1 час…7 суток, ночь не короче минуты и короче дня, целиком внутри дня; тяжесть 2…10, восстановление 1…30 ночей на уровень, коэффициенты 1…9999 bps с severe≤mild.

Эпоха — серверное время публикации, сохранённое в успешной транзакции активации. Ночь с номером sequence начинается в `activated_at + sequence × day_seconds + night_offset`. Все границы — Unix UTC seconds, интервал [start,end), без браузерного часового пояса. Первая версия неизменна: повтор с теми же правилами возвращает существующую запись, с другими — отказывает. Автоматическая смена версии или активного мира пока не реализована и не должна переписывать историю/обнулять здоровье. Поддержан один действующий календарь мира; переход на другой требует отдельной миграции здоровья.

Льготный срок каждого участника: `max(joined_at, activated_at) + day_seconds`. Поэтому существующий участник получает полный новый игровой день от включения механики, а новый — от вступления. Ночи, начавшиеся раньше этой границы, исключены целиком, даже если закончились после неё. Старый onboarding.grace_until остаётся историческим полем; API при опубликованном календаре возвращает действующую границу. Активация повышает content_revision и делает старые onboarding quotes неактуальными.

## Защита и здоровье

Учитывается одно исправное укрытие на всю ночь. Развёртывание должно начаться не позже start и закончиться не раньше end. Пересечения назначений с интервалами `world_shelter_protection`, ограниченными сроком прочности каждого периода, должны покрыть всю ночь [start,end). Непрерывные отрезки того же развёртывания объединяются; промежуток даже в секунду не защищён. Ремонт до поломки сохраняет непрерывность, после поломки не удаляет разрыв. Установка утром, текущее наличие шалаша, открытая вкладка или поздняя обработка не исправляют прошлую ночь. При поздней обработке уже сложенный шалаш может защищать прошлую ночь, если сохранённые интервалы это подтверждают.

Журнал сохраняет период, исходную и итоговую тяжесть, прогресс восстановления, укрытие и ID подтверждающих интервалов назначения и защиты. UNIQUE(actor_id,period_id) исключает двойной результат; UNIQUE(deployment_id,period_id) исключает двойное использование одного укрытия. Здоровье принадлежит game_actor, а не сессии/браузеру; membership_id допускает NULL для будущих NPC, но текущий обработчик регистрирует только игроков с membership. Новые пользователи вне мира не получают ночных заданий.

Первая незащищённая ночь после льготы даёт severity=1 и onset_at=конец ночи. Каждая следующая повышает severity на 1 до max_severity, увеличивает exposure_nights и сбрасывает прогресс восстановления. Каждые recovery_nights защищённых ночей подряд уменьшают severity на 1; при достижении 0 onset_at очищается. Назначение шалаша само по себе здоровье не меняет. Списаний Cr/вещей, смерти, удаления персонажа и блокировки форума/игр нет.

Коэффициент work_efficiency_bps вычисляется из опубликованных mild/severe bps с линейной интерполяцией между уровнями и 10000 для здорового персонажа. **Штраф к текущему мгновенному крафту не применяется**: API явно отдаёт work_penalty_applied=false; интерфейс сохраняет это объяснение. Применение коэффициента к длительной работе/NPC, лекарства, дом/койки и погода остаются следующими задачами. Бесплатное восстановление через защищённые ночи реализовано; полностью изношенный шалаш теперь можно [починить за сырьё без Cr](world-shelter-repair-implementation.md), сохранив ночлег. Приёмка этого пути до игрового включения остаётся открытой.

Изменение прав/перемещение не оцениваются задним числом по текущему дереву. В действующих API шалаш принадлежит получателю, а перенос территории с развёрнутыми шалашами запрещён до их складывания. Архивирование родителей блокируется действующими дочерними объектами. Ремонт уже закрывает интервалы с фактического серверного времени; будущие transfer/demolition/weather обязаны так же сохранять прошлую защиту.

## Фоновая обработка

Активация атомарно ставит `world.night.enroll`: по 100 membership за job, с курсором последнего ID. Регистрация игрока делегируется owner-job, чтобы не брать блокировку user после registry. Новое вступление атомарно ставит такое же задание; бизнес-ключ защищает пересечение обхода с новым вступлением.

`world.night.resolve` работает с блокировками JobQueue: craft_meta → user/persone → registry → job. Инициализация здоровья, не более 32 последовательных ночей, сохранённые результаты, outbox, checkpoint и следующее задание коммитятся вместе. Задание следующей ночи отложено до её конца. После длительного простоя ставятся следующие пачки; пропусков ради ограничения тяжести нет. Повтор старого cursor не меняет здоровье; несовпадение checkpoint с журналом останавливает обработку вместо скрытого восстановления.

`world-worker/run` регистрирует night handlers при world_write и storage_v2, независимо от wallet_ready. Lease/fencing/retry/dead-letter — существующие JobQueue. Выключение worker/world_write или maintenance останавливает обработку, **но не ход опубликованного календаря**: при возобновлении накопившиеся ночи будут рассчитаны. Пауза календаря с исключением ночей требует отдельной будущей модели интервалов; не следует использовать остановку worker как такую паузу. Dead jobs требуют штатного операторского разбора; GET не восстанавливает задания и не лечит персонажа.

## API и интерфейс

[OpenAPI](../../api/world-nights.openapi.json): GET `/world/nodes/{id}/nights?page=1&outcome=protected`. ID — собственная стартовая стоянка. Фильтр: пустой, protected, unprotected; 20 результатов на страницу, последние ночи сверху. Это числовой журнал, поэтому поиск по названиям не добавлен. История ограничена checkpoint возвращённого здоровья, чтобы параллельный worker не подмешивал более новые результаты.

Состояние различает неопубликованный календарь, ожидание регистрации, отставание расчёта и недоступность записи. Возвращаются серверные границы текущей/следующей и первой учитываемой ночи, льготный срок, условный прогноз защиты при сохранении назначения, здоровье и журнал. Панель на стоянке использует отдельный prefix=nights, фильтр/страницу в URL и отсекает ответы прежней сессии. Даты форматируются из серверных timestamps; клиент не начисляет ночи и не лечит персонажа.

## Отложенная приёмка

После решения владельца: fresh/partial install PostgreSQL и MySQL/MariaDB; повтор активации без сброса эпохи; активация для старого участника и нового вступившего; границы grace/start/end; назначение до/внутри/после ночи; непрерывные и разорванные интервалы; поломка ровно на границе; складывание после защищённой ночи до обработки; восстановление/ухудшение/предел; дубли job и отказ между health/journal/outbox; lease expiry; более 32 ночей простоя; 100+ участников; два одновременных worker; нулевой баланс; чужая стоянка; смена сессии и пагинация. Эти проверки пока не выполнялись.
