# Техническое задание

## Мир Аблакина: иерархическая карта, экономика и развитие персонажа

**Версия:** 1.0  
**Этап:** MVP  
**Платформа:** веб-приложение

---

## 1. Назначение проекта

Создать один игровой фантастический мир с древовидной иерархией объектов, экономикой, постройками, профессиями персонажей, событиями и административным редактированием.

Мир должен позволять пользователю:

- перемещаться по карте;
- видеть текущий уровень иерархии;
- изучать регионы, города и деревни;
- строить здания;
- создавать комнаты и участки земли;
- устанавливать предметы;
- назначать работников;
- получать прибыль;
- развивать профессиональные навыки;
- участвовать в событиях;
- открывать новые возможности через уровни персонажа.

Основная архитектурная идея:

- паттерн **Компоновщик** используется для построения дерева мира;
- паттерн **Посетитель** используется для выполнения операций над элементами дерева;
- экономика рассчитывается сервером через фоновые процессы;
- доступ к действиям определяется уровнями профессий и условиями.

---

# 2. Цели MVP

В первую версию необходимо включить:

1. Один игровой мир.
2. Не менее двух регионов.
3. Города и деревни.
4. Постройки разных назначений.
5. Участки земли.
6. Комнаты внутри построек.
7. Установку предметов в здания.
8. Работников.
9. Доходы и расходы.
10. События на разных уровнях.
11. Персонажа с профессиональными уровнями.
12. Ограничения действий по уровням.
13. Страницу условий получения уровней.
14. Сводную страницу ограничений.
15. Административную панель.
16. Страницу экономики мира.
17. Навигатор текущего положения пользователя.

В MVP не включать:

- несколько миров;
- полноценную боевую систему;
- сложную дипломатию;
- пользовательское редактирование ландшафта;
- торговую площадку между игроками;
- сложную транспортную систему;
- процедурную генерацию всего мира.

Архитектура должна позволять добавить эти возможности позднее без полной переработки проекта.

# 3. Концепция мира

Игровой мир представляет собой иерархическую структуру:

```text
Мир
└── Регион
    └── Населённый пункт
        ├── Город
        │   ├── Постройка
        │   │   ├── Комната
        │   │   └── Участок земли
        │   └── Участок города
        └── Деревня
            ├── Постройка
            └── Участок земли
```

Каждый объект:

- имеет уникальный идентификатор;
- имеет родительский объект;
- может иметь дочерние объекты;
- имеет тип;
- имеет название и описание;
- отображается на карте;
- участвует в экономических расчётах;
- имеет правила доступа;
- может быть изменён из админ-панели.

# 5. Паттерн Компоновщик

## 5.1. Назначение

Паттерн Компоновщик используется для представления мира в виде дерева.

Клиент должен одинаково работать с:

- отдельным предметом;
- комнатой;
- постройкой;
- населённым пунктом;
- регионом;
- всем миром.

## 5.2. Общий интерфейс

```typescript
interface WorldComponent {
  id: string;
  type: WorldNodeType;
  name: string;
  parentId?: string;

  getChildren(): WorldComponent[];

  addChild(child: WorldComponent): void;

  removeChild(childId: string): void;

  findById(id: string): WorldComponent | null;

  accept(visitor: WorldVisitor): void;
}
```

## 5.3. Компоненты дерева

```text
WorldComponent
├── WorldComposite
├── RegionComposite
├── SettlementComposite
├── BuildingComposite
├── RoomComposite
├── LandPlotComposite
└── ItemLeaf
```

## 5.4. Контейнеры

Контейнерами являются:

- мир;
- регион;
- населённый пункт;
- постройка;
- комната;
- участок, если в него можно помещать объекты.

## 5.5. Листовые объекты

Листовыми объектами могут быть:

- предмет;
- ресурс;
- работник;
- декоративный объект;
- установленное оборудование;
- событие.

## 5.6. Разрешённые связи

```text
Мир → Регион
Регион → Город или Деревня
Город/Деревня → Постройка или Участок
Постройка → Комната или Участок
Комната → Предмет
Участок → Предмет, ресурс или малая постройка
```

Система должна запрещать недопустимые вложения.

### Примеры недопустимых вложений

- нельзя установить печь на декоративном участке;
- нельзя построить шахту внутри спальни;
- нельзя добавить комнату в комнату;
- нельзя разместить торговый зал на огороде;
- нельзя создать регион внутри деревни;
- нельзя установить производственный станок в жилой комнате без специального разрешения.

# 6. Паттерн Посетитель

## 6.1. Назначение

Паттерн Посетитель используется для выполнения операций над элементами дерева без добавления логики непосредственно в классы объектов.

Это позволит отдельно реализовать:

- экономические расчёты;
- статистику;
- навигацию;
- проверку доступа;
- проверку совместимости предметов;
- влияние событий;
- расчёт населения.

## 6.2. Интерфейс посетителя

```typescript
interface WorldVisitor {
  visitWorld(world: WorldComposite): void;

  visitRegion(region: RegionComposite): void;

  visitSettlement(settlement: SettlementComposite): void;

  visitBuilding(building: BuildingComposite): void;

  visitRoom(room: RoomComposite): void;

  visitLandPlot(plot: LandPlotComposite): void;

  visitItem(item: ItemLeaf): void;
}
```

## 6.3. Обязательные посетители

### EconomyVisitor

Рассчитывает:

- доход;
- расходы;
- прибыль;
- производство;
- потребление;
- налоги;
- дефицит ресурсов;
- экономический баланс.

### PopulationVisitor

Рассчитывает:

- численность населения;
- доступные рабочие места;
- занятость;
- безработицу;
- потребность в жилье;
- потребность в медицинских и социальных услугах.

### EventImpactVisitor

Рассчитывает последствия событий:

- пожара;
- засухи;
- пандемии;
- наводнения;
- заморозков;
- нашествия вредителей;
- экономического кризиса.

### AccessVisitor

Проверяет:

- доступность объекта;
- уровень персонажа;
- наличие ресурсов;
- право собственности;
- возможность выполнить действие;
- наличие необходимых предметов.

### ItemCompatibilityVisitor

Проверяет:

- можно ли установить предмет;
- подходит ли предмет типу комнаты;
- подходит ли предмет типу постройки;
- есть ли свободный слот;
- выполнены ли требования уровня.

### NavigationVisitor

Формирует:

- путь от мира до текущего объекта;
- хлебные крошки;
- список соседних объектов;
- список дочерних объектов;
- краткую статистику текущего уровня.

### StatisticsVisitor

Формирует:

- доходы;
- расходы;
- производство;
- потребление;
- количество работников;
- количество построек;
- количество активных событий;
- состояние инфраструктуры.

# 7. Навигация по карте

Пользователь всегда должен понимать, где он находится.

## 7.1. Хлебные крошки

Пример:

```text
Аблакин
/ Зелёные равнины
/ Город Лиар
/ Мельница «Золотое зерно»
/ Производственный зал
```

Каждый элемент хлебных крошек должен быть ссылкой.

## 7.2. Навигатор

На странице объекта необходимо отображать:

- текущий объект;
- родительский объект;
- дочерние объекты;
- соседние объекты;
- тип объекта;
- координаты;
- уровень доступа;
- экономическую статистику;
- активные события.

## 7.3. Визуализация уровней

| Уровень | Представление |
|---|---|
| Мир | интерактивная карта регионов |
| Регион | карта городов и деревень |
| Город | план районов, зданий и участков |
| Постройка | план комнат |
| Комната | список слотов и предметов |
| Участок | схема земли и объектов |

На мобильных устройствах карта должна заменяться списком объектов и компактным навигатором.

```text

## 9.4. Правила установки

Предмет можно установить, если:

1. тип предмета разрешён в постройке;
2. тип предмета разрешён в комнате;
3. существует свободный слот;
4. предмет помещается по размеру;
5. выполнены требования по уровню;
6. у пользователя есть право установки;
7. хватает ресурсов;
8. постройка не разрушена;
9. не нарушено максимальное количество предметов;
10. не установлен несовместимый предмет.

Проверка должна выполняться на сервере.

Кузница:

Минимум работников:
- 1 кузнец уровня 2
- 1 помощник уровня 1

Содержание:
- 20 монет в день

Производство:
- 5 металлических деталей в день
```

## 10.3. Эффективность

Итоговая эффективность рассчитывается по формуле:

```text
Эффективность =
Базовая эффективность
× коэффициент работников
× коэффициент оборудования
× коэффициент ресурсов
× коэффициент состояния
× коэффициент события
```

Если работников меньше минимума:

- постройка работает с пониженной эффективностью;
- доход уменьшается;
- часть функций блокируется.

Если работников нет:

- производство останавливается;
- фиксированные расходы сохраняются;
- постройка может перейти в неактивное состояние.

## 13.7. Обработка события

9. Завершиться автоматически или вручную.
10. Записать историю.
11. Обновить экономические показатели.

# 24. Фоновые процессы

Расчёты экономики и события не должны выполняться внутри обычного HTTP-запроса.

Использовать очередь задач и фоновые процессы.

## 24.1. Основные фоновые задачи

```text
EconomyTickJob
EventTickJob
ConstructionTickJob
WorkerAssignmentJob
PopulationUpdateJob
StatisticsSnapshotJob
NotificationJob
ProfessionProgressionJob
BuildingMaintenanceJob
ResourceRegenerationJob
```

## 24.2. Задачи

### EconomyTickJob

- начисляет доходы;
- списывает расходы;
- обновляет ресурсы;
- рассчитывает прибыль;
- записывает транзакции.

### EventTickJob

- проверяет активные события;
- применяет последствия;
- обновляет сроки;
- завершает события.

### ConstructionTickJob

- обновляет прогресс строительства;
- проверяет ресурсы;
- завершает строительство;
- отправляет уведомление.

### WorkerAssignmentJob

- проверяет работников;
- назначает работников;
- рассчитывает эффективность;
- выявляет нехватку персонала.

### PopulationUpdateJob

- обновляет население;
- рассчитывает миграцию;
- проверяет вместимость;
- обновляет потребности.

# 29. Критерии готовности MVP

MVP считается готовым, если:

- пользователь видит карту мира;
- пользователь может перейти по всей иерархии;
- в интерфейсе отображается текущее местоположение;
- работают хлебные крошки;
- нельзя создать недопустимое вложение;
- можно создать постройку;
- можно добавить комнату;
- можно добавить участок;
- можно установить совместимый предмет;
- несовместимый предмет отклоняется;
- постройка требует работников;
- постройка получает доход и расходы;
- экономика пересчитывается автоматически;
- операции экономики сохраняются в журнале;
- пожар действует на город;
- засуха действует на регион;
- пандемия действует на весь мир;
- события отображаются на карте;
- персонаж получает опыт;
- существуют пять профессиональных направлений;
- уровень открывает и ограничивает действия;
- пользователь видит причины блокировки;
- существует страница условий получения уровней;
- существует страница сводных ограничений;
- администратор может изменять мир;
- изменения сохраняются в журнале;
- есть возможность отката изменений;
- права проверяются на сервере;
- экономические операции имеют идентификаторы;
- фоновые задачи работают независимо от HTTP-запросов.

# 31. Итоговая архитектурная идея

Система должна быть построена по следующим принципам:

```text
Дерево мира отвечает за структуру.
Компоновщик отвечает за единообразную работу с узлами.
Посетители отвечают за операции над деревом.
Экономика отвечает за состояние и финансовые расчёты.
События изменяют состояние объектов.
Профессии определяют возможности персонажа.
Уровни определяют ограничения.
Админка управляет контентом и балансом.
Фоновые задачи обеспечивают регулярные расчёты.
Журнал операций обеспечивает историю и контроль.
```

Главная цель MVP — создать не полноценную огромную игру, а работающий вертикальный срез:

```text
Мир
→ Регион
→ Город
→ Постройка
→ Комната
→ Предмет
→ Работники
→ Доход
→ Событие
→ Профессиональный уровень
→ Новые доступные действия
```

Такой вертикальный срез позволит проверить основную игровую петлю и затем постепенно добавлять новые регионы, постройки, предметы, события, профессии и миры.
