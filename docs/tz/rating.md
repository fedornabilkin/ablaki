# 1. Цель задачи

Создать систему рейтинга пользователя, которая отражает его активность, опыт и вклад в мир «Аблакин».

Рейтинг должен:

- расти за полезные действия в мире;
- расти медленнее с каждым следующим баллом;
- делать каждый следующий балл ценнее предыдущего;
- открывать доступ к новым возможностям;
- ограничивать доступ к рынку игроков и другим экономическим механикам;
- снижать риск накрутки и мультиаккаунтинга;
- быть прозрачным для игрока;
- иметь журнал всех изменений.

Рейтинг — это не уровень персонажа и не опыт крафта. Это **репутация и доверие пользователя внутри мира**.

---

# 2. Основные принципы

## 2.1. Рейтинг не должен расти слишком быстро

Быстрый рост рейтинга делает его бесполезным.

Ориентир:

```text
Рейтинг 1–10 — первые дни
Рейтинг 11–25 — первая–вторая неделя
Рейтинг 26–50 — первый месяц
Рейтинг 51+ — долгосрочная активность
```

## 2.2. Каждый следующий балл дороже

Формула должна обеспечивать прогрессию:

```text
Чем выше рейтинг, тем больше действий нужно для следующего балла.
```

Рекомендуемая модель:

```text
Не линейная прибавка.
Не фиксированное количество очков на каждый уровень.
Прогрессивное увеличение стоимости следующего балла.
```

## 2.3. Рейтинг не должен покупаться напрямую

Нельзя позволять:

```text
Купить рейтинг за кредиты
Купить рейтинг за реальные деньги
Передать рейтинг другому игроку
Продать рейтинг
Обменять рейтинг на кредиты
```

Рейтинг растёт только за подтверждённые действия пользователя.

## 2.4. Рейтинг не должен быть единственным фильтром

На старте доступ к рынку игроков должен зависеть не только от рейтинга, но и от:

```text
возраста аккаунта;
подтверждённого контакта;
отсутствия блокировок;
истории нарушений;
лимитов безопасности.
```

# 4. Модель начисления рейтинга

## 4.1. Два типа очков

Использовать две сущности:

```text
rating_points — накопленные очки рейтинга
rating — текущий рейтинг пользователя
```

Очки начисляются за действия.

Рейтинг рассчитывается из очков по формуле.

## 4.2. Базовая формула

```text
rating = количество баллов, доступных при текущем количестве rating_points
```

Для перехода на следующий балл требуется всё больше очков.

Рекомендуемая формула:

```text
points_for_next_level =
base_points × growth_factor^(current_rating)
```

Где:

```text
base_points = 100
growth_factor = 1.15
```

Пример:

```text
Для 1 балла: 100 очков
Для 2 балла: 115 очков
Для 3 балла: 132 очка
Для 4 балла: 152 очка
Для 5 баллов: 175 очков
```

## 4.3. Ограничение роста

Чтобы рейтинг не рос бесконечно быстро, использовать:

```text
дневной лимит очков;
недельный лимит очков;
лимит за однотипные действия;
уменьшение награды за повторения;
антифрод-проверки.
```

Рекомендуемые лимиты:

```text
Максимум очков в сутки: 300
Максимум очков в неделю: 1 500
Максимум очков за одно действие: 50
Максимум одинаковых действий в сутки: зависит от действия
```

# 6. Антинакрутка

## 6.1. Основные правила

```text
Очки не начисляются за пустые действия.
Очки не начисляются за повторяющиеся действия сверх лимита.
Очки не начисляются за действия между связанными аккаунтами.
Очки не начисляются за отменённые или ошибочные операции.
Очки не начисляются за покупки у NPC.
Очки не начисляются за ускорения.
Очки не начисляются за простое ожидание.
```

## 6.2. Защита от фарма

Для каждого действия хранить:

```text
количество выполнений за день;
количество выполнений за неделю;
время последнего действия;
уникальные объекты;
уникальные предметы;
уникальные контрагенты.
```

Пример:

```text
Сбор камня:
1–10 раз в день — 1 очко за раз
11–20 раз в день — 0,5 очка за раз
21+ раз в день — 0 очков
```

## 6.3. Защита от торговли между своими аккаунтами

Проверять:

```text
одинаковый IP;
одинаковое устройство;
одинаковую сессию;
частые сделки между одними аккаунтами;
быстрые цепочки переводов;
создание аккаунтов в короткий период;
одинаковые модели поведения.
```

При подозрении:

```text
не начислять очки сразу;
помечать операцию;
задерживать зачисление;
передавать на проверку модерации.
```

## 6.4. Снижение награды

```text
Первые действия — полная награда.
Повторяющиеся действия — уменьшенная награда.
Однотипный фарм — нулевая награда.
```

# 11. Логика начисления

## 11.1. Алгоритм

```text
1. Получить действие.
2. Проверить, что действие активно.
3. Проверить права пользователя.
4. Проверить, что пользователь не заблокирован.
5. Проверить идемпотентность.
6. Проверить дневной лимит.
7. Проверить недельный лимит.
8. Проверить лимит повторений.
9. Рассчитать базовые очки.
10. Применить снижение за повтор.
11. Применить множители события, если есть.
12. Начислить очки.
13. Пересчитать рейтинг.
14. Записать транзакцию.
15. Обновить доступ.
16. Отправить уведомление при новом рейтинге.
```

## 11.2. Идемпотентность

Ключ:

```text
userId + actionCode + sourceType + sourceId + operationId
```

Повторный запрос не должен:

```text
начислить очки повторно;
изменить рейтинг повторно;
создать вторую транзакцию.
```

## 11.3. Пересчёт рейтинга

Рейтинг пересчитывается после начисления очков.

```text
1. Взять текущие rating_points.
2. Пройти по таблице стоимости уровней.
3. Определить новый rating.
4. Если рейтинг вырос — создать событие.
5. Если рейтинг не изменился — только обновить очки.
```

# 16. Критерии приёмки

Задача считается выполненной, если:

- рейтинг начисляется за действия в мире;
- каждый следующий балл требует больше очков;
- есть дневные и недельные лимиты;
- есть защита от фарма;
- есть защита от накрутки;
- есть идемпотентность;
- есть журнал всех изменений;
- есть история рейтинга;
- есть правила доступа к возможностям;
- доступ к рынку игроков зависит от рейтинга;
- есть админка;
- есть аналитика;
- есть API;
- есть тесты;
- есть уведомления;
- есть обработка ошибок.

# 18. Итоговое решение

```text
Рейтинг растёт за реальные полезные действия.
Каждый следующий балл стоит дороже предыдущего.
Есть дневные и недельные лимиты.
Есть защита от фарма и мультиаккаунтинга.
Рынок игроков открывается постепенно.
```

Рекомендуемая цепочка доступа:

```text
Рейтинг 1 — базовые действия и рынок NPC
Рейтинг 5 — огород и шахта
Рейтинг 8 — мастерская и расширения
Рейтинг 12 — покупки у игроков
Рейтинг 15 — продажи игрокам
Рейтинг 21 — расширенная торговля
Рейтинг 25 — редкие предметы и обмены
Рейтинг 30 — сообщества и события
```

Это позволит сделать рейтинг значимым, защитить экономику и постепенно открывать игрокам более сложные механики.
