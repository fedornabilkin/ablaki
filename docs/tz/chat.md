# Техническое задание

## Чаты и групповые комнаты сайта «Аблакин»

**Версия:** 1.0  
**Этап:** MVP  
**Платформа:** веб-приложение  
**Основные режимы:** личные чаты, групповые комнаты, голосовой набор сообщений.

---

# 1. Назначение системы

Создать раздел чатов для общения пользователей сайта.

Система должна поддерживать:

- личные чаты один на один;
- групповые комнаты;
- название и описание групповой комнаты;
- назначение модераторов;
- добавление и исключение участников;
- автоматическое добавление пользователей в групповой чат;
- возможность пользователя самостоятельно покинуть комнату;
- поиск по чатам;
- поиск по сообщениям;
- ответы на сообщения;
- голосовой набор текста;
- индикаторы непрочитанных сообщений;
- трехколоночный интерфейс на больших экранах;
- адаптивное отображение на планшетах и мобильных устройствах;
- ограничения пользователей на уровне сайта;
- разграничение прав между владельцем комнаты, модераторами и участниками.

---

# 2. Основные понятия

## 2.1. Личный чат

Диалог между двумя пользователями.

```text
Пользователь A ↔ Пользователь B
```

Личный чат не имеет списка модераторов.

## 2.2. Групповая комната

Чат с несколькими участниками.

Комната имеет:

- название;
- описание;
- владельца или администратора;
- список участников;
- список модераторов;
- сообщения;
- настройки доступа;
- статус активности.

## 2.3. Администратор комнаты

Пользователь, который создал групповую комнату или получил права администратора.

Администратор может:

- менять название;
- добавлять описание;
- назначать модераторов;
- снимать модераторов;
- добавлять участников;
- исключать участников;
- закрывать комнату;
- передавать права администратора;
- удалять сообщения;
- управлять настройками комнаты.

## 2.4. Модератор комнаты

Пользователь, назначенный администратором комнаты.

Модератор может:

- добавлять пользователей;
- исключать пользователей;
- удалять сообщения;
- ограничивать отправку сообщений;
- просматривать список участников;
- отвечать на сообщения;
- сообщать о нарушениях.

Модератор не может:

- назначать других модераторов;
- снимать администратора;
- передавать права владельца;
- удалять комнату;
- изменять глобальные ограничения сайта.

## 2.5. Участник

Обычный пользователь групповой комнаты.

Участник может:

- читать сообщения;
- отправлять сообщения;
- отвечать на сообщения;
- искать сообщения;
- использовать голосовой набор;
- видеть список участников;
- покинуть комнату самостоятельно.

## 2.6. Глобально ограниченный пользователь

Пользователь, которому на уровне сайта запрещено:

- отправлять сообщения;
- создавать комнаты;
- добавлять пользователей;
- вступать в групповые комнаты;
- пользоваться чатами полностью.

Ограничения верхнего уровня имеют приоритет над разрешениями комнаты.

---

# 3. Типы чатов

## 3.1. Личный чат

```text
DIRECT
```

Свойства:

- два участника;
- один диалог;
- нет названия комнаты;
- отображаемое имя второго пользователя;
- аватар второго пользователя;
- статус онлайн;
- индикатор непрочитанных сообщений.

## 3.2. Групповая комната

```text
GROUP
```

Свойства:

- название;
- описание;
- аватар или цвет комнаты;
- администратор;
- модераторы;
- участники;
- правила;
- настройки;
- сообщения;
- дата создания;
- статус.

## 3.3. Системный чат

Опционально предусмотреть тип:

```text
SYSTEM
```

Используется для:

- уведомлений;
- сообщений администрации;
- системных событий;
- уведомлений о назначении модератора;
- уведомлений об исключении.

В MVP системные сообщения могут храниться внутри групповой комнаты.

---

# 4. Правила создания групповой комнаты

## 4.1. Кто может создать комнату

Создать групповую комнату может пользователь, если:

- аккаунт подтверждён;
- пользователь не ограничен правилами верхнего уровня;
- пользователь не заблокирован;
- пользователь имеет право создавать комнаты;
- не превышен лимит комнат;
- не превышен лимит активных комнат.

## 4.2. Обязательные данные перед созданием

Перед созданием комнаты администратор должен указать:

```text
Название комнаты
```

Название является обязательным.

## 4.3. Описание комнаты

Описание можно:

- добавить после создания;
- изменить позже;
- оставить пустым;
- скрыть;
- изменить только администратору.

При создании комнаты форма должна содержать:

```text
Название — обязательное поле
Описание — необязательное поле
```

## 4.4. Ограничения названия

```text
Минимальная длина: 2 символа
Максимальная длина: 80 символов
```

Название не должно:

- содержать запрещённые выражения;
- состоять только из пробелов;
- повторять системные названия;
- содержать опасный HTML или JavaScript;
- вводить пользователя в заблуждение относительно официального статуса.

## 4.5. Ограничения описания

```text
Максимальная длина: 500 символов
```

Описание должно поддерживать:

- обычный текст;
- ссылки после проверки;
- переносы строк.

Не поддерживать произвольный HTML.

---

# 5. Автоматическое добавление в групповые комнаты

## 5.1. Основное правило

Пользователь может автоматически добавляться в групповой чат без индивидуального подтверждения, если:

```text
пользователь не ограничен правилами верхнего уровня
и
комната разрешает автоматическое добавление
```

## 5.2. Приоритет ограничений

Проверка выполняется в следующем порядке:

```text
1. Глобальная блокировка пользователя
2. Глобальное ограничение на чаты
3. Ограничение пользователя на групповые чаты
4. Ограничение конкретной комнаты
5. Право администратора или модератора
6. Автоматическое добавление
```

Если пользователь ограничен на любом верхнем уровне, автоматическое добавление запрещается.

## 5.3. Типы автоматического добавления

Предусмотреть настройки:

```text
AUTO_JOIN_OPEN       — автоматическое добавление разрешено
AUTO_JOIN_DISABLED   — автоматическое добавление запрещено
AUTO_JOIN_APPROVAL   — требуется подтверждение
```

Для MVP использовать:

```text
AUTO_JOIN_OPEN
```

Но глобальный администратор должен иметь возможность изменить режим.

## 5.4. Сценарии автоматического добавления

Автоматическое добавление может выполняться:

- при создании аккаунта;
- при вступлении в игровую фракцию;
- при присоединении к региону;
- при участии в событии;
- при получении роли;
- при достижении уровня;
- при добавлении в игровую группу;
- при создании поселения;
- при выборе интереса;
- при открытии тематического раздела.

## 5.5. Правила автоматического добавления

При автоматическом добавлении:

1. проверить глобальные ограничения;
2. проверить, не является ли пользователь уже участником;
3. проверить, не покинул ли пользователь комнату ранее;
4. проверить лимит участников;
5. создать членство;
6. добавить системное сообщение;
7. показать уведомление;
8. обновить список чатов;
9. увеличить счётчик групповой комнаты.

## 5.6. Повторное автоматическое добавление

Если пользователь самостоятельно покинул комнату:

```text
повторно автоматически добавлять его нельзя
```

Исключение:

- пользователь сам снова активировал участие;
- комната является обязательной системной комнатой;
- глобальный администратор принудительно восстановил участие.

# 6. Возможность покинуть комнату

Пользователь может самостоятельно покинуть групповой чат.

## 6.1. Действие

Кнопка:

```text
Покинуть комнату
```

Перед выполнением показать подтверждение:

```text
Покинуть комнату?

После выхода вы не будете получать новые сообщения.
Вернуться можно будет по приглашению или через действие «Вступить».
```

## 6.2. После выхода

- пользователь удаляется из активных участников;
- старые сообщения становятся недоступны или доступны в режиме чтения согласно политике хранения;
- новые сообщения не доставляются;
- чат удаляется из активного списка;
- сохраняется история выхода;
- автоматическое повторное добавление запрещается;
- пользователю показывается статус `LEFT`.

## 6.3. Последний администратор

Нельзя позволить последнему администратору покинуть комнату без решения:

1. назначить другого администратора;
2. закрыть комнату;
3. удалить комнату;
4. передать права системе.

Если это системная комната, владелец не может покинуть её самостоятельно.

# 7. Роли и права

## 7.1. Таблица разрешений

| Действие | Участник | Модератор | Администратор | Глобальный админ |
|---|---:|---:|---:|---:|
| Читать сообщения | Да | Да | Да | Да |
| Отправлять сообщения | Да | Да | Да | Да |
| Отвечать на сообщения | Да | Да | Да | Да |
| Использовать голосовой набор | Да | Да | Да | Да |
| Искать сообщения | Да | Да | Да | Да |
| Видеть участников | Да | Да | Да | Да |
| Покинуть комнату | Да | Да | Да* | Да |
| Добавить пользователя | Нет | Да | Да | Да |
| Исключить пользователя | Нет | Да | Да | Да |
| Удалить сообщение | Нет | Да | Да | Да |
| Назначить модератора | Нет | Нет | Да | Да |
| Снять модератора | Нет | Нет | Да | Да |
| Изменить название | Нет | Нет | Да | Да |
| Изменить описание | Нет | Нет | Да | Да |
| Изменить настройки комнаты | Нет | Нет | Да | Да |
| Удалить комнату | Нет | Нет | Да | Да |
| Изменить глобальные ограничения | Нет | Нет | Нет | Да |

`*` Администратор не может покинуть комнату, если он последний администратор.

## 7.2. Глобальные ограничения

Глобальный администратор может запретить пользователю:

```text
READ_CHAT
SEND_MESSAGE
CREATE_ROOM
JOIN_GROUP
INVITE_USERS
MODERATE_ROOM
USE_VOICE_INPUT
SEARCH_MESSAGES
```

Ограничения должны проверяться на сервере для каждого действия.

# 8. Структура интерфейса

## 8.1. Большие экраны

На больших экранах раздел чатов отображается в три колонки:

```text
┌─────────────────┬──────────────────────────────┬──────────────────┐
│ 1. Список чатов │ 2. Сообщения выбранного чата │ 3. Информация    │
│                 │                              │                  │
│ Личные         │ Заголовок чата                │ Комната/пользователь│
│ Групповые      │ Сообщения                     │ Участники         │
│ Поиск          │ Ответы                        │ Роли              │
│ Фильтры        │ Поле ввода                    │ Настройки         │
└─────────────────┴──────────────────────────────┴──────────────────┘
```

## 8.2. Первая колонка

Содержит:

- поиск по чатам;
- переключатели фильтров;
- список личных чатов;
- список групповых комнат;
- индикаторы непрочитанных сообщений;
- индикатор новых чатов;
- сортировку по последней активности.

## 8.3. Вторая колонка

Содержит:

- заголовок выбранного чата;
- аватар;
- название;
- статус;
- список сообщений;
- ответы;
- разделитель непрочитанных сообщений;
- поле ввода;
- кнопку отправки;
- кнопку голосового набора;
- кнопку вложений;
- состояние доставки;
- прокрутку;
- поиск по сообщениям.

## 8.4. Третья колонка

Для личного чата отображать:

- аватар;
- имя;
- никнейм;
- статус онлайн;
- краткую информацию;
- общие достижения;
- кнопку открыть профиль;
- кнопку ограничить пользователя;
- кнопку заблокировать;
- кнопку очистить чат;
- настройки уведомлений.

Для групповой комнаты отображать:

- название;
- описание;
- аватар или цвет;
- дату создания;
- администратора;
- список модераторов;
- список участников;
- количество участников;
- статус автоматического добавления;
- кнопку поиска участников;
- кнопку покинуть комнату;
- настройки уведомлений;
- кнопку пожаловаться.

# 9. Адаптивность

## 9.1. Большой экран

```text
3 колонки
```

Рекомендуемые размеры:

```text
Левая колонка: 280–360 px
Центральная колонка: гибкая
Правая колонка: 280–360 px
```

## 9.2. Планшет

Использовать две колонки:

```text
Левая колонка + сообщения
```

Информация о пользователе или комнате открывается боковой панелью.

## 9.3. Мобильный экран

Использовать один экран за раз:

```text
Список чатов
→ выбранный чат
→ информация о чате
```

Навигация:

- кнопка «Назад»;
- выдвижная панель;
- нижнее или верхнее меню;
- модальные окна.

# 10. Левая колонка: фильтры чатов

В верхней части расположить toggle-кнопки:

```text
[Все 12] [Личные 5] [Групповые 7]
```

## 10.1. Фильтр «Все»

Показывает:

- все личные чаты;
- все групповые комнаты;
- активные чаты;
- чаты с непрочитанными сообщениями.

## 10.2. Фильтр «Личные»

Показывает только личные чаты.

## 10.3. Фильтр «Групповые»

Показывает только групповые комнаты.

## 10.4. Количество на кнопках

Количество должно отображаться рядом с названием фильтра.

Варианты подсчёта:

```text
Все — количество доступных чатов
Личные — количество личных чатов
Групповые — количество групповых комнат
```

Для чатов с непрочитанными сообщениями дополнительно использовать маленький индикатор.

Пример:

```text
Все 12
Личные 5
Групповые 7
```

Если есть новые сообщения:

```text
Все 12 ●
Личные 5 ●
Групповые 7 ●
```

# 11. Список чатов

## 11.1. Элемент личного чата

Отображать:

- аватар;
- имя пользователя;
- последнее сообщение;
- дату или время;
- индикатор онлайн;
- количество непрочитанных;
- индикатор черновика;
- индикатор ответа;
- индикатор вложения.

Пример:

```text
[Аватар] Алекс
          Хорошо, я проверю...
          12:45[1]
```

## 11.2. Элемент групповой комнаты

Отображать:

- аватар или цвет комнаты;
- название;
- последнее сообщение;
- автора последнего сообщения;
- дату или время;
- количество участников;
- количество непрочитанных;
- индикатор новых сообщений;
- закреплённое сообщение;
- статус комнаты.

Пример:

```text
[Иконка] Строители города
         Иван: Готов новый проект
         12:48[2]
         24 участника
```

## 11.3. Сортировка

По умолчанию:

```text
последняя активность сверху
```

Системные комнаты могут быть закреплены сверху.

# 12. Индикаторы сообщений

Необходимо реализовать несколько типов индикаторов.

## 12.1. Индикатор непрочитанных сообщений в чате

В списке чатов:

```text
[3]
```

Означает количество непрочитанных сообщений.

## 12.2. Разделитель новых сообщений

Внутри выбранного чата:

```text
──── Новые сообщения ────
```

Разделитель должен находиться перед первым непрочитанным сообщением.

## 12.3. Индикатор новых сообщений в списке чатов

Если в любом чате появилось новое сообщение:

- выделить чат;
- показать точку;
- увеличить счётчик;
- обновить позицию чата.

## 12.4. Индикатор на иконке чатов

На иконке раздела чатов отображать:

```text
[Иконка чатов] 12
```

Где `12` — общее количество непрочитанных сообщений во всех чатах.

Если непрочитанных сообщений больше 99:

```text
99+
```

## 12.5. Состояния сообщения

```text
SENDING    — отправляется
SENT       — отправлено сервером
DELIVERED  — доставлено
READ       — прочитано
FAILED     — ошибка отправки
```

# 13. Сообщения

## 13.1. Типы сообщений

```text
TEXT             — текст
SYSTEM           — системное
IMAGE            — изображение
FILE             — файл
AUDIO            — аудио
VOICE_TRANSCRIPT — текст голосового набора
REPLY            — сообщение с ответом
```

В MVP можно начать с:

```text
TEXT
SYSTEM
REPLY
VOICE_TRANSCRIPT
```

## 13.2. Поля сообщения

```text
id
chatId
senderId
type
content
replyToMessageId
createdAt
updatedAt
deletedAt
status
edited
metadata
```

## 13.3. Ограничения текста

```text
Максимальная длина сообщения: 4 000 символов
```

Дополнительно:

- убрать управляющие символы;
- проверять HTML;
- экранировать пользовательский ввод;
- запрещать вставку скриптов;
- поддерживать переносы строк;
- ограничить количество ссылок;
- ограничить частоту отправки.

## 13.4. Редактирование

В MVP можно разрешить редактирование собственных сообщений:

```text
В течение 15 минут после отправки
```

После редактирования показывать:

```text
изменено
```

Историю изменений хранить для модераторов и администраторов.

## 13.5. Удаление

Пользователь может удалить собственное сообщение.

Модератор и администратор могут удалить любое сообщение в комнате.

После удаления отображать:

```text
Сообщение удалено
```

Содержимое не показывать обычным пользователям.

# 15. Голосовой набор

## 15.1. Назначение

Добавить возможность преобразовывать речь пользователя в текст сообщения.

Рекомендуемый вариант для браузера — Web Speech API, включающий интерфейс распознавания речи `SpeechRecognition`. Поддержка зависит от браузера и платформы, поэтому необходимо иметь запасной вариант ручного ввода. [108][110]

## 15.2. Кнопка

В поле ввода разместить кнопку микрофона:

```text
[Микрофон]
```

Состояния:

```text
IDLE        — ожидание
LISTENING   — запись голоса
PROCESSING  — распознавание
RESULT      — текст получен
ERROR       — ошибка
UNSUPPORTED — браузер не поддерживает функцию
```

## 15.3. Сценарий

1. Пользователь нажимает кнопку микрофона.
2. Браузер запрашивает доступ к микрофону.
3. Система показывает индикатор записи.
4. Пользователь говорит.
5. Распознанный текст отображается в поле ввода.
6. Пользователь может исправить текст.
7. Пользователь нажимает «Отправить».
8. Сообщение отправляется как обычный текст.
9. В журнале сохраняется признак `VOICE_TRANSCRIPT`.

## 15.4. Требования

- не отправлять сообщение автоматически без подтверждения;
- позволить редактировать распознанный текст;
- поддержать русский язык;
- предусмотреть выбор языка;
- показывать ошибку доступа к микрофону;
- останавливать запись по повторному нажатию;
- автоматически останавливать запись после паузы;
- не хранить аудиозапись без отдельного согласия;
- показывать уведомление о передаче голоса внешнему сервису, если используется внешний распознаватель.

## 15.5. Языки

В MVP:

```text
Русский
Английский
Немецкий
```

Язык можно выбирать:

```text
Автоматически
Русский
English
Deutsch
```

- имя автора;

# 18. Добавление пользователей в комнату

## 18.1. Кто может добавлять

Добавлять пользователей могут:

- администратор комнаты;
- модератор комнаты;
- глобальный администратор.

## 18.2. Сценарий

1. Нажать «Добавить участников».
2. Открыть поиск пользователей.
3. Найти одного или нескольких пользователей.
4. Проверить их глобальные ограничения.
5. Показать предупреждение, если пользователь не может быть добавлен.
6. Подтвердить добавление.
7. Создать членство.
8. Создать системное сообщение.
9. Отправить уведомление.
10. Обновить список участников.

## 18.3. Массовое добавление

Предусмотреть возможность выбрать несколько пользователей.

Лимит MVP:

```text
Не более 50 пользователей за одну операцию
```

## 18.4. Нельзя добавить

Нельзя добавить пользователя, если:

- он глобально заблокирован;
- ему запрещено вступать в групповые комнаты;
- он уже участник;
- он ранее покинул комнату, если включён запрет повторного добавления;
- достигнут лимит участников;
- пользователь заблокировал администратора;
- комната закрыта;
- добавляющий не имеет прав.

# 19. Исключение пользователей

## 19.1. Кто может исключать

- администратор комнаты;
- модератор комнаты;
- глобальный администратор.

## 19.2. Ограничения

Модератор не может:

- исключить администратора;
- исключить другого модератора, если это запрещено настройками;
- изменить глобальный статус пользователя;
- удалить комнату.

Администратор не может:

- исключить себя без передачи прав;
- исключить глобального администратора;
- обойти глобальную блокировку.

## 19.3. Сценарий исключения

1. Открыть меню участника.
2. Нажать «Исключить».
3. Показать подтверждение.
4. При необходимости указать причину.
5. Проверить право на сервере.
6. Удалить активное членство.
7. Закрыть доступ к новым сообщениям.
8. Создать системное сообщение.
9. Отправить уведомление пользователю.
10. Записать действие в журнал.

## 19.4. Причина исключения

Причина необязательна для обычного модератора, но обязательна:

- при массовом исключении;
- при исключении администратора глобальным администратором;
- при ручной санкции;
- при расследовании.

# 20. Управление модераторами

## 20.1. Назначение модератора

Администратор:

1. открывает список участников;
2. выбирает пользователя;
3. нажимает «Назначить модератором»;
4. подтверждает действие;
5. система меняет роль;
6. создаёт системное сообщение;
7. отправляет уведомление;
8. записывает операцию в журнал.

## 20.2. Снятие модератора

Администратор может снять модератора.

После снятия:

- пользователь остаётся участником;
- права модератора снимаются;
- история действий сохраняется;
- уведомление отправляется пользователю.

## 20.3. Передача администратора

Предусмотреть возможность:

```text
Передать права администратора
```

Передача должна требовать:

- подтверждения текущего администратора;
- выбора нового пользователя;
- повторного подтверждения;
- записи в аудит.

# 22. Системные сообщения

Система должна создавать сообщения для событий комнаты:

```text
Пользователь A присоединился к комнате
Пользователь A был добавлен
Пользователь A покинул комнату
Пользователь A был исключён
Пользователь A назначен модератором
Пользователь A снят с должности модератора
Название комнаты изменено
Описание комнаты изменено
Комната закрыта
```

Системные сообщения:

- имеют тип `SYSTEM`;
- не могут быть отправлены обычным пользователем;
- отображаются с особым стилем;
- не увеличивают обычный счётчик непрочитанных, если это настройка комнаты;
- сохраняются в истории.

# 24. Архитектура реального времени

## 24.1. WebSocket

Для доставки новых сообщений использовать:

```text

```

- новых сообщений;
- изменений статуса;

WebSocket-соединение само по себе не даёт права на действия. Авторизацию нужно проверять отдельно для каждого действия и каждого сообщения. Также необходимо проверять `Origin` при установлении соединения и использовать список разрешённых источников. [109]

- изменения настроек;
- получения списка участников;
- административных действий.

# 25. Авторизация WebSocket

При подключении:

1. проверить TLS;
2. проверить `Origin`;
3. проверить access token;
4. определить пользователя;
5. создать connection session;
6. подписать пользователя на разрешённые чаты;
7. обновлять heartbeat;
8. удалять соединение по таймауту.

Для каждого действия:

```text
проверить аутентификацию
проверить членство в чате
проверить глобальные ограничения
проверить роль
проверить лимиты
проверить тип операции
```

Нельзя считать, что открытое WebSocket-соединение автоматически даёт доступ ко всем чатам.

# 29. Личные чаты

## 29.1. Создание

Личный чат создаётся при первом действии:

```text
Пользователь A нажал «Написать»
```

Если чат между этими пользователями уже существует, создавать новый нельзя.

Уникальный ключ:

```text
min(userA, userB) + max(userA, userB)
```

## 29.2. Ограничения

Нельзя отправить сообщение, если:

- отправитель заблокирован;
- получатель заблокировал отправителя;
- отправителю запрещены личные сообщения;
- получатель запретил входящие сообщения;
- превышен лимит сообщений;
- аккаунт не подтверждён, если это обязательное правило.

## 29.3. Информация о пользователе

В третьей колонке личного чата отображать:

- аватар;
- имя;
- никнейм;
- онлайн-статус;

# 34. Индикаторы непрочитанных сообщений

## 34.1. Расчёт

Для каждого пользователя хранить:

```text
lastReadMessageId
lastReadAt
unreadCount
```

Количество непрочитанных сообщений рассчитывать как количество сообщений после `lastReadMessageId`, отправленных не самим пользователем.

## 34.2. Открытие чата

При открытии чата:

1. загрузить историю;
2. определить первое непрочитанное сообщение;
3. вставить разделитель;
4. после просмотра вызвать endpoint `read`;
5. обновить счётчики;
6. отправить WebSocket-событие.

## 34.3. Не считать прочитанным

Сообщение не считается прочитанным, если:

- чат открыт в фоне;
- вкладка неактивна;
- пользователь не прокрутил до сообщения;
- окно скрыто;
- соединение потеряно.

Запрещённые:

- есть rate limiting;
- есть журнал действий модераторов;
- пользователи без доступа не видят сообщения;
- удалённые сообщения не отображаются обычным пользователям;
- поиск учитывает права доступа.

# 48. Итоговая логика

```text
Пользователь открывает раздел «Чаты».

В левой колонке видит:
- фильтры «Все», «Личные», «Групповые»;
- количество чатов;
- поиск;
- список личных и групповых чатов;
- индикаторы непрочитанных.

Пользователь выбирает чат.

В центральной колонке отображаются:
- сообщения;
- ответы;
- разделитель новых сообщений;
- поле ввода;
- кнопка голосового набора;
- кнопка отправки;
- поиск по сообщениям.

В правой колонке отображаются:
- данные пользователя или комнаты;
- описание;
- список участников;
- роли;
- модераторы;
- настройки;
- кнопка выхода.

Администратор комнаты может:
- изменить название;
- добавить описание;
- назначить модераторов;
- добавить участников;
- исключить участников;
- удалить сообщения;
- изменить настройки.

Модератор может:
- добавлять пользователей;
- исключать пользователей;
- удалять сообщения;
- ограничивать отправку.

Участник может:
- читать;
- писать;
- отвечать;
- искать;
- использовать голосовой набор;
- покинуть комнату.

Глобальные ограничения сайта имеют приоритет над всеми локальными правами комнаты.
```

# 49. Главный принцип

```text
Личный чат используется для общения один на один.

Групповая комната используется для общения сообщества.

Название комнаты обязательно при создании.

Описание можно добавить позже.

Пользователь может автоматически попасть в комнату,
если это разрешено комнатой и не запрещено глобальными правилами.

Администратор управляет комнатой.

Модераторы помогают управлять участниками и сообщениями.

Любой участник может самостоятельно покинуть комнату.

Три колонки обеспечивают одновременный доступ к чатам,
сообщениям и информации о комнате.

Поиск помогает находить комнаты, пользователей и сообщения.

Голосовой набор преобразует речь в редактируемый текст.

Индикаторы непрочитанных сообщений позволяют не пропустить активность.
```
