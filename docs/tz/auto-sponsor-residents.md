# ТЗ: Автоматическое спонсирование новых игроков городом

**Версия:** 1.0  
**Дата:** 29.10.2026  
**Статус:** концепция для проработки  
**Приоритет:** высокий  
**Модуль:** Города / Новые игроки / Бюджеты / Экономика

---

# 1. Идея

При поселении нового игрока в город система автоматически резервирует часть городского бюджета на его стартовую поддержку.

Это решает главную проблему:

```text
Новый игрок не должен зависеть от того,
успел ли владелец города вручную пополнить бюджет.
```

Владелец города заранее пополняет городской бюджет.

Когда новый игрок выбирает город и размещает стоянку, система:

```text
1. Проверяет бюджет города.
2. Резервирует стартовый спонсорский пакет.
3. Создаёт обязательство перед новичком.
4. Постепенно выдаёт поддержку.
5. Фиксирует все операции в журнале.
```

Это не эмиссия «из ниоткуда». Это **перераспределение уже созданных кредитов** из городского бюджета новому игроку.

---

# 2. Главный принцип

```text
Город спонсирует новичка из заранее накопленного бюджета,
а не создаёт кредиты в момент его поселения.
```

Правильная модель:

```text
Владелец города пополняет бюджет
→ система резервирует часть бюджета
→ новый игрок получает поддержку
→ город получает нового жителя и будущую активность
```

Неправильная модель:

```text
Новый игрок пришёл
→ система создала кредиты из ниоткуда
→ город получил нового жителя
→ количество кредитов в экономике выросло
```

Второй вариант допустим только как ограниченный системный бонус, но не как основной механизм поддержки новичков.

---

# 3. Почему идея хорошая

## 3.1. Новичок не остаётся без поддержки

Игрок может прийти в город, где владелец забыл пополнить бюджет.

Если поддержка создаётся автоматически из заранее зарезервированного бюджета, новичок всё равно получает старт.

## 3.2. Владелец города получает мотивацию

Чем больше активных новых жителей приходит в город, тем больше:

```text
активности;
сделок;
налогов;
комиссий;
спроса на ресурсы;
развития экономики города.
```

Владелец города заинтересован:

```text
пополнять бюджет;
создавать задания;
проводить конкурсы;
помогать новичкам;
развивать инфраструктуру;
привлекать игроков.
```

## 3.3. Экономика становится предсказуемой

Городской бюджет заранее показывает:

```text
сколько новичков город может принять;
сколько кредитов зарезервировано;
сколько поддержки доступно;
когда бюджет заканчивается.
```

Это лучше, чем выдавать поддержку из воздуха.

## 3.4. Снижается риск злоупотреблений

Если поддержка выдаётся только из бюджета города, то:

```text
нельзя бесконечно создавать новых аккаунтов для получения бонусов;
нельзя получать поддержку без участия города;
нельзя генерировать кредиты через массовую регистрацию.
```

---

# 4. Важное ограничение

Автоматическое резервирование не должно быть эмиссией.

```text
Городской бюджет должен быть пополнен заранее.
```

Если бюджет города пуст:

```text
новый игрок всё равно может поселиться;
но спонсорский пакет не выдаётся;
игрок получает только базовый системный старт;
город помечается как «нет мест для спонсорства» или «поддержка временно недоступна».
```

Нельзя допускать отрицательный бюджет города.

---

# 5. Модель поддержки новичка

## 5.1. Два вида поддержки

### Системный старт

Выдаётся всем новым игрокам независимо от города.

```text
Источник: системная эмиссия
Размер: небольшой
Цель: игрок может начать играть
```

Пример:

```text
100 кредитов
базовые ресурсы
1 инструмент
1 эликсир исследователя
```

### Городское спонсорство

Выдаётся только при поселении в город с доступным бюджетом.

```text
Источник: бюджет города
Размер: заметный, но ограниченный
Цель: ускорить первый прогресс и связать игрока с городом
```

Пример:

```text
150 кредитов
ресурсы
ускорение
местный стартовый набор
```

## 5.2. Рекомендуемая логика

```text
Системный старт — гарантирован.
Городское спонсорство — возможно, если есть бюджет.
```

Так новичок никогда не остаётся полностью без поддержки, но город может дать дополнительную помощь.

# 6. Механика резервирования

## 6.1. Когда происходит резервирование

Резервирование выполняется в момент:

```text
игрок выбрал город;
игрок подтвердил поселение;
игрок создал стоянку в городе.
```

Рекомендуемый момент:

```text
После создания стоянки.
```

Почему:

```text
Это подтверждает реальное начало игры.
Позволяет избежать резервирования при простом просмотре городов.
Уменьшает риск создания пустых аккаунтов.
```

## 6.2. Что резервируется

При поселении система резервирует:

```text
городской спонсорский пакет нового игрока.
```

Пример:

```text
Спонсорский пакет: 150 Cr
```

## 6.3. Как это выглядит в бюджете

```text
Баланс города: 10 000 Cr
Зарезервировано: 150 Cr
Доступно: 9 850 Cr
```

Резерв — это не расход и не выдача.

Это обязательство:

```text
Деньги уже не могут быть потрачены на другое.
Но игрок ещё не получил их полностью.
```

## 6.4. Когда резерв превращается в выдачу

Поддержку лучше выдавать частями.

Пример:

```text
При поселении: 50 Cr
Через 24 часа: 50 Cr
После первого задания: 50 Cr
```

Так новичок получает причину вернуться, а город получает более длительную активность.

# 7. Рекомендуемый спонсорский пакет

## 7.1. Базовый пакет

```text
150 кредитов
```

Выдача:

```text
50 Cr — сразу после поселения
50 Cr — через 24 часа
50 Cr — после выполнения первого городского задания
```

## 7.2. Ресурсы

```text
10 брёвен
10 камней
5 волокон
5 воды
2 семени моркови
```

## 7.3. Дополнительные бонусы

```text
1 ускорение на 30 минут
1 эликсир исследователя
```

## 7.4. Полная стоимость пакета

```text
150 кредитов
+ ресурсы
+ ускорение
+ эликсир
```

Для бюджета города можно учитывать только кредитную часть:

```text
150 Cr
```

Ресурсы и предметы могут выдаваться из городского склада или создаваться системой по отдельным правилам.

Для первой версии рекомендуется:

```text
Выдавать только кредиты.
Ресурсы и предметы добавить позже.
```

# 8. Правила городского бюджета

## 8.1. Структура бюджета

```text
city_budget
├── available_balance
├── reserved_for_newcomers
├── reserved_for_quests
├── reserved_for_events
├── reserved_for_projects
└── burned_amount
```

## 8.2. Балансы

```text
total_balance =
available_balance
+ reserved_for_newcomers
+ reserved_for_quests
+ reserved_for_events
+ reserved_for_projects
```

## 8.3. Правила

```text
Нельзя потратить зарезервированные кредиты на другие цели.
Нельзя сделать available_balance отрицательным.
Нельзя выдать больше, чем зарезервировано.
Нельзя резервировать больше, чем есть в available_balance.
Нельзя удалять резерв без завершения или отмены обязательства.
```

## 8.4. Пример

```text
Городской бюджет: 10 000 Cr

Резервы:
новички: 1 500 Cr
задания: 2 000 Cr
события: 500 Cr

Доступно:
6 000 Cr
```

# 9. Лимиты

## 9.1. Лимиты города

```text
Максимум спонсируемых новичков в сутки: 10
Максимум спонсируемых новичков в неделю: 50
Максимум суммы резервов на новичков в сутки: 1 500 Cr
Минимальный остаток бюджета города: 1 000 Cr
Максимальная доля бюджета на новичков: 30%
```

## 9.2. Лимиты игрока

```text
Городское спонсорство: 1 раз на аккаунт
Повторное получение: запрещено
Перенос спонсорства в другой город: запрещено
Возврат спонсорства в бюджет: только при отмене поселения до выдачи
```

## 9.3. Лимиты владельца города

```text
Владелец не может изменить размер пакета произвольно.
Владелец не может выдать поддержку без поселения.
Владелец не может зарезервировать бюджет для конкретного игрока вручную.
Владелец не может вернуть зарезервированные кредиты себе после поселения.
```

# 10. Антифрод

## 10.1. Риски

```text
Создание множества аккаунтов для получения спонсорства.
Сговор владельца города и новых аккаунтов.
Быстрая регистрация и удаление аккаунтов.
Перевод кредитов между своими аккаунтами.
Фарм городских заданий.
Использование одного устройства или IP.
```

## 10.2. Защита

```text
Спонсорство — один раз на аккаунт.
Выдача — частями.
Последняя часть — только после реального действия.
Проверка устройства и IP.
Проверка возраста аккаунта.
Проверка активности.
Проверка связанных аккаунтов.
Лимит на город в сутки.
Лимит на владельца города.
Задержка вывода крупных сумм.
Журнал всех операций.
```

## 10.3. Рекомендуемое правило

Последнюю часть пакета выдавать только после действия, которое трудно выполнить ботом:

```text
выполнить первое городское задание;
построить первый объект;
сделать первый крафт;
собрать урожай;
провести первую сделку на рынке.
```

# 13. Сценарии

## Сценарий 1. У города достаточно бюджета

```text
1. Новый игрок регистрируется.
2. Выбирает город.
3. Создаёт стоянку.
4. Система проверяет правила города.
5. Система проверяет available_balance.
6. Система резервирует 150 Cr.
7. Система создаёт sponsorship со статусом RESERVED.
8. Система выдаёт первую часть: 50 Cr.
9. Статус становится PARTIALLY_PAID.
10. Через 24 часа выдаётся вторая часть.
11. После первого задания выдаётся третья часть.
12. Статус становится COMPLETED.
```

## Сценарий 2. У города недостаточно бюджета

```text
1. Новый игрок выбирает город.
2. Создаёт стоянку.
3. Система проверяет бюджет.
4. available_balance меньше стоимости пакета.
5. Система не создаёт спонсорство.
6. Игрок получает только системный старт.
7. Город получает уведомление:
   «Бюджет для спонсорства новичков закончился».
```

## Сценарий 3. Город достиг дневного лимита

```text
1. Город уже спонсировал 10 новичков за сутки.
2. Новый игрок создаёт стоянку.
3. Система не резервирует бюджет.
4. Игрок получает только системный старт.
5. Владелец города получает уведомление.
```

## Сценарий 4. Игрок не выполнил условие

```text
1. Игрок получил первые две части.
2. Третья часть зависит от выполнения задания.
3. Игрок не выполнил задание в течение 7 дней.
4. Резерв аннулируется.
5. Оставшаяся часть возвращается в available_balance города.
6. Спонсорство получает статус EXPIRED.
```

# 14. Интерфейс

## 14.1. Для нового игрока

При поселении показывать:

```text
Добро пожаловать в город «{Название}»!

Город подготовил для вас стартовую поддержку:

- 150 кредитов
- ресурсы для старта
- ускорение строительства
- эликсир исследователя

Первая часть уже зачислена.
Следующая часть будет доступна через 24 часа.
```

Если поддержки нет:

```text
Добро пожаловать в город «{Название}»!

Сейчас город не может предоставить дополнительную поддержку,
но вы получили базовый стартовый набор.
```

## 14.2. Для владельца города

Владелец видит:

```text
Баланс города
Доступно
Зарезервировано на новичков
Спонсировано за сутки
Лимит на сутки
Оставшиеся места
Список новых жителей
Статус их поддержки
```

Пример:

```text
Бюджет города: 10 000 Cr
Доступно: 8 350 Cr
Зарезервировано на новичков: 1 500 Cr
Спонсировано сегодня: 4 из 10
Осталось мест сегодня: 6
```

## 14.3. Уведомления владельцу

```text
Новый житель поселился в городе
Выдана первая часть поддержки
Бюджет для новичков заканчивается
Достигнут дневной лимит
Новый игрок выполнил первое задание
```

# 16. Логика резервирования

## 16.1. Алгоритм

```text
1. Игрок создаёт стоянку в городе.
2. Проверить, что спонсорство включено.
3. Проверить, что игрок ещё не получал спонсорство.
4. Проверить, что аккаунт не заблокирован.
5. Проверить возраст аккаунта.
6. Проверить дневной лимит города.
7. Проверить недельный лимит города.
8. Проверить available_balance города.
9. Проверить минимальный остаток бюджета.
10. Проверить долю бюджета на новичков.
11. Зарезервировать сумму.
12. Создать sponsorship.
13. Создать платежи по частям.
14. Выдать первую часть.
15. Записать операции в журнал.
16. Отправить уведомления.
```

## 16.2. Идемпотентность

Ключ:

```text
userId + cityId + SPONSORSHIP + plotId
```

Повторный запрос не должен:

```text
создавать второе спонсорство;
резервировать кредиты повторно;
выдавать первую часть повторно;
уменьшать доступный бюджет повторно.
```

# 17. Экономический эффект

## 17.1. Для нового игрока

```text
Гарантированный системный старт.
Возможное дополнительное спонсорство.
Понятный путь первых действий.
Причина вернуться через 24 часа.
Причина выполнить первое городское задание.
```

## 17.2. Для владельца города

```text
Новые жители увеличивают активность.
Активность увеличивает налоги и комиссии.
Комиссии пополняют бюджет.
Бюджет позволяет принимать новых жителей.
Возникает устойчивый цикл развития.
```

## 17.3. Для экономики

```text
Кредиты не создаются при поселении.
Кредиты перераспределяются из бюджета города.
Часть бюджетных операций сжигается.
Экономика остаётся управляемой.
```

# 18. Цикл развития города

```text
Владелец пополняет бюджет
→ город принимает новичков
→ новичок получает поддержку
→ новичок начинает играть
→ новичок выполняет задания
→ новичок торгует и строит
→ город получает налоги и комиссии
→ бюджет города растёт
→ город может принимать больше новичков
```

Это здоровый цикл, если соблюдать лимиты и не превращать городские выплаты в бесконечную эмиссию.

# 20. Критерии приёмки

Задача считается выполненной, если:

- новый игрок получает системный старт всегда;
- при наличии бюджета города игрок получает дополнительное спонсорство;
- спонсорство резервируется автоматически;
- бюджет города не может стать отрицательным;
- резерв нельзя потратить на другие цели;
- поддержка выдаётся частями;
- последняя часть зависит от реального действия;
- есть дневные и недельные лимиты;
- спонсорство выдаётся один раз на аккаунт;
- есть защита от мультиаккаунтов;
- есть журнал всех операций;
- есть идемпотентность;
- владелец города видит бюджет, резервы и лимиты;
- есть уведомления игроку и владельцу города;
- есть API и UI;
- есть тесты.

# 21. Итоговое решение

Идея правильная, если реализовать её так:

```text
Город заранее пополняет бюджет.
При поселении новичка система резервирует часть бюджета.
Поддержка выдаётся частями.
Последняя часть выдаётся за реальное действие.
Кредиты не создаются в момент поселения.
Город получает мотивацию привлекать активных игроков.
```

Рекомендуемая стартовая модель:

```text
Системный старт: 100 Cr
Городское спонсорство: 150 Cr
Выдача: 50 + 50 + 50 Cr
Лимит: 10 новичков в сутки на город
Условие последней части: первое городское задание
```

Это автоматизирует поддержку новичков, защищает экономику от бесконтрольной эмиссии и создаёт устойчивую мотивацию для владельцев городов развивать свои территории.
