# 1. Цель задачи

Создать рынок в городах, где игроки смогут продавать и покупать предметы за внутреннюю валюту — кредиты.

Рынок должен:

- дать игрокам способ продавать ресурсы и предметы;
- создать экономическую активность между пользователями;
- поддержать специализацию игроков;
- не допустить накрутку кредитов;
- не допустить обесценивания предметов;
- работать безопасно и прозрачно;
- иметь журнал всех операций;
- поддерживать будущие расширения: аукцион, заказы, городские рынки, налоги.

# 2. Основные принципы

## 2.1. Валюта

Внутренняя валюта рынка — кредиты.

```text
Обозначение: Cr
Базовый курс отображения: 1 Cr = 1 ₽
Кредиты нельзя вывести в реальные деньги.
```

Кредиты, полученные с рынка, остаются внутри игры.

## 2.2. Типы рынка

На первом этапе реализуются два типа рынка:

| Тип | Кто продаёт | Кто покупает | Цены |
|---|---|---|---|
| Городской рынок NPC | Игрок | NPC-рынок | Фиксированные |
| Рынок игроков | Игрок | Игрок | Свободные, с ограничениями |

## 2.3. Что разрешено продавать

Разрешены только предметы из белого списка.

На старте:

```text
Базовые ресурсы
Материалы
Готовые предметы
Инструменты
Еда
Косметика без привязки к владельцу
```

## 2.4. Что запрещено продавать

Запрещены:

```text
Объекты, установленные на карте
Активные стройки
Предметы, участвующие в квестах
Системные предметы
Предметы с привязкой к владельцу
Предметы, полученные в результате ошибки или эксплойта
Предметы, находящиеся в чужом хранилище
Предметы, находящиеся в активной операции
```

# 3. Роли и доступ

## 3.1. Игрок

Игрок может:

- открыть рынок в городе;
- посмотреть доступные объявления;
- выставить предмет на продажу;
- купить предмет у другого игрока;
- продать предмет городскому рынку;
- купить предмет у городского рынка;
- отменить своё объявление;
- посмотреть историю своих сделок;
- получить кредиты после продажи.

## 3.2. Гость

Гость может:

- просматривать рынок, если это разрешено настройками;
- не может покупать, продавать или создавать объявления.

## 3.3. Модератор

Модератор может:

- просматривать объявления;
- скрывать объявление;
- блокировать объявление;
- просматривать историю сделок;
- просматривать жалобы;
- помечать подозрительные операции;
- отменять сделку по регламенту.

## 3.4. Администратор

Администратор может:

- управлять городскими ценами;
- включать и отключать категории;
- управлять лимитами;
- настраивать комиссию;
- просматривать аналитику;
- блокировать пользователей;
- отменять подозрительные сделки;
- изменять глобальные настройки рынка.

Все действия администратора должны логироваться.

# 4. Городской рынок NPC

## 4.1. Назначение

Городской рынок NPC нужен для старта экономики.

Он позволяет:

- продать базовые ресурсы;
- купить недостающие материалы;
- получить гарантированную цену;
- не зависеть от наличия других игроков.

## 4.2. Правила продажи NPC

Игрок может продать предмет городскому рынку.

```text
Цена продажи NPC = базовая цена × коэффициент продажи
```

Рекомендуемый коэффициент:

```text
0,4–0,6
```

Пример:

```text
Базовая цена бревна: 4 Cr
Коэффициент продажи: 0,5
Цена продажи NPC: 2 Cr
```

## 4.3. Правила покупки у NPC

Игрок может купить предмет у городского рынка.

```text
Цена покупки NPC = базовая цена × коэффициент покупки
```

Рекомендуемый коэффициент:

```text
1,1–1,3
```

Пример:

```text
Базовая цена бревна: 4 Cr
Коэффициент покупки: 1,25
Цена покупки NPC: 5 Cr
```

```text
Не более 20 продаж NPC в сутки

Не более 50 одинаковых предметов за одну операцию
```

Лимиты должны настраиваться в админке.

# 5. Рынок игроков

## 5.1. Назначение

Рынок игроков позволяет пользователям продавать предметы друг другу по собственной цене.

## 5.2. Основной сценарий

```text
1. Игрок открывает рынок в городе.
2. Выбирает предмет из инвентаря или хранилища.
3. Указывает количество и цену.
4. Создаёт объявление.
5. Предмет резервируется.
6. Другой игрок находит объявление.
7. Покупает предмет.
8. Кредиты списываются у покупателя.
9. Комиссия удерживается.
10. Предмет передаётся покупателю.
11. Продавец получает кредиты.
12. Операция фиксируется в журнале.
```

## 5.3. Тип объявления

На старте используется один тип:

```text
Фиксированная цена
```

Аукцион, ставки и торги не входят в первую версию.

## 5.4. Статусы объявления

| Статус | Описание |
|---|---|
| `DRAFT` | Черновик, не виден другим |
| `ACTIVE` | Активно, доступно для покупки |
| `RESERVED` | Временно зарезервировано |
| `SOLD` | Продано |
| `CANCELLED` | Отменено продавцом |
| `EXPIRED` | Истёк срок |
| `BLOCKED` | Заблокировано модератором |
| `REMOVED` | Удалено системой |

# 6. Создание объявления

## 6.1. Обязательные поля

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `seller_id` | ID | да | Продавец |
| `city_id` | ID | да | Город, в котором размещён рынок |
| `market_id` | ID | да | Конкретный рынок |
| `item_code` | string | да | Код предмета |
| `item_instance_id` | ID | да | Конкретный экземпляр предмета |
| `quantity` | integer | да | Количество |
| `price_per_unit` | integer | да | Цена за единицу |
| `total_price` | integer | да | Общая цена |
| `commission_rate` | decimal | да | Комиссия на момент создания |
| `commission_amount` | integer | да | Комиссия |
| `seller_income` | integer | да | Сумма к получению продавцом |
| `status` | string | да | Статус |
| `expires_at` | datetime | да | Дата окончания |
| `created_at` | datetime | да | Дата создания |
| `updated_at` | datetime | да | Дата обновления |

## 6.2. Условия создания

Объявление можно создать, если:

```text
пользователь авторизован;
пользователь не заблокирован;
предмет принадлежит пользователю;
предмет не привязан;
предмет разрешён к продаже;
предмет не участвует в активной стройке;
предмет не участвует в квесте;
предмет находится в доступном хранилище;
количество больше 0;
цена больше 0;
не превышен лимит активных объявлений;
не превышен дневной лимит объявлений;
рынок активен;
город доступен.
```

## 6.3. Резервирование предмета

При создании объявления предмет должен быть зарезервирован.

```text
Предмет нельзя:
- продать повторно;
- использовать в крафте;
- переместить;
- уничтожить;
- использовать в стройке;
- передать другому игроку.
```

Если предмет был удалён, уничтожен, использован или стал недоступен, объявление должно автоматически перейти в статус `REMOVED`.

## 6.4. Отмена объявления

Продавец может отменить объявление, если оно в статусе:

```text
ACTIVE
RESERVED
```

После отмены:

```text
предмет возвращается владельцу;
резерв снимается;
кредиты не начисляются;
операция фиксируется в журнале.
```

# 7. Покупка

## 7.1. Условия покупки

Покупка возможна, если:

```text
пользователь авторизован;
пользователь не заблокирован;
объявление активно;
покупатель не является продавцом;
у покупателя достаточно кредитов;
предмет всё ещё зарезервирован;
количество доступно;
рынок активен;
город доступен;
не превышен дневной лимит покупок;
не превышен дневной лимит расходов.
```

## 7.2. Процесс покупки

Покупка должна выполняться атомарно.

```text
1. Проверить объявление.
2. Проверить права покупателя.
3. Проверить баланс.
4. Зарезервировать сумму.
5. Проверить предмет.
6. Списать кредиты у покупателя.
7. Удержать комиссию.
8. Передать предмет покупателю.
9. Начислить кредиты продавцу.
10. Изменить статус объявления.
11. Создать запись сделки.
12. Создать записи в журнале экономики.
13. Отправить уведомления.
```

Если любая проверка не прошла, операция отменяется полностью.

## 7.3. Защита от двойной покупки

Две попытки купить один и тот же предмет одновременно не должны привести к двойной продаже.

Требования:

```text
транзакция базы данных;
блокировка строки объявления;
проверка статуса;
идемпотентный ключ операции;
уникальный идентификатор сделки;
```

## 7.4. Ошибка покупки

Если после списания кредитов предмет невозможно передать:

```text
кредиты возвращаются покупателю;
сделка отменяется;
объявление возвращается в ACTIVE;
операция помечается как ошибочная;
создаётся запись в журнале ошибок.
```

# 8. Комиссия

## 8.1. Базовая комиссия

```text
10% от суммы сделки
```

Комиссия удерживается с продавца.

## 8.2. Формула

```text
total_price = price_per_unit × quantity
commission_amount = round(total_price × commission_rate)
seller_income = total_price − commission_amount
```

Пример:

```text
Цена предмета: 100 Cr
Комиссия: 10%
Комиссия: 10 Cr
Продавец получает: 90 Cr
```

## 8.3. Округление

```text
Округление комиссии: до целого кредита
Правило: математическое округление
Минимальная комиссия: 1 Cr при total_price > 0
```

Примеры:

```text
100 Cr → комиссия 10 Cr
55 Cr → комиссия 6 Cr
12 Cr → комиссия 1 Cr
5 Cr → комиссия 1 Cr
```

## 8.4. Куда уходит комиссия

Комиссия не возвращается продавцу.

Возможные варианты:

```text
сжигание кредитов;
зачисление в городской фонд;
зачисление в системный фонд;
использование для будущих городских событий.
```

Для первой версии:

```text
Комиссия сжигается.
```

# 14. Журнал экономики

Каждая операция рынка должна создавать запись в `economy_transactions`.

## 14.1. Типы операций

# 16. Идемпотентность

Для каждой операции должен быть уникальный ключ:

```text
idempotency_key = userId + marketId + actionType + operationId
```

Повторный запрос с тем же ключом не должен:

```text
создавать второе объявление;
списывать кредиты повторно;
передавать предмет повторно;
начислять кредиты повторно;
создавать вторую транзакцию.
```

# 22. Критерии приёмки

Задача считается выполненной, если:

- игрок может открыть рынок в городе;
- игрок может продать предмет NPC;
- игрок может купить предмет у NPC;
- игрок может создать объявление;
- другой игрок может купить объявление;
- комиссия рассчитывается корректно;
- предмет резервируется;
- предмет нельзя продать дважды;
- кредиты не могут быть начислены дважды;
- все операции записываются в журнал;
- есть идемпотентность;
- есть лимиты;
- есть защита от накрутки;
- есть история сделок;
- есть уведомления;
- есть админка;
- есть аналитика;
- есть тесты;
- есть обработка ошибок;
- есть восстановление после сбоя.

# 25. Итоговое решение

```text
Первый этап: городской рынок NPC с фиксированными ценами.
Второй этап: рынок игроков с комиссией 10%.
Третий этап: аукцион и расширенная торговля.
```

Рынок игроков — хорошая механика, но только при наличии:

```text
белого списка предметов;
лимитов;
комиссии;
журнала;
идемпотентности;
антифрода;
модерации;
аналитики.
```

Без этих мер свободный рынок может быстро привести к накрутке кредитов, спекуляции и обесцениванию игровой экономики.
