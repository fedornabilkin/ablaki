**Приоритет:** высокий  
**Модуль:** Уведомления / Хедер / Пользовательский интерфейс

---

# 1. Цель задачи

Реализовать центр уведомлений пользователя в виде колокольчика в хедере.

Функционал должен позволять:

- видеть количество непрочитанных уведомлений;
- открывать список последних уведомлений;
- читать уведомления по одному;
- читать все уведомления сразу;
- подгружать предыдущие уведомления;
- переходить из уведомления в соответствующий раздел или страницу;
- видеть категорию, дату и время уведомления.

---

# 2. Основные принципы

```text
1. Уведомления создаются только системой.
2. Пользователь не может создавать уведомления вручную.
3. Непрочитанные уведомления отображаются бейджем с числом.
4. Список открывается по клику на колокольчик.
5. По умолчанию загружаются последние 30 уведомлений.
6. Следующие 30 загружаются по кнопке «Показать ещё».
7. Каждое уведомление можно отметить прочитанным отдельно.
8. Все уведомления можно отметить прочитанными одной кнопкой.
9. По клику на уведомление пользователь переходит на связанную страницу.
10. Переход по уведомлению также помечает его прочитанным.
11. Все действия должны быть идемпотентными.
12. Все уведомления должны сохраняться в базе.
```

# 3. Расположение в интерфейсе

## 3.1. Хедер

В правой части хедера размещается иконка колокольчика.

```text
[Логотип] [Навигация] .................. [Колокольчик] [Аватар]
```

## 3.2. Бейдж непрочитанных

Если есть непрочитанные уведомления, рядом с колокольчиком отображается бейдж.

```text
🔔 3
```

Правила:

```text
0 непрочитанных — бейдж не отображается
1–99 — отображается число
100+ — отображается «99+»
```

## 3.3. Состояния колокольчика

| Состояние | Внешний вид |
|---|---|
| Нет уведомлений | Обычная иконка колокольчика |
| Есть непрочитанные | Колокольчик + красный бейдж с числом |
| 100+ непрочитанных | Колокольчик + бейдж «99+» |
| Загрузка | Индикатор загрузки |
| Ошибка | Иконка ошибки или всплывающее сообщение |

# 4. Окно уведомлений

## 4.1. Открытие

Окно открывается по клику на колокольчик.

Требования:

```text
Открытие — по клику
Закрытие — по клику вне окна, по Escape или по кнопке закрытия
Позиция — под колокольчиком, выравнивание по правому краю
Адаптивность — на мобильных устройствах открывается как панель или модальное окно
```

## 4.2. Размер

Рекомендуемые размеры:

```text
Desktop: ширина 380–440 px
Mobile: ширина 100% экрана
Максимальная высота: 70–80% высоты экрана
Прокрутка: вертикальная
```

## 4.3. Структура окна

```text
┌──────────────────────────────────────┐
│ Уведомления                [Прочитать все] │
├──────────────────────────────────────┤
│ [Уведомление 1]                       │
│ [Уведомление 2]                       │
│ [Уведомление 3]                       │
│ ...                                   │
│ [Уведомление 30]                      │
├──────────────────────────────────────┤
│ [Показать ещё 30]                     │
└──────────────────────────────────────┘
```

## 4.4. Пустое состояние

Если уведомлений нет:

```text
🔔
Уведомлений пока нет

Здесь появятся события,
связанные с вашей стоянкой, городом,
рынком и развитием мира.
```

# 5. Карточка уведомления

## 5.1. Обязательные элементы

Каждое уведомление должно содержать:

```text
иконку категории;
краткий текст;
категорию;
дату и время;
кнопку «Прочитать»;
индикатор прочитанности;
ссылку для перехода, если она задана.
```

## 5.2. Внешний вид

```text
┌──────────────────────────────────────┐
│ [иконка]  Краткий текст уведомления  │
│           Категория                  │
│           29.10.2026, 21:45          │
│                              [✓]     │
└──────────────────────────────────────┘
```

## 5.3. Непрочитанное уведомление

```text
Фон: светлый акцентный фон
Слева: цветная полоса или точка
Текст: обычный или полужирный
Кнопка «Прочитать»: активна
```

## 5.4. Прочитанное уведомление

```text
Фон: обычный фон
Текст: приглушённый
Кнопка «Прочитать»: скрыта, неактивна или заменена состоянием «Прочитано»
```

## 5.5. Клик по карточке

По клику на основную область уведомления:

```text
1. Уведомление помечается прочитанным.
2. Пользователь переходит по ссылке.
3. Окно уведомлений закрывается.
```

Если ссылки нет:

```text
Уведомление помечается прочитанным.
Переход не выполняется.
```

# 6. Кнопки

## 6.1. Кнопка «Прочитать»

Располагается справа в карточке уведомления.

Иконка:

```text
Одна галочка: ✓
```

Действие:

```text
Отметить одно уведомление прочитанным.
```

Требования:

```text
Видна только у непрочитанных уведомлений.
После нажатия уведомление становится прочитанным.
Бейдж в хедере уменьшается на 1.
Операция не должна выполняться повторно.
```

## 6.2. Кнопка «Прочитать все»

Располагается в верхней части окна уведомлений.

Иконка:

```text
Двойная галочка: ✓✓
```

Действие:

```text
Отметить все непрочитанные уведомления пользователя прочитанными.
```

Требования:

```text
Видна, если есть хотя бы одно непрочитанное уведомление.
После нажатия бейдж исчезает.
Все видимые и невидимые непрочитанные уведомления становятся прочитанными.
Операция должна быть подтверждена или легко отменяема, если уведомлений много.
Операция должна быть идемпотентной.
```

## 6.3. Кнопка «Показать ещё»

Располагается внизу списка.

Текст:

```text
Показать ещё 30
```

Действие:

```text
Загрузить следующие 30 уведомлений.
```

Требования:

```text
Кнопка скрыта, если уведомлений больше нет.
Во время загрузки показывается индикатор.
Новые уведомления добавляются в конец списка.
Позиция прокрутки не должна сбрасываться.
```

# 11. Логика работы

## 11.1. Загрузка списка

```text
1. Пользователь открывает колокольчик.
2. Фронт запрашивает последние 30 уведомлений.
3. Сервер возвращает список, количество непрочитанных и флаг has_more.
4. Фронт отображает список.
5. При нажатии «Показать ещё» запрашиваются следующие 30.
6. Новые элементы добавляются в конец списка.
```

## 11.2. Отметить одно прочитанным

```text
1. Пользователь нажимает «✓».
2. Фронт отправляет запрос.
3. Сервер проверяет, что уведомление принадлежит пользователю.
4. Сервер проверяет, что уведомление не прочитано.
5. Сервер ставит is_read = true и read_at.
6. Сервер возвращает новый unread_count.
7. Фронт обновляет карточку и бейдж.
```

## 11.3. Отметить все прочитанными

```text
1. Пользователь нажимает «✓✓».
2. Фронт отправляет запрос read-all.
3. Сервер помечает все непрочитанные уведомления пользователя.
4. Сервер возвращает количество изменённых записей.
5. Фронт обновляет список и убирает бейдж.
```

## 11.4. Переход по уведомлению

```text
1. Пользователь кликает по карточке.
2. Фронт отправляет запрос на отметку прочитанным.
3. Фронт выполняет переход по ссылке.
4. Окно уведомлений закрывается.
```

Переход должен происходить даже при ошибке отметки прочтения, но ошибка должна быть зафиксирована.

---

# 12. Идемпотентность

Для каждой операции используется уникальный ключ:

```text
userId + notificationId + actionType + operationId
```

Повторный запрос не должен:

```text
повторно уменьшать unread_count;
создавать вторую операцию;
менять read_at повторно;
создавать дубликат уведомления.
```

Для `read-all` использовать ключ:

```text
userId + READ_ALL + дата/время запроса
```

# 13. Обновление бейджа

## 13.1. Способы обновления

Рекомендуемая комбинация:

```text
1. Обновление при загрузке страницы.
2. Обновление после открытия окна уведомлений.
3. Обновление после отметки прочитанным.
4. Обновление после отметки всех прочитанными.
5. Периодический опрос, если realtime недоступен.
6. WebSocket или Server-Sent Events, если realtime доступен.
```

## 13.2. Периодический опрос

Для первой версии:

```text
Интервал: 30–60 секунд
Только когда пользователь активен
Не опрашивать в фоновой вкладке
```

## 13.3. Realtime

Если используется WebSocket или SSE:

```text
Событие: notification.created
Данные: notification_id, unread_count
```

# 14. Хранение и очистка

## 14.1. Хранение

```text
Уведомления хранятся минимум 90 дней.
Важные уведомления могут храниться дольше.
Системные объявления могут иметь отдельный срок.
```

## 14.2. Очистка

```text
Обычные уведомления: удалять через 90 дней
Прочитанные уведомления: можно удалять раньше
Важные уведомления: хранить по отдельному правилу
Уведомления с платежами: хранить согласно требованиям учёта
```

## 14.3. Лимиты

```text
Максимум уведомлений на пользователя: 1 000
Максимум непрочитанных: 500
Максимум одинаковых уведомлений в час: зависит от типа
```

При превышении лимита старые менее важные уведомления архивируются или удаляются.

# 17. Критерии приёмки

Задача считается выполненной, если:

- в хедере есть колокольчик;
- есть бейдж с числом непрочитанных;
- при 100+ отображается «99+»;
- по клику открывается окно уведомлений;
- загружаются последние 30 уведомлений;
- можно загрузить следующие 30;
- у каждого уведомления есть дата, время, текст и категория;
- есть кнопка «Прочитать» у непрочитанных;
- есть кнопка «Прочитать все»;
- по клику на уведомление выполняется переход;
- переход помечает уведомление прочитанным;
- бейдж корректно обновляется;
- уведомления хранятся в базе;
- есть журнал и идемпотентность;
- есть API;
- есть UI для desktop и mobile;
- есть тесты.
