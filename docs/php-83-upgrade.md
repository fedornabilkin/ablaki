# PHP 8.3.36

Изолированное обновление от production `bf08acb`, без невыпущенных функций мира. PHP FPM и Composer CLI закреплены на 8.3.36, Composer — на 2.10.3; Yii обновлён до 2.0.55. Старый Codeception 2 заменён совместимым Codeception 5. Разрешён только Composer-плагин Yii, который регистрирует расширения приложения.

`session.upload_progress.enabled=0` установлен для CLI и принудительно для FPM согласно дополнительной рекомендации PHP от 2026-10-23. Исходный запуск миграций сохранён; PHP-FPM получает сигналы напрямую через `exec`.

## Порядок смены runtime

После `git pull` deploy вызывает `deploy/php-runtime-upgrade.sh <checkout> <test|production>`. При совпадении версии, fingerprint и наличии vendor он сразу завершает работу. При изменении runtime сначала собираются образы и устанавливается lock в отдельном vendor mount; проверяются платформа, autoload, версия и расширения. Работающее приложение продолжает использовать прежние библиотеки. Затем останавливаются писатели приложения, прежний vendor перемещается в игнорируемый `.php-runtime-upgrade/<timestamp>/vendor`, подготовленный vendor становится активным и проверяется готовность FPM. Обычный `make up` открывает nginx; существующий test activation пересоздаёт worker. Незавершённая активация мира сохраняет остановку писателей до штатного resume.

Схема БД, её данные, `.env`, имена Compose-проекта и volumes этим механизмом не меняются. Дампа БД нет. При ошибке установки или старта helper возвращает прежний vendor, тег предыдущего образа и ранее работавшие процессы. Ошибка остаётся неуспешной для CI. Файлы отката сохраняются локально на сервере, секреты в Git не попадают.

## Ручной откат после успешного выпуска

Откат выполнять в том же checkout при остановленных nginx/PHP/Composer и test worker. Каталог брать из строки `[php-runtime]` конкретного выпуска. Сохранить текущий vendor в отдельном каталоге, вернуть vendor из этого выпуска, восстановить тег из `image-reference` на ID из `image-id`, вернуть соответствующий предыдущий Git-коммит и запустить прежний образ с сохранённой конфигурацией. Не выполнять Composer install старого lock под новым PHP. После отката проверить API, cron и worker; БД не восстанавливать. Удалить `active` только после проверки выбранного каталога, чтобы следующая попытка повторила проверку runtime.

## Проверки

CI проверяет production/dev install из lock, Composer audit, API-сценарии, транзакции и конкуренцию MySQL/PostgreSQL, собирает оба Linux-образа, проверяет FPM через HTTP и его корректную остановку. Выкладка зависит от обоих jobs. После запуска VPS отдельно проверяются версия PHP/Yii, autoload, расширения, FPM и cron. Результаты конкретного выпуска фиксируются в плане `2026-10-24-php-83-security-upgrade`.
