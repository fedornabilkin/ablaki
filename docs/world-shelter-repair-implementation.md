# Ремонт шалаша и история защиты

Тринадцатый блок, 2026-09-27, ветка `feature/09-worlds`. BE:K8, DB:I6, FE:H8 реализованы в коде. Проверки приложения, миграции, сборка, коммит и выкладка не выполнялись. Маркер этого блока — 14, актуальная версия после огорода — 15; на test остаётся версия 10 и прежний набор функций.

## Игровой путь

На своей стартовой стоянке владелец выбирает «Рассчитать ремонт». Доступен как частично повреждённый, так и полностью сломанный шалаш. Установленный шалаш ремонтируется на месте, без свободной ячейки и без отмены ночлега. Сложенный должен находиться в доступной активной ячейке собственного хранилища. Нельзя ремонтировать чужой экземпляр или шалаш на другой стоянке через текущую.

Ремонт ручной, без станции, инструментов и оплаты Cr. Он нужен для восстановления после длительного отсутствия даже с нулевым балансом. Материалы берутся только из активных ячеек рюкзака; содержимое сундуков и установленные вещи автоматически не расходуются. Недостающие материалы выделены красным, подтверждение недоступно до нового расчёта с достаточным запасом.

Норма полного ремонта — исходное сырьё одной партии действующего рецепта `classic-plank` плюс одной партии `classic-rope`. При текущем стандартном каталоге это 1 бревно и 3 волокна. Для каждого материала расход равен `ceil(full_quantity × повреждение / максимальная_прочность)`. Это норма ремонта каркаса и обвязки, а не рецепт создания дополнительного шалаша. Рецепты должны быть активными, бесплатными, ручными и без инструментов; их сырьё — доступным для бесплатного сбора, без оборудования/контейнеров. Несовместимое изменение каталога закрывает ремонт до настройки; старые quotes перестают действовать по revision каталога. Это начальная норма, игровая приёмка баланса ещё впереди.

## Команда и сохранность предмета

[API шалаша](api/world-shelter.openapi.json) дополнен POST `nodes/{id}/shelter-repair-preview` и `shelter-repair`. В обоих случаях `direct_deploy=false`, `end_lodging=false`. ID пути — собственная стартовая стоянка; экземпляр выбирает сервер по разовому grant. Terms включают `protection_id`; при ремонте — расчёт материалов, доступность, причины отказа и прочность до/после.

Общий CommandBus удерживает блокировки каталога, владельца и registry. Quote фиксирует ревизии экземпляра, inventory, хранилищ и узлов. При commit условия пересчитываются; изменившиеся целочисленное повреждение, запасы, каталог или назначение требуют нового расчёта. Само течение секунд без изменения повреждения не делает quote бесполезным. Списание материалов, восстановление до максимума, интервалы защиты, журнал ремонта, аудит и outbox фиксируются одной транзакцией. Ошибка полностью откатывает действие, повтор request key возвращает сохранённый результат.

Сохраняются тот же instance, deployment, building, storage и lodging; разовое право не сбрасывается, новая вещь не выдаётся. Для сложенного шалаша сохраняется его текущая ячейка. Износ рассчитывается на одно серверное время внутри команды; дробный остаток, класс размещения и ставка не сбрасываются. Журнал `world_shelter_repair` связывает исходную/итоговую прочность и полный расчёт с уникальной operation.

## Защита без переписывания прошлых ночей

Миграция 14 добавляет `world_shelter_protection`: deployment, серверные границы, рассчитанный момент исчерпания, стартовые прочность/остаток/ставка/версия и operation. Nullable UNIQUE(active_deployment_id) допускает только один открытый интервал. Начальное развёртывание открывает интервал; складывание закрывает его. Ремонт закрывает старый и открывает новый в тот же момент, не меняя исходный `world_shelter_deployment.protected_until`.

Миграция переносит прежние deployments пачками по 100, сохраняя их исходные времена/истечение и закрытость. Она не восстанавливает прочность и не меняет ночные результаты. DDL завершён до транзакций переноса данных на MySQL/MariaDB; повтор после прерывания пропускает уже перенесённые operation. FK используют общий адаптер фактических типов ID.

Ночной расчёт пересекает интервалы назначения с интервалами защиты в пределах одного развёртывания. Для защищённой ночи объединение должно покрыть всю ночь без разрыва. Ремонт ещё исправного шалаша сохраняет непрерывность; промежуток между поломкой и ремонтом остаётся незащищённым, включая отложенный расчёт ночей. Журнал сохраняет ID обеих групп интервалов. Ранее сохранённые результаты не переписываются.

Новая публикация ночного календаря сначала убеждается, что текущие рецепты допускают бесплатный ручной ремонт. Повтор уже опубликованной политики возвращает прежнюю эпоху и правила. Нулевой баланс не мешает ремонту и последующему выздоровлению через защищённые ночи; мгновенного лечения при ремонте нет.
