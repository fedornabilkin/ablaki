## Схема и перенос инвентарей

Отдельная папка `yii2/console/world-migrations` содержит семнадцать возобновляемых миграций: дерево и шаблоны, команды/задания, хранилища/экземпляры, накопленный износ, переход с baseline, счета экономики, снимки кошелька, финансовые родители, казна/обязательства, оплаченные заказы/расходы, покупки помещений, шалаш/назначения ночлега, календарь/здоровье/результаты ночей, ремонт/интервалы защиты, огород/постоянные расширения, права мест оборудования и жильё/назначения/зачёт коек за ночь. На MySQL DDL выполняется вне внешней safeUp-транзакции; перенос данных имеет отдельные транзакции. FK используют фактические типы ID. Миграции сами не меняют старые credit-колонки; для них подготовлен отдельный offline-перенос. Откат с удалением игровых данных не предусмотрен.

`world-setup/install` применяет только этот набор, запускает seed и после успеха фиксирует `schema_version=17`. Частично установленная схема не открывает функции мира. После первой тестовой выкладки команда вызывается отдельным шагом только test workflow; Docker entrypoint и production workflow её не запускают. На тесте пока установлена версия 10. Install не публикует ночной календарь, цены огородов и не запускает болезнь.

`StorageBackfill` создаёт backpack/chest storage по устойчивым identity key, сохраняет inventory ID сундука, его содержимое, capacity и durability. Ленивый craft_container материализуется с текущими настройками. Пустые строки сохраняются с `slot=NULL`, пересечения позиций нормализуются, overflow не удаляется. В каждой транзакции владельца сравниваются суммы quantity до и после переноса. Checkpoint записывается отдельно после commit владельца: прерванная пачка может повторить владельца без повторного создания storage.

Код перехода готов, фактическое переключение не выполнялось. Добавлены сохраняемый baseline, постоянная блокировка новых записей, возобновляемый backfill, сверка и отдельная команда активации. Порядок и ограничения: [переход хранения](world-storage-rollout.md). Перед запуском требуется остановка всех writers сайта и старых процессов. Прямое включение флагов storage_v2/economy_tick запрещено; для хранения предусмотрен только путь storage-activate после сверки и подготовки индекса. Проверки на копиях двух СУБД остаются открытыми.

Подготовлены, но не выполнялись: `world-audit/schema`, `world-audit/data`, `world-audit/baseline`. Baseline снимается пачками в том же окне остановки записей; сам отчёт не блокирует все аккаунты и не является единым snapshot при продолжающейся игре. Отчёты схемы и данных, baseline и сверка должны быть получены на следующем согласованном этапе.

## Управление после согласования проверки

Ниже справочник команд, **не инструкция немедленно включить мир**. В этом изменении они не запускались.

| Команда из `yii2` | Назначение |
|---|---|
| `php yii world-audit/schema` | Реальные типы/FK/индексы/engine/version без секретов. |
| `php yii world-audit/data` | Ограниченная выборка проблем; автоматического исправления нет. |
| `php yii world-audit/baseline 0 100` | Пачка пользователей; продолжение по `next_after_user`. |
| `php yii world-setup/install` | Отдельная установка после подготовки БД. Требует `WORLD_INSTALL=confirmed-world-install`. |
| `php yii world-setup/seed` | Повтор seed без перезаписи ручных изменений. |
| `php yii world-setup/grant-manager USER_ID` | Добавить `world-manage` уже существующему `p-admin`; новых администраторов не создаёт. |
| `php yii world-setup/flag world_read 1` | Разрешить чтение в registry после полной установки; дополнительно требуется `WORLD_READ=1` у приложения. |
| `php yii world-setup/flag world_write 1` | Разрешить новые команды после чтения; дополнительно `WORLD_WRITE=1`. |
| `php yii world-setup/flag world_write 0` | Закрыть новые команды; сохранённые результаты остаются повторяемыми при действующей авторизации. |
| `php yii world-setup/backfill 100` | Подготовительная пачка; дополнительно `WORLD_BACKFILL_MAINTENANCE=1` после остановки writers. Не включает новое хранение. |
| `php yii world-worker/run` | Обработать зарегистрированные задания при `WORLD_WORKER=1`. Без зарегистрированных domain handlers мир не симулируется. |

Все команды `world-setup/*` требуют явного `WORLD_INSTALL`. В приложении переменные флагов читаются при создании модуля; изменение окружения должно попасть в соответствующие процессы приложения/worker.

## Порядок блокировок

Новые команды: `craft_meta → user (ID по возрастанию) → persone (ID по возрастанию) → world_registry → nodes → storage → inventory/equipment → jobs`. `user` берётся до `persone`, чтобы не добавлять обратный порядок относительно UserClearService. Registry пока сериализует записи нового мира; это сознательное ограничение пропускной способности первого этапа. Его дробление требует отдельной работы с гонками дерева/счетов.

Claim задания кратко блокирует registry и job. Выполнение повторно получает общие блокировки, проверяет актуальные lease/fence и держит job до commit. Handler не должен делать внешние сетевые запросы внутри этой транзакции. Inbox и доменный результат consumer записываются вместе. Очередь обеспечивает повторную доставку; единственность эффекта требует business key/ограничений самого обработчика.
