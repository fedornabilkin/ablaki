# Архитектурное соглашение backend

Принципы PCM Helper адаптированы к PHP/Yii2; требования Vue, TypeScript и Bulma к серверному коду не относятся.

## Ответственность
- Контроллер проверяет входные данные и права, вызывает прикладной сервис, формирует HTTP-ответ.
- ActiveRecord описывает хранение и валидацию сущности. Доменные правила и операции с несколькими записями координируются сервисом.
- Код группировать по существующим доменам; не перестраивать каталоги при точечном исправлении.
- Общий сервис не должен зависеть от контроллера конкретного приложения.
- Чистую логику по возможности отделять от I/O. Dependency injection применять к реальным внешним зависимостям.
- SOLID/GRASP и паттерны использовать для уменьшения связности, а не усложнения простых операций.

## Целостность экономики
- Изменение баланса, состояния операции, комиссии и истории выполняется одной транзакцией.
- Проверка прав, доступности и достаточности средств должна использовать актуальное состояние под блокировкой либо условное атомарное обновление.
- Блокировать несколько записей в стабильном порядке; не держать транзакцию во время сетевых вызовов.
- Повтор команды не должен дублировать начисление, списание или возврат.
- Проверять результаты save/update/delete. Ошибка записи должна приводить к откату, а не успешному ответу.
- Для новых сценариев избегать глобального изменяемого static-контекста middleware.
- Проверять повтор, конкуренцию, сбой промежуточной записи и согласованность истории.

## API и безопасность
- Аутентификация не заменяет проверку владельца конкретной сущности.
- Ошибка валидации должна иметь неуспешный HTTP-статус и понятный errors-контракт.
- Клиент не получает секреты, приватные ходы до разрешённого момента или техническую трассировку.
- GET предназначен для чтения. Существующие изменяющие GET-маршруты переводить с учётом совместимости клиентов.
- Токены доступа и одноразовые коды входа должны иметь отдельный жизненный цикл; миграцию auth_key планировать явно.
- Изменения схемы, валютной точности и миграций проверять на копии данных; сохранять PostgreSQL и существующий MySQL fallback.
