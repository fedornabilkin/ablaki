# Общие соглашения backend

Адаптировано 2026-09-05 из общих соглашений PCM Helper для Yii2. Соседний репозиторий для применения правил не требуется.

## Подход
- По решению владельца от 2026-09-05 дальнейшая разработка ведётся непосредственно в `master`; отдельные рабочие ветки и обязательные PR не создаются без новой просьбы. Перед началом синхронизировать историю, сохранять все пользовательские изменения, перед push выполнять проверки.
- Перед изменением изучать текущую реализацию, аналогичные решения и потребителей контракта.
- Сохранять пользовательские изменения, ограничивать работу задачей; избегать массовых переименований и несвязанного рефакторинга.
- Предпочитать понятные решения и существующие зависимости. Не вводить слои ради формального применения паттерна.
- Правила обязательны и для AI-агентов.

## Структура
- Git-репозиторий — back; приложения и Composer находятся в yii2.
- api — JSON API, backend — админка, frontend — серверный UI, console — команды и миграции.
- Общие домены находятся в common/modules; общие прикладные сервисы — common/services.
- Планы хранить в plans по [plans.md](plans.md); существующие docs/plan сохранять.
- Архитектура: [architecture.md](architecture.md). Ограничения релиза: [deployment.md](deployment.md).

## Совместимость и качество
- PHP-код текущего этапа должен сохранять синтаксическую совместимость с PHP 7.3; обновление runtime — отдельная приоритетная задача.
- Composer manifest и lock обновлять согласованно, проверяя реальный audit и совместимость. Старые dependabot-ветки не являются доказательством безопасности.
- Публичные изменения API согласовывать с Vue SPA и серверным UI.
- Запускать PHP lint изменённых файлов и поведенческие проверки затронутого сценария.
- Для DailyRewardService: php -d extension=pdo_sqlite tests/release/daily-reward.php из yii2 при доступном SQLite driver.
- Этот тест использует собственную временную БД. Он не подтверждает FOR UPDATE на PostgreSQL/MySQL; эти проверки обязательны до production.
- Не запускать тесты на production-БД. Миграции и сбросы тестовой БД должны иметь явно определённую среду.
- Документировать пройденные проверки и недоступные сценарии. Не считать сборку/линт доказательством корректности экономики.

## Данные
- Списки API поддерживают серверный `q`-поиск, фильтры и пагинацию с полным количеством записей/страниц. Новый клиент запрашивает `envelope=1`; прежний контракт сохраняется. По умолчанию новые записи сверху (`sort=-id`), исключения явно обозначаются.
- Баланс, ставки, комиссии и права принадлежат серверу; значения клиента не являются источником истины.
- Секреты и токены не включать в репозиторий и логи.
- Документация и пользовательские тексты — UTF-8; технические ошибки отделять от ответа пользователю.
