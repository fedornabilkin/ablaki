# Соглашение по релизу backend

## Подготовка

- По решению владельца работа ведётся непосредственно в master. Перед push синхронизировать историю, сохранить локальные изменения и проверить затронутый код.
- PHP lint и поведенческие тесты обязательны для изменённого PHP. Проверки на временной SQLite не заменяют проверку конкурентных операций на PostgreSQL/MySQL; тесты не запускать на production-БД.
- Изменения API сохраняют совместимость клиента. До публикации затронутых финансовых операций проверять auth, ставки, завершение/отмену игры, биржу и ежедневный бонус.
- Обновление PHP, зависимостей и инфраструктуры не добавлять в обычный деплой без задачи на эти изменения.

## Окружения

- Production backend: /var/www/api.ablakin.ru, существующая MySQL по MYSQL_DB_* production .env.
- Test backend: /var/code/ablaki, существующая PostgreSQL по PG_DB_* test .env.
- Выбор БД принадлежит существующему конфигу Yii. Не создавать БД, не копировать данные и не менять подключения ради публикации кода.
- Сохранять .env, локальные конфиги Yii, vendor, загрузки, порты, Compose project и volumes. Не назначать новое COMPOSE_PROJECT_NAME вместо существующего.
- Общий compose-файл не задаёт фиксированную подсеть: новые сети получают адреса от Docker. COMPOSE_SUBNET больше не используется. Не удалять существующие сети ради деплоя.
- Test использует отдельные TEST_BACKEND_* secrets без production fallback. API: http://94.250.251.94:3180/, admin: http://94.250.251.94:3195, frontend: http://94.250.251.94:3181.
- Служебные каталоги /opt/ablaki-backend и /opt/ablaki-backend-test содержат исполняемый через Bash deploy-скрипт. Новые releases/incoming/vendor-артефакты не создаются.
- Production frontend: /var/www/ablakin.ru; test frontend: /var/code/ablaki-front/project/dist.

## Публикация

- По прямому уточнению владельца от 2026-09-06 автоматизация на VPS выполняет **git pull, затем make up**. Не дополнять её остановкой приложения, проверочными Docker-контейнерами, установкой vendor, rebuild, backup, изменением .env или переносом данных.
- Pull выполняется с --ff-only. При его ошибке make up не запускается. Не применять reset/checkout для обхода локальных изменений.
- Push master запускает CI и production. Ручной test использует ветку, уже выбранную в тестовом checkout; автоматического переключения ветки нет.
- В make up остаются миграции существующей БД, SHA для /health и запуск PHP/nginx. Автоматическое определение/запуск БД и force-recreate убраны. Ошибка миграции передаётся вызывающему процессу.
- Не использовать make init, down --volumes или network prune при обновлении приложения.
- Полный откат к старому Makefile/entrypoint не подходит: он вернул бы Composer 1.8/PostgreSQL на MySQL prod и Yii init Development. Исправления runtime и API сохраняются, но дополнительные операции на VPS не выполняются.
- Успех backend job означает завершение двух команд. Frontend отдельно проверяет полный /health, APP_ENVIRONMENT, контракт списков и CORS.
- APP_ENVIRONMENT в .env задаётся при настройке окружения как production или test; deploy-скрипт его не меняет.
- Старые артефакты автоматически не удаляются. Автоматического восстановления данных нет.
- Доступы и реальное выполнение на VPS подтверждать результатом нового run; наличие workflow не считать успешным деплоем.
